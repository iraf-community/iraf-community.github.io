## HELP task ambiguities

**Mike Fitzpatrick** wrote on Mar 30, 1998

<pre style="background: transparent; box-shadow: none; border: none;">

&gt; In this case, &quot;help&quot; accesses the wrong file.  I have been trying to get
&gt; &quot;ellipse&quot; to work, and wanted to see just what its &quot;controlpar&quot; pset
&gt; does.  I did &quot;help controlpar&quot;, and what I got was
&gt; 
&gt; 	CONTROLPARS (Feb96)      stsdas.analysis.fitting 
&gt; 
&gt; I was able to get the right help file by doing &quot;help isophote.controlpar&quot;.
&gt; Apparently the trouble was caused by the fact that I had accessed
&gt; &quot;analysis&quot; more recently than &quot;isophote&quot;, even though the task I had been
&gt; using was &quot;ellipse&quot;.  I don&#x27;t know if anything can be done about this
&gt; quirk, but it can be very puzzling.

	The ambiguity comes about because the help task searches for the
template first in all modules in the current package, and then in all
modules in all packages except the current one.  The &#x27;curpack&#x27; parameter
defaults to &quot;AskCL&quot; which follows the above scheme, but you can also set
it explicitly as in

	cl&gt; help controlpar curpack=isophote

but this is clumsier than &quot;help isophote.controlpar&quot; and just as obscure.
A better solution would be to enable the &#x27;all&#x27; parameter to HELP, i.e.

	cl&gt; help controlpar all+

With the ANALYSIS package loaded you would still see the FITTING pkg help
page first but just keep scrolling and you&#x27;ll see the one you want right
afterwards.  &#x27;All&#x27; defaults to no so you usually only see the first match
which may not always be correct, turn it on and you&#x27;ll see every match and
perhaps even stumble onto something helpful you weren&#x27;t expecting.

Cheers,
-Mike
</pre>
