===== 2001AUG08 RELEASE NOTES =================================================

The latest release of MXTOOLS features several new tasks including QDWFPC2,
which does QDPHOT CCD stellar photometry on two Hubble Space Telescope WFPC2 
observations, WFPC2COLOR, which converts HST WFPC2 instrumental magnitudes 
to standard colors using the Holtzman et al. (1995, PASP, 107, 1065) color 
equations, and QDCMD, which reads the output of WFPC2COLOR and displays a 
color-magnitude diagram on a user-chosen graphics device.
 
The QDWFPC2 demonstration can be seen by typing the command `qdwfpc2&#x27; and 
accepting the two default WFPC2 images of the Galactic globular cluster 
NGC 362.  The QDWFPC2 task is actually an IRAF script which first does QDPHOT 
photometry on the WFPC2 images, then converts the F439W and F555W instrumental
magnitudes into standard Johnson B and V magnitudes using the WFPC2COLOR task,
and finally displays the results as a color-magnitude diagram using QDCMD.  
The entire process generally takes just a few seconds (typically &lt;10 seconds 
on a slow 200-MHz Sun Ultra1 workstation).
 
The QDWFPC2 task has been designed for ease of use for undergraduates working
with HST archival WFPC2 images of stellar population in the Local Group.
Anyone interested in using QDWFPC2 to analyze WFPC2 observations of Galactic
star clusters in a laboratory setting as part of a senior-level astrophysics 
course on stellar evolution is encouraged to contact me for further discussion.

I have noticed that there is a catch in computing and adding heliocentric
correction VHELIO to a bunch of files using task RVCORR in astutils
package.

When the date-obs is in new format (including time) that time is taken for
computing VHELIO and HJD even if there is a EXPTIME keyword even if the
keywpars are set appropriately. It ignores the UTMIDDLE as well. What is
still worse that the SETJD task sets the HJD correctly to the midtime of
the exposure but after running RVCORR even that HJD is replaced by the
value at the beginning of exposure.

So how can I get the correct HJD and VHELIO to the middle of the exposure?
The ASTHEDIT seems not to have function for computing heliocentric
correction VHELIO either.

Is there a trick or is it necessary to write a new task to do this ?
