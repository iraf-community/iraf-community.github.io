# IMEXAMINE behavior

**Frank Valdes** wrote on Mar 23, 2000

<pre style="background: transparent; box-shadow: none; border: none;">
&gt; 1) imexamine does not work correctly with sections in three (or more ?)
&gt;    dimensional images. Working on an image of size [1024,1024,2] and executing
&gt;    &gt;imexam image[*,*,2]
&gt;    displays the correct part of the image but operations like &#x27;s&#x27; or &#x27;r&#x27; etc.
&gt;    seem to be working on some other part of the image, presumably image[*,*,1]

This is true.  I can&#x27;t recall right now why this is the case.  IMEXAMINE needs
some work to be more useful with higher dimensional images.  For now
you would need to use IMCOPY to copy out the plane you want to examine.


&gt; 2) imexamine started without a file name returns values for the file
&gt;    it finds last displayed even if this file no longer exists - and the values
&gt;    returned are wrong !
&gt;    If the file it picks up from the display buffer does no longer exist
&gt;    imexamine should bail out with an error message.

This was actually a preconceived feature.  The idea is that one might want
to examine the image display buffer as an image; i.e. you would get
back values from the 8-bit display.  This was considered useful for
situations when some other task, say a data acquisition task, loads
the display, possibly without creating an image or an image in
an IRAF format.
</pre>
