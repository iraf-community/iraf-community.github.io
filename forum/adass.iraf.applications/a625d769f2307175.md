## How big can multispec files get?

**Frank Valdes** wrote on Mar 09, 1999

<pre style="background: transparent; box-shadow: none; border: none;">
Q:  I&#x27;m trying to make a multi-spec file of a catalogue of galaxy spectra.
I have 558 objects drawn from 8 fields. Whan I combine 7 of them using
scopy (a total of 487 objects) everthing works OK. However, when I try
8 it crashes citing `too many WCS systems` and exhibiting problems with
the resulting header. The resulting spectrum is produced but has zero
spectra from spectrum 545 onwards.

I&#x27;ve tried increasing len_minuserarea to 1000000 to squeeze everything
it but to no avail. Nothing is wrong in terms of disk space either. Nor
is it anything worng with the last file as I&#x27;ve played with the order.


A: There are definite limits to the number of spectra in the multispec
format.  The one you are encountering is a limit in how many &quot;attributes&quot;
can be in an image.  For multispec format the &quot;attributes&quot; are the
key=value things in the WAT keywords.  This mostly means the specN
values.  The current limit is 512 attributes which means about 500
specN values (to allow for a few other attributes such as the units, etc).

This limit applies to the more complex multispec format where the coordinate
systems can be independent.  If all your catalog spectra have the same
linear coordinate systems (same CRVAL1, etc) or can be put into that
form through resampling with DISPCOR then the &quot;equispec&quot; format
would be used.  This has a simple WCS but needs many APNUM/APID type keywords.
This would run into the indexing limit (provided the header size was
set big enough) of 999.
</pre>
