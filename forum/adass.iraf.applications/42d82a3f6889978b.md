# Effective airmass for combined image: IMCOMBINE

**Frank Valdes** wrote on May 14, 1998

<pre style="background: transparent; box-shadow: none; border: none;">

Q:  I am currently combining 4 exposures of the same image. I have used
geomap to obtain the transformations relative to a reference frame, and
I then used register to perform the registration. I then performed an
average imcombine to combine the images. My problem is, how do I
determine the proper airmass of the combined image (since imcombine
simply uses the image header of the first image in the list) ?


A:  If the airmass is varying between exposures then you probably need to
apply a multiplicative scaling to your exposures when combining.  If
you let IMCOMBINE compute this then you would use the image which has a
scale factor nearest one as the basis for the airmass.  You can also
set the scaling values from a file or from a header keywords.  In this
case you can adjust things so that one of your images has unit
scaling.  Use this as the first one in the list of input images to
IMCOMBINE and then the appropriate airmass will be that for the first
image which is, as you said, the header that is used as the basis for
the output header.  Alternatively to having IMCOMBINE do the scaling
you could scale your images to one of the image separately (say with
IMARITH) and then use IMCOMBINE with no scaling.  The best detailed way
to determine the scaling is to use photometry of the common stars,
using any of the photometry tasks in IRAF, and determine how to scale
the images to make the photometry agree to one of the images as
reference.  This would then be the airmass reference image.

Of course if the images were taken consecutively and you combine by
averaging (without scaling) you could just treat this as a single long
exposure and compute the airmass at the middle of the total exposure
(maybe using SETAIRMASS after setting the the starting exposure time
and total exposure time appropriately).

I hope this helps.  This questions has not come up much before so this
is the best answer I currently have.
</pre>

Just set the samplepar.harmonics parameter to &quot;5 6 7 8&quot;. The task will
create additional columns in the output table with the harmonic
amplitudes and their errors.

Note that these amplitudes are NOT converted into deviations from a
perfect ellipse. Instead, they are written in raw intensity units.
They can be converted into deviations from an ellipse by using task
&#x27;ttools.tcalc&#x27;. Just divide the respective columns by columns labeled
&#x27;SMA&#x27; and &#x27;GRAD&#x27;.
