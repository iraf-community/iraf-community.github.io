Bug Report - the &#x27;s&#x27; option (to run &#x27;ldetect&#x27; at a particular
location)in xplot.xexamine for fields containing excessive numbers of
counts.

We have found that an overflow occurs for fields with very high
counts/sqarcmin in the central region.  This occurs when computing an
exponential of the average surface brightness in conjunction with
calculating expected excursions from the mean under Poisson
statistics.  The offense is committed in &#x27;xspatial.detect.bkden&#x27;,
called during the operation.  The default region is a circle at the
field center with radius 7.5 arcmin.  When the average counts in this
area is large (e.g. 140 counts/sq_arcmin as was the case for the
center of the Virgo cluster in a 202 ksec observation), the error
message &#x27;floating point overflow&#x27; will occur because of BKDEN taking e
to the power of 140.  The workaround is to skip BKDEN by setting the
parameter &#x27;xexamine.bkden&#x27; larger than zero.  A reasonable value for
the background density can be estimated by choosing your own region
and using &#x27;imcnts&#x27;.

PROS PATCH 2.5.1 is now available for SUNs and DEC UNIX.  A future
issue of H&amp;P will describe revisions to the PROS USER&#x27;S GUIDE.  If you
want to install our patch, please ftp to the location at the bottom of
this message, cd to pub/pros/pros_2.5_p1, and read README_p1.ftp, and
whichever of README.Sun or README.Alpha is appropriate for your
operating system.

II) Summary of changes made in this release (PROS 2.5.1) :

  ********* NEW TASKS **********

   &lt;package.task&gt; - &lt;description&gt;

   xproto.marx2qpoe -  
      A new task uses FIT2QP to convert the MARX EVENT FITS
      into  a QPOE file. The output QPOE is spatially sorted 
      with key_y as the primary key and key_x as the secondary 
      key.  See H&amp;P#23 and the help file for details.  NB: MARX
      is the AXAF simulator.

   xproto.xexamine_r -  
      This task is a slight modification of xexamine. In addition to all
      the features in xexamine(xplot), it now works for QPOE files 
      which are not square.  However, the blocking factor for both
      dimensions has to be the same.  See the help file for details. 


  ********* BUGFIXES AND ENHANCEMENTS *************

   &lt;package.task&gt; - &lt;description&gt;

   xproto.imdetect
        - Fixed the bug that crashed imdetect when run on image files. 
	  (ref. H&amp;P#23)
        - Removed &quot;implicit  &quot;a-z&quot;&quot; in some fortran code which
          caused compiling problems on Alpha.

   xspatial.detect.lpeak
        - Fixed the bug that caused two rows of detect 
          cells to be ignored along one edge, whilst the 
          other edge was not ignored.  (ref. H&amp;P#23)

   xdataio.fits2qp 
        - Added two more index keys to QPOE for ASC
          (AXAF Science Center) data.

  ********* FOR DEC UNIX ON ALPHA  ***************
