This is a common "gotcha".  The IDENTIFY task reads input from the  <br>
cursor, from parameters, and from the standard input of the task.  It  <br>
is this last part, where it asks for such things as the wavelength,  <br>
that causes problems with the simplest way to invoke a script.  I  <br>
suspect you are doing something like:<br>
<br>
     cl&gt; cl &lt; myscript.cl<br>
<br>
In this case you are redirecting the standard input of the CL from  <br>
the terminal to the script file which then causes the problem you  <br>
have.  There is an easy solution.  You must declare the script as a  <br>
task as follows:<br>
<br>
     cl&gt; task $myscript = &lt;path&gt;myscript.cl<br>
     cl&gt; myscript		# This runs the script<br>
<br>
The script must use the .cl extension.  The path, such as home$, is  <br>
optional but if you don't specify a path then the script will only  <br>
run in the directory where the script file is located.  The first $  <br>
in the task statement says that the script does not have parameters.   <br>
Note there are other ways to write scripts, which also use the task  <br>
statement to define them, that include parameters and is more like a  <br>
programing language (see <a href="http://iraf.noao.edu/iraf/ftp/iraf/docs/">http://iraf.noao.edu/iraf/ftp/iraf/docs/</a> <br>
script.pdf).<br>
<br>
To repeat, IDENTIFY cannot be used in a script that is executed by  <br>
redirection to the cl but can be used in other forms script invocations.<br>
