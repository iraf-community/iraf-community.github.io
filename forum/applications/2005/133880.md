The part that I did not see mentioned is about the world coordinate system (WCS).Â  The various<br>
mscred tasks are designed to use a WCS description in the headers.Â  The concept is that<br>
the distortion terms are relatively fixed and are stored in the headers.Â  The main sources of<br>
observational error are assumed to be a telescope offset (corrected by adjusting the WCS<br>
"tangent point") and a linear transformation which accounts for rotations and refraction.<br>
Msccmatch is meant to automate determining and correcting these errors leaving the<br>
higher order distortion terms unchanged.Â  Then mscimage uses the WCS, now assumed<br>
to be accurate everywhere in the images, to resample the data to an undistorted celestial<br>
grid.<br>
<br>
So if you don't have a WCS which represents the distortions in the simulated mosaic see<br>
<br>
<a href="http://iraf.noao.edu/projects/ccdmosaic/astrometry/astrom.html">http://iraf.noao.edu/projects/ccdmosaic/astrometry/astrom.html</a><br>
<br>
In particular you should use mscfinder.msctpeak with a projection of tnx (after you have<br>
an approximate, possibly just linear, WCS).Â  In order to do that your simulation should include<br>
the GSC stars you used initially and you would have a simple text file list of the RA (in hours)<br>
and Dec (in degrees).<br>
<br>
An important thing that people often neglect is to verify things by the simple test of overlaying<br>
star positions on the data.Â  This is done with msczero and the 'm' key and a list of coordinates.<br>
If you can do this and see the stars marked correctly everywhere in the distorted image then<br>
mscimage will also work correctly.Â  If you see the positions are off in the corners or some other<br>
pattern then you will have errors in the resampled image.<br>
