I think what you are trying to do is what is done by the tasks in<br>
apextract.  If you want to add a sigma spectrum to your spectrum, then<br>
the following information may prove useful (this information was from a<br>
reply to another user by another IRAF support person).  The example<br>
provided makes use of the artdata package to add what you want to a<br>
spectrum.<br>
<br>
As far as I can tell, spectool will not add a sigma spectrum.  The<br>
spectrum arithmetic tool will only modify what already exists.<br>
<br>
I hope that helps.  Let us know if you have further questions or<br>
problems.<br>
<br>
Cheers,<br>
<br>
Phillip<br>
<br>
------------------------------------------------------------------------<br>
<br>
mkpattern temp ndim=3 ncols=3680 nlines=1 n3=2 header=testspec<br>
imcopy testspec[*,2,1] temp[*,1,1]<br>
imcopy testspec[*,2,2] temp[*,1,2]<br>
hedit temp wat0_001 "system=equispec" add+ verify-<br>
hedit temp apnum1 "1 1" add+ verify-<br>
scopy temp test format=multispec<br>
imdel temp<br>
spectool test plotsig+<br>
<br>
The first command is from the ARTDATA package and it creates an empty<br>
3680x1x2 image.  The next two commands copy the spectrum and the sigmas<br>
into the first and second planes.  The next command adds a keyword that<br>
identifies the format as "equispec" which IRAF and SPECTOOL uses.<br>
The APNUM1 keyword is needed to associate an aperture number with the<br>
particular line.  If there are multiple spectra then there would need<br>
to be one<br>
for each line.  Note that aperture information need not be the same<br>
as the line<br>
numbers.<br>
<br>
At this point the format is close and some tasks will be happy but<br>
not SPECTOOL.<br>
So we use SCOPY to formally produce all the keywords associated with the<br>
equispec and multispec formats.<br>
<br>
Note that in the registers you should only see one thing.  The<br>
associated spectra<br>
are not considered separate registers.  The "control panel" is where<br>
you can<br>
set which things to plot.<br>

----------------------------------------------------------------------<br>
<br>
The format is automatically produced when the IRAF aperture extraction<br>
tasks are run with parameters to output the "extras" spectra and the<br>
information needed to compute uncertainties during extraction are<br>
specified.<br>
<br>
So let me tell you what the format is and some hints on how you can<br>
create it.  1D spectra in IRAF are currently lines in the first plane<br>
of 1D, 2D, or 3D images; in section notation these<br>
are <li>, [*,?], or [*,?,1] where ? is some line number.  When there<br>
are multiple lines these are multiple spectra.  The associated<br>
spectra are specified in 3D images.  The planes are<br>
sometimes called "bands" which is why the keywords you need are<br>
BANDIDn, where n<br>
is the coordinate along the 3rd dimension.<br>
<br>
So you need to make a IxJxK image.  J may be 1 for a single spectrum<br>
with associated information.  Then you need to create the keywords<br>
BANDIDk where the values are "spectrum", "raw", "sky", "sigma", or<br>
"continuum".  Only the first word is used so something like "sigma<br>
based on a model" is as good as "sigma".<br>
<br>
The tasks which you might use for this (in addition to any others<br>
that you know that generate FITS files) are IMSTACK and HEDIT.  As a<br>
hint, you can use IMSTACK with just one file to increase the<br>
dimensionality:<br>
<br>
cl&gt; imstack spec1d spec2d<br>
cl&gt; imstack sigma1d sigma2d<br>
cl&gt; imstack spec2d,sigma2d spec3d<br>
cl&gt; hedit spec3d bandid2 sigma add+<br>
cl&gt; imhead spec3d l+<br>
[...]<br>
BANDID2 = 'sigma'<br>
[...]<br>
