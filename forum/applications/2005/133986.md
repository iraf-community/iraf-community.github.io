The effect you are seeing is caused by a combination of the hot pixel and the variance weighting.Â  If you use either variance weighting or clean then the algorithm creates a smoothed profile of the 2D spectrum and the extracted value is based on the fitting of the profile to the data at each column.Â  The fitting, which is basically the normalization of the observed data, is greatly affected by hot pixels.Â  Cleaning often helps to iteratively remove the hot pixel so it doesn't affect the normalization.Â  However, if the hot pixel is very strong then the iterations actually remove the good data in preference to the hot pixel because both the good and hot data are then seen as deviant from the profile normalized initially by all the data including the hot pixel.Â  Note that when this happens it causes the bad things you mention both with and without cleaning.<br>
<br>
So, you need to either not use the variance extraction (which you already have as the second "band" of the extractions) or you need to use the saturation parameter to chop off the really hot pixels a priori before the normalization, etc.Â  I recommend you always use the saturation parameter for this data.Â  The benefit of the variance weighting is sometimes overrated but you can use it with the clipping of the hot pixels.Â  I also recommend the cleaning but only if you can minimize the effects of the hot pixels, again using the saturation parameter.<br>
