Hello Dugan,<br>

The formating is causing a problem.  The program is trying to figure  <br>
out if the keyword value is a number or a string.  It assumes a  <br>
string starts in column 11 with a quote mark.   Since this is not the  <br>
case it is interpreting the value as a number.  The program could be  <br>
smarter but it is not.  A way to fix your data automatically is with  <br>
the task HFIX.  The following should work:<br>
<br>
cl&gt; hfix *.fits command="!sed 's/DATE-OBS= */DATE-OBS= /' $fname &gt;  <br>
temp; mv temp $fname"<br>
<br>
I haven't tried to reproduce the segmentation violation but I expect  <br>
it may be due to the format problem.  If you still get an error you  <br>
can just send me a long header listing (imhead &lt;image&gt; l+) and I can  <br>
create a dummy image with the same header.<br>
<br>
