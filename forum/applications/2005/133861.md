Hi Gabriel,<br>
	The ulimit trick usually fixes this but only when the memory<br>
corrupted comes from all tasks.  If this is limited to MKOBJECTS then<br>
it may be related to the data itself and be no more than a bug in the<br>
task.  Does it happen reliably with your e.g. object list but not when<br>
trying one of the help page examples?  Does it happen for any other task?<br>
	If it is limited to the one task and your data files, could you<br>
please put your sample input image and object list in the /pub of our<br>
<a href="ftp://iraf.noao.edu">ftp://iraf.noao.edu</a> archive so we can have a look?  Also, it would help<br>
to know what distribution of Linux you're using and the IRAF version<br>
(i.e. V2.12.2 or the V2.12.2a patch from Jul04)?  Note that there are<br>
some known issues with the Debian package created by one of the users,<br>
if you're using this try installing the binaries from our archive instead.<br>
Hope this helps.<br>
