<blockquote><br>
Question # 1<br>

The output can be plotted with splot which is what I want, but I am wondering why the messages in the prompt doesn't show up. Does anyone know?</blockquote><br>
<br>
Because you specified the arguments on the commandline, they aren't prompted for.  Run with just the task name and you'll see the prompts.<br>
<br>
<blockquote><br>
Question # 2<br>
I got a whole list of images such as<br>
F02001010012alif4ttagfcal.fit F02001010022bsic4ttagfcal.fit<br>
F02001010012asic4ttagfcal.fit F02001010012bsic4ttagfcal.fit<br>
F02001010031alif4ttagfcal.fit F02001010031asic4ttagfcal.fit<br>
F02001010021alif4ttagfcal.fit F02001010031blif4ttagfcal.fit<br>
F02001010021asic4ttagfcal.fit F02001010031bsic4ttagfcal.fit<br>
</blockquote><br>
<br>
These need to be specified one-per-line.....<br>
<br>
<blockquote><br>
I would like to process a list of files to make it automatic.<br>
tab2spec (@infile, @outfile)</blockquote><br>
<br>
You can use an editor to create the 'outfile' with the desired image names, if what you want is to generate the output list on the commandline then use a command like<br>
<br>
<pre><code>
cl&gt; tab2spec F0200101*.fit F0200101*%ttagfcal%%.fit
</code></pre><br>
<br>
The '%' operator does a string substitution inline and the above command will remove the 'ttagfcal' part of the filename from each of the input filenames.<br>
<br>

<div>
<blockquote><br>
For my Q 1, If I don't specify the arguments on the command line,<br>
<br>
ct&gt; tab2spec<br>
ERROR on line 51: Header file name not found or ambiguous ([0])<br>
tab2spec () </blockquote><br>
<br>
The fact you don't get the prompt makes me wonder how you declared the task, i.e. if it was something like "task $tab2spec = ...." then the '$' says the task has no parameters.  Since you *do* have parameters, you shouldn't be using the '$' before the task name.  If you change this, you'll need to unlearn the task before running it again.<br>
<br>
The error indicates that the 'infile' local variable is empty rather than coming from the parameter, and so when you call keypar it sees only the '[0]' extension.  If you type 'd_trace' before running your script, you'll toggle on a debug flag that will print detailed info as the script executes that might help us figure out what's going on.<br>
<br>
<blockquote><br>
For my Q 2, could you show me how to use an editor to create an @outfile from @infile? I really appreciate your help. </blockquote><br>
<br>
It depends on which editor you use:  what I meant was that you would copy the input list to an output list, then e.g. use "vi" on the output list and issue the command ":1,$s/ttagfcal//g" to remove the string from the filename.  You could do this all at once using the command<br>
<br>
<pre><code>cat inlist | sed -e &quot;s/ttagfcal//&quot; &gt; outlist</code></pre><br>
<br>
Cheers,<br>
-Mike

<div>
From the help page and the task source it appears that the KEYPAR task does not allow an input list of images, but prefers a single imaage as the argument.  As such, you will need to modify your script to handle one image at a time rather than using the '*' wildcard to   create a list.<br>
<br>
<blockquote>Another question, after doing âd_traceâ, how do I get out without having to logout...... </blockquote><br>
<br>
The 'd_trace' is a toggle, i.e. type it again to disable the debug-output in the same CL session.<br>
