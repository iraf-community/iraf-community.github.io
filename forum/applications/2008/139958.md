**Mike Fitzpatrick** wrote on Jul 28, 2008

{% raw %}
<div>
This usually means that either you didn't reset your 'stdimage' environment variable to be as big as the image (and so you're using the default 512x512 frame buffer), or when you did the installation a /usr/local/lib/imtoolrc link wasn't created which points to $iraf/dev/imtoolrc and so DS9 doesn't have a valid table of frame buffer sizes.<br>
<br>
You can display with the 'fill' parameter enabled and the image will be scaled to fit whatever size stdimage you set, use the GDEVICES command to get a list of available stdimage sizes.  If you cannot write to the /usr/local/lib directory, you can copy the $iraf/dev/imtoolrc file to ".imtoolrc" in your unix home directory and restart DS9 to use a private version.<br>
<br>
Cheers,<br>
-Mike
</div>

**Mike Fitzpatrick** wrote on Jul 28, 2008

{% raw %}
<div>
The imtoolrc file looks fine.<br>
<br>
To reset the frame buffer size, use the GDEVICES command to get a list of available sizes.  You can reset this on the command-line with the command like<br>
<br>
<pre><code>cl&gt; reset stdimage = imt2048</code></pre><br>
<br>
Or look in your login.cl file and change/uncomment (by removing the '#') the value set there.<br>
<br>
To display with the 'fill' parameter set, use either of<br>
<br>
<pre><code>cl&gt; display dev$pix fill=yes
cl&gt; display dev$pix fill+</code></pre><br>
<br>
If you haven't already seen it, you might also have a look at the Beginner's Guide:  <a href="http://iraf.net/irafdocs/beguide/">http://iraf.net/irafdocs/beguide/</a><br>
<br>
-Mike
</div>
