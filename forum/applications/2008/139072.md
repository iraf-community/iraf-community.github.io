<div>
For loading images using DS9 directly, ds9 opens the image and reads the header and so will make use of the WCS to display RA/Dec coords.  I tried a DSS image and confirmed that this worked, at least with the version of DS9 I have.<br>
<br>
For IRAF display however, what gets sent to the DS9 as part of the display WCS is the name of the file being displayed and not the actual FITS wcs keywords.  DS9 doesn't then use this information to open the image itself the way it would for a standalone image load and so you don't see the WCS readout.  This is normal and something that DS9 needs to change to have it work properly.<br>
<br>
-Mike

**Mike Fitzpatrick** wrote on Feb 26, 2008

{% raw %}
<div>
It's not a question of a protocol being available:  The current IIS protocol used for display has a 'set wcs' function that includes a full path to the image being displayed, the intent being the server can open this image itself to access pixel and header information (such as XImtool does when sent the image name, or DS9 does when loading an image standalone).  DS9 never does anything with this name, but even if every byte of the image were transferred over the display protocol, it is still up to the DS9 developers to do something with that information.  <br>
<br>
The remainder of the 'wcs' sent in a display call consists of a linear mapping of the pixels to the frame buffer and the z1/z2 values to approximate the display value.  Access to real pixels and FITS WCS keywords requires the image to be opened.<br>
<br>
Cheers,<br>
-Mike
