# increasing precision of cctran output

**jsimon** wrote on Jul 30, 2008

{% raw %}
<div>
Hi,<br>
<br>
I'm using images.imcoords.cctran to transform (x,y) coordinates on an image to RA and Dec (the plate solution has distortion terms, so that the nonlinear part is important).  One of the parameters of cctran is min_sig, described as the number of significant digits in the output file.  The default value of min_sig is 7, corresponding to 0.1".  I would like to get one more decimal place in the output, but no matter what number I set min_sig to, it gives me the same output with 0.1" precision.  Is there something I'm missing that would actually increase the precision?  An example parameter set is included below:<br>
<br>
input   =     Pal13.fits.coo.1  The input coordinate files<br>
output  =  Pal13.fits.coo.1.rd  The output coordinate files<br>
database=      Pal13.mscred.db  The input database file<br>
solution=  Pal13.newastrom.fits  The input plate solutions<br>
(geometr=            geometric) Transformation type (linear,geometric)<br>
(forward=                  yes) Transform x / y to ra / dec (yes) or vice versa <br>
(xref   =                INDEF) The X reference pixel<br>
(yref   =                INDEF) The Y reference pixel<br>
(xmag   =                INDEF) The X axis scale in arcsec per pixel<br>
(ymag   =                INDEF) The Y axis scale in arcsec per pixel<br>
(xrotati=                INDEF) The X axis rotation angle in degrees<br>
(yrotati=                INDEF) The Y axis rotation angle in degrees<br>
(lngref =                INDEF) The ra / longitude reference coordinate in lngun<br>
(latref =                INDEF) The dec / latitude reference coordinate in latun<br>
(lngunit=                     ) The input / output ra / longitude reference coor<br>
(latunit=                     ) The input / output dec / latitude reference coor<br>
(project=                  tan) The sky projection geometry<br>
(xcolumn=                    1) Input column containing the x / ra / longitude c<br>
(ycolumn=                    2) Input column containing the y / dec / latitude c<br>
(lngform=                     ) Output format of the ra / longitude / x coordina<br>
(latform=                     ) Output format of the dec / latitude / y coordina<br>
(min_sig=                   10) Minimum precision of the output coordinates<br>
(mode   =                   ql)<br>
<br>

<div>
Hello Josh,<br>
<br>
I believe you need to use the format parameter.  You might also like that it can produce sexigesimal coordinates and/or RA in hours instead of degrees.<br>
<br>
<pre><code>
%.3H  -- format to sexigesimal hours with 3 places past the seconds; i.e. milliseconds of time

%.2h -- format to sexisimal degrees with 2 places past the seconds; i.e. centiseconds of degree

%.9g -- decimal with 9 digits of precision
</code></pre><br>
<br>
See wcsctran help for information about the format syntax.  It is similar to C or other modern languages with the addiiton of the h/H, m/M formats.  You can use printf to test formats.<br>
<br>
<pre><code>
ecl&gt; printf (&quot;%.2M\n&quot;, 1.234567)
0:04.94
ecl&gt; printf (&quot;%.2m\n&quot;, 1.234567)
1:14.07
ecl&gt; printf (&quot;%.2H\n&quot;, 1.234567)
0:04:56.30
ecl&gt; printf (&quot;%.2h\n&quot;, 1.234567)
1:14:04.44
</code></pre><br>
<br>
Yours,<br>
Frank Valdes
</div>
