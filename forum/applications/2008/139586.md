# ccdproc processes calib. frames when ccdproc keyword set

**Evert Rol** wrote on May 21, 2008

{% raw %}
<div>
Hi,<br>
<br>
I'm reducing some (object) frames through CCDPROC. The dark, zero and flatfield have already been reduced through some pipeline; I only had to trim them, which I did through CCDPROC as well. This resulted in the CCDPROC header keyword set for the calibration frames.<br>
When running CCDPROC on my object files, however, I note that CCDPROC additionally processes the calibration files as well, ie it subtracts the bias from the dark and flatfield, and subtracts the dark from the flatfield. Even while these have already been processed and the CCDPROC flag set in their header.<br>
On the CCDPROC help page, I find:<br>
<br>
"Having  selected  a  calibration  image  it  checks  if  it has been<br>
    processed by looking for the image header flag CCDPROC.   If  it  is<br>
    not  present  then  the  calibration  image  is processed.  When any<br>
    image has been processed the CCDPROC  flag  is  added.   For  images<br>
    processed  directly  by  ccdproc the individual processing flags are<br>
    checked  even  if  the  CCDPROC  flag  is  present.   However,   the <br>
    automatic  processing  of the calibration images is only done if the<br>
    CCDPROC flag is absent!  This is to make the task more efficient  by<br>
    not  having  to  check  every  flag  for every calibration image for<br>
    every input image.  Thus, if additional processing steps  are  added<br>
    after  images  have been partially reduced then input images will be<br>
    processed for the new steps  but  calibration  images  will  not  be<br>
    processed automatically."<br>
<br>
From that, I would think that the calibration frames shouldn't be processed. <br>
<br>
Could anyone confirm this behaviour, or clarify my understanding of the help text? <br>
Is there any flag (in ccdproc or the ccdred package) that toggles this behaviour? I cannot find it.<br>
<br>
I guess the easy work-around is to add some dummy ZEROCOR and DARKCOR keywords to the respective headers, but I'd like to know if I just didn't miss anything obvious.<br>
<br>
  Evert<br>
<br>
ps: I'm using IRAF v2.14

Hello Evert,<br>
<br>
I checked the code.  While there could be some complexity I missed, it appears to me that the help page is incorrect.  It looks like the CCDPROC keyword is written but not explicitly used by the tasks in CCDRED.  Each operation set to yes in the CCDPROC parameters is checked against the appropriate keyword in the calibration  data to decide whether the calibrations should be processed prior to applying them to the target data.<br>
<br>
So I believe you will need to put the appropriate flags in your calibration images.<br>
<br>
