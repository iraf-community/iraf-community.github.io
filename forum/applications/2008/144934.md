**Mike Fitzpatrick** wrote on Nov 24, 2008

{% raw %}
<div>
Darkcombine is a CL script calling CCDPROC and COMBINE, I suspect the double list is simply the output of these two tasks being run sequentially.<br>
<br>
As for the 'Cannot open image' messages:  these usually just mean the image does not exist (e.g. isn't readable by you, is in a different directory, etc).  Running darcombine directly on the 'Dark0*.imh' would indeed print a 'no images to combine' message if that template didn't match any valid image in the current directory.  Are you sure about the filenames, permissions and such for these images?  Can you say, IMSTAT the same 'Dark0*.imh" list or is that an error as well?<br>
<br>
-Mike
</div>

**Mike Fitzpatrick** wrote on Nov 24, 2008

{% raw %}
<div>
Image extension names must all be lower-case, i.e. a foo.fit will work, a foo.FIT will not.<br>
<br>
By 'converting to imh' did you actually use IMCOPY or RFITS or some other program to write out a .imh format?  Simply renaming a FITS file with a .imh extension would certainly explain the problem (the extension is used to determine the image type).<br>
<br>
-Mike
</div>

**Mike Fitzpatrick** wrote on Nov 24, 2008

{% raw %}
<div>
The use of "FIT" is not recognized as a valid extension even if you add it to the 'imextn' list.  You'll need to rename the files to have a lower-case extension, e.g.<br>
<br>
<pre><code>cl&gt; rename *.FIT fits field=extn</code></pre><br>
<br>
will rename all files with .FIT extensions to have .fits extensions.<br>
<br>
-Mike
</div>
{% endraw %}
