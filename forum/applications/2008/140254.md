# imcombine memory problem

**neilzim** wrote on Sep 29, 2008

{% raw %}
<div>
I'm trying to use the following script to median three images:<br>
<br>
<pre><code>
#! /iraf/irafbin/bin.macintel/cl.e -f

noao
images
immatch
printf (&quot;imcombine @darkin.lis darkout.fits\n&quot;) | cl()

logout
</code></pre><br>
<br>
where darkin.lis is a text file containing a list of three FITS filenames. It fails with the following error:<br>
<br>
<blockquote>Warning: Cannot open pixel file (/Users/neil/proj1640/DATA/9.8.08/Processed/DARK_D_196.fits)- Maybe min_lenuserarea is too large<br>
</blockquote><br>
<br>
DARK_D_196.fits is the first file on the darkin.lis input list. The fits file has 110 header keywords. Having read that the min_lensuserarea variable has to be at least 80 times the number of keywords, I set it to 10000 in the beginning of the script, but this didn't change anything. I also tried a suggestion I found somewhere else in this forum, <blockquote>set imcombine_maxmemory = 100000000</blockquote>--also no change there.<br>
<br>
The input FITS file size is 2048*2048 pixels*32 bits = 17 MB. Is this too large for imcombine to handle?
