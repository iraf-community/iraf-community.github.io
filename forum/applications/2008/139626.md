**Mike Fitzpatrick** wrote on May 29, 2008

{% raw %}
<div>
XC is declared as a foreign task in the CL, meaning that it is executed with a shell spawned to run the command.  That shell is not a normal login shell and so the environment typically comes from the .cshrc file and not the .login file, this means that the $path defined in .cshrc must include the directory where you've installed the local iraf commands.<br>
<br>
One way to check whether your paths are setup correctly is with a simple shell escape, e.g.<br>
<br>
<pre><code>cl&gt; !which xc</code></pre><br>
<br>
should return the path if it is found, or a 'command not found' otherwise.<br>
<br>
Cheers,<br>
-Mike
</div>

**Mike Fitzpatrick** wrote on May 29, 2008

{% raw %}
<div>
If you try running the 'xc' command outside of the CL does it work?  If you run it as "cl&gt; !!which cl" (i.e. with two exlamation marks) does it work?  In this second case, the '!!' forces the command to be executed in a Bourne shell, in the first case this should be the same shell as when you execute a foreign command.  In either case, 'command not found' is a shell message indicating a path problem.<br>
<br>
You might also try "cl&gt; !env" to dump the full environment -- look for the 'path' or 'PATH' variable to be sure it has /usr/local/bin, also check the SHELL variable to see which shell is being used.  This will tell you whether you need to edit your .cshrc file or .bashrc.<br>
<br>
Cheers,<br>
-Mike
</div>
{% endraw %}
