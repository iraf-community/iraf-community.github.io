I extract my echelle spectra using doecslit after flat-fielding and scattered light correction, i.e., all frames had their apertures "defined" already with apall (found and traced). When I use doecslit, IRAF crashes if I don't provide the apref parameter, for which I then have to use my original tracer (the bright star) but shouldn't I be using the aperture parameters I found with apall for each individual object instead? Why does IRAF need that parameter? Is it using that one instead of the parameters given in the database for each object? Is this a bug?<br>

<div>
Hello Ivan,<br>
<br>
Doecslit will not redo things it has already done unless the "redo" parameter is set.  So it should use any aperture database if present rather than redo aperture definitions.  A crash is, of course, a bug.  The fact it needs apref set would also be a bug.  I am not aware of a previous report of this behavior.  If putting a value in satisfies the task and lets you get things done then that is a workaround.  Unless it is a <em>show stopper</em> problem I won't pursue this further.<br>

Yours,<br>
Frank Valdes
