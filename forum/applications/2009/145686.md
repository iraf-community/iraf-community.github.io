**Mike Fitzpatrick** wrote on Mar 01, 2009

{% raw %}
<div>
The 'syntax error' looks like it coming from the CL, are you putting this command in a file or using it on the commandline directly?  It should be in a file, however there are some differences you need to make for it to work.<br>
<br>
Since you want to use Beijing as the observatory, I suggest you use the 'BAO' entry in the observatory database.  Also, your header does not have a UT keyword, I assume you want to use TIME-OBS at the ut value.<br>
The problem however is that both your DATE-OBS and TIME-OBS keywords aren't quoted as strings and particularly for DATE-OBS will cause a problem.  To put the values in quotes you can use commands like<br>
<br>
<pre><code>
hselect (&quot;test&quot;, &quot;time-obs&quot;, &quot;yes&quot;) | scan (s1)
hselect (&quot;test&quot;, &quot;date-obs&quot;, &quot;ye&quot;)s | scan (s2)
hedit (&quot;test&quot;, &quot;time-obs&quot;, &#x27;&quot;&#x27;//s1//&#x27;&quot;&#x27;)
hedit (&quot;test&quot;, &quot;date-obs&quot;, &#x27;&quot;&#x27;//s2//&#x27;&quot;&#x27;)</code></pre><br>
<br>
This will use the existing values but put them in quotes in the header, most likely you would wrap this in a small script to update many images.  With that done, you can use ASTHEDIT by putting the following in a test file called 'cmd':<br>
<br>
<pre><code>st = mst (@&#x27;date-obs&#x27;, @&#x27;time-obs&#x27;, obsdb(&quot;BAO&quot;,&quot;longitude&quot;))</code></pre><br>
<br>
and then execute<br>
<br>
<pre><code>cl&gt; asthedit test.fits cmd</code></pre><br>
<br>
Cheers,<br>
-Mike
</div>

**Mike Fitzpatrick** wrote on Mar 01, 2009

{% raw %}
<div>
<blockquote><br>
First, I have got many fits images. Say test01.fit, test02.fit......<br>
When I type in<br>
<br>
hselect ("test*.fit", "time-obs", "yes") | scan (s1)<br>
<br>
All the time-obs of the images are updated with the same time-obs, which is the time-obs of the first image</blockquote><br>
<br>
This is because your HSELECT is getting the values from many images but the scan is to a single variable and so all you get is the first value.  To process many images you would need to wrap things up into a script command and process them individually, e.g.<br>
<br>
<pre><code>
procedure fixit()
begin
    string fname

    files (&quot;test*.fit&quot;, &gt; &quot;imagelist&quot;)    # create a list of the files
    list = &quot;imagelist&quot;
    while (fscan (list, fname) != EOF) {
        hselect (fname, &quot;time-obs&quot;, &quot;yes&quot;) | scan (s1)
        hselect (fname, &quot;date-obs&quot;, &quot;ye&quot;)s | scan (s2)
        hedit (fname, &quot;time-obs&quot;, &#x27;&quot;&#x27;//s1//&#x27;&quot;&#x27;)
        hedit (fname, &quot;date-obs&quot;, &#x27;&quot;&#x27;//s2//&#x27;&quot;&#x27;)

        asthedit (fname, &quot;cmd&quot;)                  # fix the image
    }
end
</code></pre><br>
<br>
Note I'm using literal strings for the command filename and the image names, you would change these as needed.  Since the task doesn't have any parameters you would declare it as<br>
<br>
<pre><code>task $fixit = /path/fixit.cl</code></pre><br>
<br>
where the '$' indicates no params.<br>
<br>
The segmentaton violation I've seen when the DATE-OBS string isn't quoted (we'll fix this to catch it).  The HSELECT task only gets the current value, it is the HEDIT that does the change but be sure the 'update' parameter is set and verify the change.  In the above script you may want to just to the edits first and then run ASTHEDIT separately.<br>
<br>
Cheers,<br>
-Mike
</div>
