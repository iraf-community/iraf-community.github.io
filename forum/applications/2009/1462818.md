I'm having a problem with the convolve task in the images.imfilter<br>
package.<br>
<br>
ERROR (502, "floating point invalid operation")<br>
<br>
I have placed 4 files in the ftp area to show the problem.<br>
  rgx1.fits             an image that will pass through ok<br>
  rgx2.fits             an image that will cause the error<br>

but how?<br>
<br>

a higher data type (float, long, or scaled short, clipping out of range<br>
values, anything?) at the time of file creation? Avoiding additional<br>
intermediate files (wfits or change_pixtype) is desireable due to time<br>
constraints for getting the image processed and on its way.<br>

Richard

<div>
I think you're right about there being an overflow, but I think what you want is for the <u>input</u> image to be promoted before the calculation, rather than the output image once the overflow has happened.  In either case, there's no way to do this currently with the CONVOLVE task other than to use e.g. CHPIXTYPE to change the image type before using it.  The images appear to have had some bit of processing already, perhaps the type can be changed upstream in the pipeline?<br>
