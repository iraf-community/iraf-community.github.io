<div>
The 'logfile' parameter is a package param for IMRED (i.e. do an "cl&gt; epar imred"), but you can set it on the ccdproc() command line anyway.<br>
<br>
I'm assuming your script does not have a 'procedure' statement at the beginning?  In this case you can still declare it as a parameterless script but it effectively runs as if you had redirected to the cl.  Try renaming the file 'casleored.cl' and making it into a procedure script, i.e.<br>
<br>
<pre><code>
procedure casleored ()

begin

    .....include the script statements you already have

end
</code></pre><br>
<br>
This should be enough to turn your file into a procedure script.  Otherwise, if you just run ccdproc from the command line does the logfile grow just as large?<br>
<br>
-Mike
</div>

**Mike Fitzpatrick** wrote on Feb 26, 2009

{% raw %}
<div>
In procedure scripts you need to use "compute mode" syntax.  That is, your commands<br>
<br>
<pre><code>
#Move BIAS files
mkdir bias
mv bias*.fit bias/ </code></pre><br>
<br>
Needs to be written using the parenthesis and with arguments separated by commas, and with literal values in strings, e.g.<br>
<br>
<pre><code>
mkdir (&quot;bias&quot;)
mv (&quot;bias*.fit&quot;, &quot;bias/&quot;)</code></pre><br>
<br>
You only have parameters if something is declared in the 'procedure' statement and before the 'begin' line, since you don't have that use the original task statement "task $casleored = .....".<br>
<br>
I don't know where the @file stuff is coming from, none of the code you've posted uses it!<br>
<br>
-Mike
</div>
