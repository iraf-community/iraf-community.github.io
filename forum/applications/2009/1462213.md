# TPROJECT bug - output filenames

**Ray Butler** wrote on Jul 30, 2009

{% raw %}
<div>
Hi,<br>
<br>
I believe I have found a minor but irritating (aren't they all?!) bug in TPROJECT.<br>
It does not seem to be happy with a long filename for its output table.<br>
<br>
E.g. in testing (script excerpt), I found that this works:<br>
<br>
ratio="./GOOD/klwz0408_.txt"<br>
tproject (""//wavecal//"", ""//ratio//"", "Wavelength_um, Ratio_Flux", uniq-)<br>
<br>
...whereas this (and many similar variations on the long filename theme) doesn't work:<br>
<br>
ratio="./GOOD/klwz0408_x.txt"<br>
tproject (""//wavecal//"", ""//ratio//"", "Wavelength_um, Ratio_Flux", uniq-)<br>
ERROR: Cannot open file (./GOOD/klwz0408_x.txt)<br>
<br>
Just one extra character ("x") in the filename made it crash. The total string length here is 21 characters...is there perhaps an arbitrary 20 character limit? If so, it should be removed.<br>
<br>
[I stress that this is not because it's being asked to clobber the named output file...that file doesn't pre-exist].<br>
<br>
BTW, I'm using TABLES Version 3.8, Feb 2008, in the February 2008 Scisoft 7.1 Collection<br>
<br>
Cheers,<br>
Ray
</div>
{% endraw %}

<div>
As far as I can tell there is no arbitrary 20 char limit on the filename, and indeed I was able to call the task using the exact path you used.  It seems a little strange you are concatenating null strings on the variables, but even that worked for me.<br>
<br>
Note I was doing this in /tmp,  if I had to guess I'd say that perhaps your current directory is already some really long path and this is just pushing it past the limit (which depending on the vintage of the binary may be 64 chars but is 255 nowadays).  Otherwise, you might want to contact the STScI helpdesk (help@stsci.edu) to see if this is a known problem to them.<br>
<br>
-Mike
