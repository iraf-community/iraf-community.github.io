<div>
The geometrical interpretation of the coefficients that come out of a polynomial fit depends on assumptions and how the task is used.  If you use<br>
<br>
<pre><code>
fitgeometry = &quot;rotate&quot;
xterms = &quot;none&quot;
yterms = &quot;none&quot;
</code></pre><br>
<br>
and assume the rotation point is fixed (that is, does not shift) then the "xshift" and "yshift" values must satisfy an equation like:<br>
<br>
<pre><code>
xshift = xo * (1 - cos(theta)) + yo * sin(theta)
yshift = yo * (1 - cos(theta)) - xo * sin(theta)
</code></pre><br>
<br>
where (xo, yo) is the rotation point.  This follows from the model of the transformation: <br>
<br>
<pre><code>
xin = xo + (xref-xo) * cos(theta) - (yref-yo) * sin(theta)
yin = yo + (xref-xo) * sin(theta) + (yref-yo) * cos(theta)
</code></pre><br>
<br>
Therefore, you would need to solve the first set of equations given the output of geomap that tells you theta, xshift, and yshift.  You might have to flip the signs of the rotation (i.e use 360-theta).<br>
<br>
Since the measured positions would be expected to have some noise there will be some error in deducing (xo, yo).<br>
<br>
I hope this helps.<br>
<br>
Yours,<br>
Frank Valdes
</div>

<div>
Hi,<br>
<br>
GEOTRAN does not explicitly compute a rotation at all.  It computes coefficients to a polynomial function.  As described in the help the polynomial coefficients can be "interpreted" as a rotation for some forms of the polynomial.  But since it is not really fitting an equation with a rotation there is no specific rotation origin and, it follows, that it is not possible to constrain the origin even if you know what it is.<br>
<br>
As for the constraint to positive angles, this must be limited by the parameter file and the limit can be changed by the user.  However, even easier is simply to use angles greater than 180 degrees which is equivalent to  negative angles less than 180 degrees.  For instances an rotation of -10 degrees is the same as a rotation of 350 degrees.<br>
<br>
Frank Valdes
</div>

<pre><code>
string imtype,eka,toka
int ol,oj,oh,sizex,sizey
imhead(fname)|scan(imtype)
ol=strstr(&#x27;,&#x27;,imtype)
eka=substr(imtype,1,ol-1)
toka=substr(imtype,ol+1,strlen(imtype))
oj=strstr(&#x27;[&#x27;,eka)
oh=strstr(&#x27;]&#x27;,toka)
eka=substr(eka,oj+1,strlen(eka))
toka=substr(toka,1,oh-1)
x=int(eka)
y=int(toka)
=x
=y</code></pre>
