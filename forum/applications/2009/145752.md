<div>
Hi Frank,<br>
<br>
A quick stab in the dark:<br>
<br>
<blockquote><br>
NUMBER: 517<br>
MODULE: rv.rvidlines<br>
SYSTEM: V2.12-V2.12.1<br>
DATE:   Thu Feb  6 15:01:26 MST 2003<br>
FROM:   valdes<br>
<br>
BUG:    The task first parses the date keyword given in KEYWPARS which<br>
        sets the year, month, day, and optionally the UT.  But then<br>
        it parses the UT keyword given in KEYWPARS in the same way<br>
        as for the date.  If this keyword is not in YYYY-MM-DDTHH:MM:SS.S<br>
        format then the year, month, and day are clobbered the program<br>
        crashes.  So in this version there is no substitue to using<br>
        this format for the date and setting the UT keyword to<br>
        be the same as the date keyword.<br>
<br>
STATUS: Fixed in the next release.<br>
</blockquote><br>
<br>
This would explain a crash on v2.12 and not on v2.13, but it could also just be a platform difference.  If this doesn't fix it, could you upload a problem image to <a href="ftp://iraf.noao.edu/pub">ftp://iraf.noao.edu/pub</a> and post the parameters you're using so we can try to reproduce it?<br>
<br>
-Mike
</div>
