<div>
I want to spit out a gif file to standard output from a graphics program like splot or one of my rvsao tasks to serve over the Web.  Is there a way to do this using the g-gif graphcap entry in some way?  Ideally, I would like to avoid creating an intermediate file, but I can create and delete one if I have to. <div>
The default for the sgi2gif translator is to write to STDOUT when the input is either from STDIN or there is only one file.  So, if this is truly what you want then a slight tweak to the graphcap would look like:<br>
<br>
<pre><code>
g-gif|UNIX generic interface to multi-frame GIF file generator:\
        :DD=ugif,tmp$sgk,!{ sgidispatch sgi2gif -w $(PX) -h $(PY) \
        -bg 255 255 255 -fg 0 0 0 &lt; $F ; \
        rm $F.[1-8]; }&amp;:MF#8:NF:tc=sgi_image_format:
</code></pre><br>
<br>
i.e. remove the -root flag and redirect the $F filename.<br>
<br>
Whether this does what you want is another matter:  For web display you'll generally need to output some http header text like the mime-type for the client to make sense of it.  Since you're presumably already using a script of some kind you might consider just writing to a fixed filename and have the script return the gif file (on stdout if you like).  I've never actually tried this from within IRAF so you might check that the binary data on the stdout stream isn't messing up the parent CL session.<br>
<br>
Cheers,<br>
-Mike
</div>
{% endraw %}
