For an authoritative answer (I don't use this task) you should check with the STScI help desk (help@stsci.edu) since this is their task.  However, a quick scan of the code seems to indicate that the output fluxes only take into account the valid pixels (i.e. not the dqf-flagged ones).  The inellip param is supposed to apply the pre-defined ellipses and compute results from those, I'm not sure why it appears to be refitting.<br>
