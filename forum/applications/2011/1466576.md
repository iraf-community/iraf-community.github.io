# Bug? Does FITPSF output RSIGMA or HWHM?

**Chris Simpson** wrote on Jun 02, 2011

{% raw %}
<div>
Edit: should have said I'm running IRAF V2.15 on Fedora 13.<br>
<br>
I'm running digiphot.apphot.fitpsf on an image to fit circular gaussians (radguass) to stars but find that the values it outputs are always too large when compared to imexam. The help says that when fitting a radgauss function it outputs RSIGMA, where FWHM=2.35*RSIGMA. However, the values it outputs are consistent with the HWHM as measured by other packages, which made me wonder if the output was really what the documentation claimed.<br>
<br>
Trawling through the source code, I think the task is actually outputting the HWHM, as the apsfradgauss.x file has the following lines:<br>
<br>
Before fitting, it comes up with an initial guess for par[4] as:<br>
	par[4] = (fwhmpsf ** 2 / 4.0)<br>
<br>
After fitting it converts this back as follows:<br>
	par[4] = sqrt (abs(par[4]))<br>
<br>
and then there doesn't appear to be any more conversion before it's printed. So if fwhmpsf was the correct FWHM, then par[4] will, after fitting, have the value of 0.5*fwhmpsf (since it was not multiplies by 4 before the square root was taken), and this is what gets printed to the screen or file.<br>
<br>
Hence I think the value that fitpsf outputs claiming to be RSIGMA is really HWHM (in pixels). This explains my results.<br>
<br>
Can anybody confirm?
</div>
