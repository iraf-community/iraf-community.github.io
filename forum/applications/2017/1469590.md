**Mike Fitzpatrick** wrote on Apr 05, 2017

<div>
<br>
                This was reported once before but never resolved.  There are/were several known issues with FITPARAMS related to the 64-bit binary which might be fixed by using the 32-bit version of x_photcal.e.  Depending on your IRAF version this may already be installed under a 64-bit architecture (i.e. linux64 or macintel, use "show arch" to check yours) but you can verify it using a command like<br>
<br>
    % file /iraf/iraf/noao/bin.linux64/x_photcal.e                 # or 'bin.macintel'<br>
<br>
If it says 64-bit binary then get a new 32-bit version from either of<br>
<br>
    ftp://iraf.noao.edu/iraf/v216/support/linux/x_photcal.e<br>
<br>
    ftp://iraf.noao.edu/iraf/v216/support/macosx/x_photcal.e<br>
<br>
Download these in binary mode, reset the execute permissions and install in your iraf$noao/bin.linux64 or iraf$noao/bin.macintel directories.<br>
<br>
The cursor read itself is done in the CL so if the above doesn't fix it, try getting a new cl.e, ecl.e and vocl.e binary from those same ftp directories.  Download these in binary mode, reset the execute permissions and install in your iraf$bin.linux64 or iraf$bin.macintel directories.  Hope this helps.<br>
</div>
{% endraw %}
