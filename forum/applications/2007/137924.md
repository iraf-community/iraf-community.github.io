**Francisco Valdes** wrote on Aug 06, 2007

{% raw %}
<div>
Hi Nicola,<br>
<br>
Thank you for the data.  I was able to reproduce the problem easily and then debug the code.  The underlying problem was a step where the log of y1 is taken and then the anti-log.  Because of precision it was possible that<br>
<br>
10**(log10(3505.25)) = 3505.249<br>
<br>
When this value is then used in the interpolator routines (which themselves<br>
should do range checking but don't) it triggered an error.  I'm not sure what the work around should be and you may have to do some fudging to get the result you want.<br>
<br>
The bug log is below.  The problem has been fixed in the code for a future version.<br>
<br>
Yours,<br>
Frank<br>
<br>
NUMBER: 559<br>
MODULE: longslit.transform<br>
SYSTEM: -V2.12.3<br>
DATE:   Tue Aug  7 10:39:13 MST 2007<br>
FROM:   valdes<br>
<br>
BUG:    When using log resampling (xlog=yes or ylog=yes) it is possible to<br>
        get a segmentation error.  This is caused by taking the log and<br>
        anti-log of coordinates and not getting back exactly the same value<br>
        due to real precision problems.  This process caused an attempt to<br>
        go outside the valid range of the interpolator.  This may be a<br>
        rare problem but if it does happen one may be able to use the<br>
        x1, x2, y1, y2 values to work around the problem.  The workaround<br>
        for a future release is to use double precision and to impose<br>
        range limits on data passed to the interpolator.<br>
<br>
STATUS: Fixed for the next release.
