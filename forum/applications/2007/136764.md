# imexpr file name parsing problems

**Doug Mink** wrote on Feb 06, 2007

{% raw %}
<div>
This is either a shell bug or an imexpr bug.  When you give imexpr a command<br>
such as the following:<br>
<br>
im &gt; imexpr "a-b" out.fits a.fits b.fits<br>
<br>
it fails with the message<br>
<br>
Error: bad image parameter reference b.fits<br>
<br>
but<br>
<br>
im &gt; imexpr "a-b" out.fits ./a.fits ./b.fits<br>
<br>
works just fine.  From further testing, it looks like a.fits and b.fits are taken to be<br>
references to files assigned to imexpr.a and imexpr.b if not preceded by "/" and<br>
the self-reference crashes the program.  Can this be fixed?<br>
<br>
-Doug
</div>
{% endraw %}

**Mike Fitzpatrick** wrote on Feb 06, 2007

{% raw %}
<div>
Hi Doug,<br>
<br>
The confusion is because the task allows an expression parameter to be referenced as a keyword in an image, e.g. "a.itime" means the ITIME keyword from the image 'a'.  The task is seeing your "a.fits" an looking for a FITS keyword of the image 'a'.  In general, avoid simple single-char image names like this, but specifying the image without the extension will also work.<br>
<br>
<blockquote>Can this be fixed? </blockquote><br>
<br>
Yes, rename your images 8-)  Modifying the task to allow the keyword syntax and a special case of 26 filenames is a little more difficult.<br>
<br>
Cheers,<br>
-Mike
</div>
{% endraw %}
