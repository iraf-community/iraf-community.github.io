Hello Cristina,<br>
<br>
Yes your are allowed to have data which is only part of the full CCD.  It is important that the various SEC parameters are self-consistent and map to the<br>
same CCD pixels.  In other words, CCDPROC will check that what it identifies as the CCD pixels from CCDSEC match when doing bias subtraction and flat fielding.  It is possible for the zero and flat calibrations to be bigger than the object images and the program will automatically applied the proper subsection (again assuming the initial CCDSEC description was correct and self-consistent).<br>
<br>
My first comment is that IRAF sections are one indexed.  So<br>
<br>
BIASSEC = '[0:0,260:790]' / overscan portion of frame <br>
<br>
is incorrect.  It is also not clear to me from what you sent if the overscan consists of columns (almost always the case) or rows (which means the<br>
serial readout of the CCD is stored as colums which is unusual).  Another question about the overscan is whether there is a single column (maybe it is<br>
just column 1 if BIASSEC was really intended to be [1:1,260:790]).<br>
<br>
Next the sizes of the various sections must be the same.  The size is computed<br>
from [x1:x2,y1:y2] as  xsize=x2-x1+1 and ysize=y2-y1+1.  Any error about size mismatches would be based on differences in xsize and ysize.  In particular, the sizes of CCDSEC and DATASEC need to be the same.  However, a caveat is that in imred.ccdred these must match while in mscred.ccdred it is possible to have DATASEC be smaller by the binning factor.  Which CCDPROC are you using?<br>
<br>
In your case it looks like a 2x2 binning was done.  If you are using imred.ccdproc, or it is simpler to ignore the binning and treat everything as unbinned pixels, then you need to adjust CCDSEC to be something like DATASEC.  In fact it might be that you should just set CCDSEC to be the same as DATASEC.<br>
<br>
So maybe (!?) you need<br>
<br>
BIASSEC = '[1:1,*]   / Overscan is just the first column<br>
DATASEC = '[263:785,260:790]<br>
CCDSEC = '[263:785,520:1580]<br>
<br>
I hope this helps.<br>

Frank Valdes
