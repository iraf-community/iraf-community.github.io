**Mike Fitzpatrick** wrote on Jun 25, 2007

{% raw %}
<div>
In this case the culprit is most likely starting at line 204 of fabry$t_mkshift.x:<br>
<br>
<pre><code>
        # Compute deltas and sigmas
        call salloc (work, nstars, TY_REAL)

        do i =  2, nimages {
            call mkdelta (i, nstars, nimages, Memi[index+i-1],  Memr[x_table],
                        dx[i], sigx[i], work)
            call mkdelta (i, nstars, nimages, Memi[index+i-1],  Memr[y_table],
                        dy[i], sigy[i], work)
        }
</code></pre><br>
<br>
The mkdelta() procedure is declared such that 'work' is a real array, but it is being passed in as an int pointer.  Change the calls to 'Memr[work]' instead and you can start working through the next problem.<br>
<br>
The newer GCC compilers get pickier as they get older (as do I), you may find other type problems that used to be legal.  Most often these will be boolean/int type clashes (e.g. an int variable used as a boolean in an if-clause, checked against TRUE/FALSE instead of YES/NO, etc.   <br>
<br>
Cheers,<br>
-Mike
</div>
