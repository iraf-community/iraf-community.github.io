**Mike Fitzpatrick** wrote on Jun 06, 2007

{% raw %}
<div>
Okay, so the input image is fine and we can assume it's the processed image to XSLM that gets passed that is causing trouble.  So, if you copy the xdimsum$src/iterstat.cl file to another directory you can edit it and use the local copy for testing, e.g.<br>
<br>
<pre><code>
cl&gt; copy xdimsum$src/iterstat.cl /tmp
cl&gt; edit /tmp/iterstat.cl

then change the l ines which read:

           imstatistics (img // usec, fields=&quot;mean,stddev,npix,midpt,mode&quot;,
                lower=lower, upper=upper, nclip=maxiter, lsigma=nsigrej,
                usigma=nsigrej, binwidth=0.1, format-, cache-) | scan (mn,
                sig, npx, med, mod)

to insted read:
          imstatistics (img // usec, fields=&quot;mean,stddev,npix,midpt,mode&quot;,
                lower=lower, upper=upper, nclip=maxiter, lsigma=nsigrej,
                usigma=nsigrej, binwidth=0.1, format-, cache-)

            imstatistics (img // usec, fields=&quot;mean,stddev,npix,midpt,mode&quot;,
                lower=lower, upper=upper, nclip=maxiter, lsigma=nsigrej,
                usigma=nsigrej, binwidth=0.1, format-, cache-) | scan (mn,
                sig, npx, med, mod)
</code></pre><br>
<br>
This just runs the IMSTAT command twice, once to output to the screen so you can see the results, and second to do it as before. <br>
<br>
I think what's happening is that the IMSTAT is failing somehow and so the 'mn' variable isn't being loaded in the scan() call, what you may see instead is an error of some kind.<br>
<br>
-Mike
</div>

**Mike Fitzpatrick** wrote on Jun 06, 2007

{% raw %}
<div>
<blockquote><br>
Warning: Cannot open pixel file (_skytemp)- Maybe min_lenuserarea is too large<br>
_skytemp is not an image or a number<br>
Error reading image _sclmsktemp[50:1998,50:1998] ... <br>
</blockquote><br>
<br>
These are the errors:  The cannot open pixel file may mean you've got an invalid 'imdir' variable defined, this is the location the pixel files are stored for .imh format images.  You can reset this in your login.cl file, or on the command-line as<br>
<br>
<pre><code>cl&gt; reset imdir = HDR$

or

cl&gt; reset imtype = &quot;fits&quot;
</code></pre><br>
<br>
The first command says to put the .pix file in the same directory as the .imh file, the second says to use FITS files instead.  Either way, do a 'flpr 0' (zero not oh) and try the task again.  Let me know what happens.<br>
<br>
-Mike
</div>
