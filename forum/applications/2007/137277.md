If you see in datapars config file <br>
you may see where:<br>
<em>itime,r,h,1.0,,,'Exposure time'<br>
exposure,s,h,'',,,'Exposure time image header keyword'</em><br>
<br>
In datapars help file you may read:<br>
<em>If exposure is undefined or  not present  in  the  image  header  a warning message is issued and the value of itime is used. The itime units are arbitrary  but  must  be consistent  for  images analyzed together.</em><br>
You may use any of this parameters. (exposure&lt;-&gt;itime,filter &lt;-&gt;ifilter,obstime &lt;-&gt; otime,airmass &lt;-&gt; xairmass)<br>
I think it is easier use keyword name, which are <br>
standart for every telescope.<br>

Okay. Partly a false alarm. Things work how they used to. The phot tasks don't strip the image extension off by default. I was falsely remembering that they did. While it is up, these tasks SHOULD strip the image extension when default is used. Here's the help page for daofind:<br>
<br>
<blockquote><br>
    output  = "default"<br>
        The  name  of  the  results  file  or  the results directory. If<br>
        output is "default", "dir$default" or a directory  specification<br>
        then  a results file name of the form dir$root.extension.version<br>
        is constructed, where dir is the directory,  root  is  the  root<br>
        image   name,  extension  is  "coo"  and  version  is  the  next <br>
        available version number for the file. If the output  string  is<br>
        undefined  then  no  output  file is created. One output file is<br>
        created for every input image.<br>
</blockquote><br>
<br>
The other tasks agree with this too.<br>
