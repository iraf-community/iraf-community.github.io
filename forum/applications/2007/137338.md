**Mike Fitzpatrick** wrote on May 12, 2007

{% raw %}
<div>
Compilation requires that you define a $iraf and $IRAFARCH environment variable (in your .cshrc or .bashrc file) so the system will know where to find IRAF and your binary architecture.  For you these values should probably iraf=/Local/Iraf/iraf/ (note the trailing '/' is required, the capitals are from your post) and IRAFARCH=redhat (for Fedora).<br>
<br>
If it still doesn't work, check that the xpp.e and rpp.e will actually run, e.g.<br>
<br>
<pre><code>
% cd $iraf/unix/bin.redhat
% ./xpp.e
</code></pre><br>
<br>
Note any system errors (e.g. missing libs, bus error etc), otherwise you wouldn't normally see anything output.  Also note that a $host variable defined for other purposes may interfere with this working.  Post back if you still have problems.<br>
<br>
Cheers,<br>
-Mike
</div>

<div>
<blockquote><br>
Now I set-up all<br>
variables in cl.csh script(which I run)<br>
(I copy some files from/Local/Iraf/iraf/ to ~/IRAF/<br>
to have access to them)<br>
setenv iraf "/Local/Iraf/iraf/"<br>
setenv IRAFARCH "redhat"<br>
setenv host ~/IRAF/unix/<br>
setenv hlib ~/IRAF/unix/hlib/<br>
setenv hbin ~/IRAF/unix/bin.redhat/<br>
setenv arch ".redhat"<br>
setenv IRAFBIN ~/IRAF/bin.redhat/<br>
set MACH = $IRAFARCH<br>
set file = ~/IRAF/bin.redhat/cl.e </blockquote><br>
<br>
The use of "~/IRAF/unix/...." here should be "$iraf/unix/....".   The $iraf/bin.redhat directory is for the core system tasks (PLOT, IMAGES, etc), while $iraf/unix/bin.redhat are the "HSI binaries" for things related to compilation, graphics translators, etc.  When the system is installed, a link called 'xpp' is made to the 'xpp.e' binary in the iraf$unix/bin.redhat.  Variables like $IRAFARCH and $arch are used to locate the binaries.  Hope this helps.<br>
<br>
-Mike[/quote]
