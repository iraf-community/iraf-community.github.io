One at a time the ra &amp; dec are converted to x,y coords and written to a file. Then a command variable is prepared by the code:<br>

<div>
This isn't really a bug, it is a funny interaction with the way the bash shell handles the stdin/stdout streams.  Specifically what's happening is that on process-startup the IRAF main issues a F_CANCEL on the input stream to cancel any pending input coming from the CL (e.g. from an earlier interrupted task).  The effectively causes a rewind on stdin when using the redirection in a bash shell.<br>
<br>
When you run the binary directly you can workaround this by calling the task as e.g.<br>
<br>
<pre><code>
/iraf/iraf/bin.linux/x_images.e -d /dev/null imexamine ......
</code></pre><br>
<br>
where the '-d /dev/null' says to run as a detached (i.e. background) process.  Using the sort of script you have the task is still reading from the parent CL process as a connected subprocess.<br>
<br>
I'd also suggest you have a look at the notes on writing host-level CL scripts, this may do what you as well:<br>
<br>
<a href="http://iraf.noao.edu/iraf/web/new_stuff/cl_host.html">http://iraf.noao.edu/iraf/web/new_stuff/cl_host.html</a>
</div>
{% endraw %}
