<div>
A quick reply without looking at your data just yet:  I think the answer is explained in Buglog 575, specifically<br>
<br>
<blockquote><br>
NUMBER: 575<br>
MODULE: all tasks using the icfit tools<br>
SYSTEM:  - V2.14<br>
DATE:   Mon Jun 28 14:08:48 MST 2010<br>
FROM:   valdes<br>
<br>
BUG:    The icfit tools are used in many tasks involving 1D function fitting.<br>
       These include onedspec tasks like continuum and identify.  The<br>
       tools provide for a grow radius where any sigma rejected points<br>
       have neighbors also rejected.  The logic was wrong<br>
       in two ways; one where if a neighbor was also a rejected point<br>
       it did not also reject neighbors of that point, and another where<br>
       the grow radius units were used both as in pixels and in user<br>
       coordinates.  In reality the grow is supposed to be in user<br>
       coordinate units.  In addition some tasks, like continuum, incorrectly<br>
       described the units adding to the confusion.<br>
<br>
STATUS: Fixed for the next IRAF release.<br>
</blockquote><br>
<br>
So the difference you see is in the behavior of the 'grow' parameter between the two versions, indeed if you set grow=0 then you get the same results in both versions.  Since the v2.16 change is a fix so the code behaves correctly then this is the version you should use.<br>
<br>
Post back if this doesn't explain what you're seeing.
</div>
{% endraw %}
