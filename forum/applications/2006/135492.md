# Stellar grouping issues

**rachel** wrote on Jul 18, 2006

{% raw %}
<div>
I was wondering how PSF selects what stars it includes in a group and if there was any way this could be changed. The field I am working on contains a density of stars such that allstar doesn't seem to be able to subtract them. Some of the stars only have 1 pixel of separation. It leaves behind clusters of stars and this seems to be caused by some kind of grouping issue. <br>
I have set psfrad=3 and fitrad=1.57 which is equal to the FWHM of the brightest, unsaturated star. Is there any other task or parameter that determines grouping of stars? In daopars, there is a parameter called maxgroup that allows no more than 100 stars fit per group (this can't be made any higher). Is there a possibility that because of this parameter and the proximity of the stars to one another, there is not a way to fit and subtract these stars?<br>

**Philip Massey** wrote on Jul 18, 2006

{% raw %}
<div>
My own guess is that this is a problem related to sky subtraction, not grouping, For one thing, "allstar" does not use the standard grouping used by NSTAR<br>
(and, I believe, by PSF).  So, it might be an issue related to sky determination.<br>
You might try setting daopars.fitsky to "yes".<br>
<br>
But, if you want to experiment with the grouping issue, you can readily<br>
set the maximum number of stars in a group to &gt; 100.  I don't think this makes<br>
sense, but you can do it.  Simply do a <br>
<br>
daopars.maxgroup.p_maximum=300 (say)<br>
<br>
and then you will be able to epar daopars and set maxgroup to a larger value.<br>
But, I don't think this is going to get you where you want to go.<br>
<br>
The only stars that are going to affect the PSF are those within a PSFrad. I've never heard of restricting this to only 3 pixels, but I sure hope you don't have<br>
&gt;100 stars within 3 pixels of a star you're picking for a PSF star!javascript:emoticon(':roll:')<br>
<br>
Is there really no light coming from the brightest star you're interested in<br>
beyond 3 pixels?  If there is, you need to make the PSFrad to whatever this value is.   Sounds like your data is horribly undersampled, and that daophot<br>
isn't a good solution.<br>
<br>
---phil
