# Correcting Row Offsets?

{% raw %}
<div>
I've got some images which suffer from time variable noise which offsets each row of pixels by a small amount from the rows above and below it.  The noise can be corrected in most cases by adding a small offset to each row such that the median of the row matches the median of the entire image.  I've written a script to do this in IDL and it works beautifully, but I am looking for a way to do this in IRAF so that I can keep all my reductions in one script rather than jumping back and forth between IRAF and IDL.<br>
<br>
Does anyone know of a clever way to do this?  I've been looking for the right type of filter for it, but so far I haven't found anything that works nearly as well as my simple IDL routine.<br>

**Mike Fitzpatrick** wrote on Jan 29, 2006

{% raw %}
<div>
If I understand your problem correctly, to each row you want to add something like the difference between the median of the row and the median of the entire image, right?  Not quite a one-liner but try<br>
<br>
    real   im_mean<br>
    imstat (oldimage, fields="midpt", format-) | scan (im_mean)<br>
    imexpr ("a + (b - median(a))", newimage, a=oldimage, b=im_mean)<br>
<br>
In the expression 'a' is processed for each line in the image, '(b-median(a))' is a scalar value that's the offset I think you're looking for.  See the help pages for IMSTAT and IMEXPR for details.<br>
<br>
Cheers,<br>
-Mike
</div>
{% endraw %}

**Mike Fitzpatrick** wrote on Jan 29, 2006

<div>
IMEXPR loops through the image rows automatically.  What I means is that<br>
'a' (in this case) is a vector operand containing all the pixels in a row of<br>
the image, the expression is repeated/re-evaluated for each row.  If you want<br>
to operate on only a few rows then you can just tack the section onto the image name when you call it, or see the use of the I/J/K builtins for using the row/col/band number in the expression.<br>
<br>
-Mike
</div>

<div>
<blockquote>real im_mean <br>
imstat ("test1", fields="midpt", format-) | scan (im_mean) <br>
imexpr ("a + (b - median(a)", "test2", a="test1", b=im_mean) <br>
</blockquote><br>
   Note there is a missing closed paren in your expression.<br>
<br>
<blockquote>I get the following error after running the imexpr line: <br>
ERROR: ambiguous parameter `a' within `&lt;searchpath&gt;' <br>
</blockquote><br>
    The syntax above is the normal script 'program mode', the error message sometimes happens due to quirks in the CL and can usually be cleared by declaring a dummy parameter 'a' to avoid the message, e.g.<br>
<br>
    string a<br>
    real im_mean <br>
          :<br>
<br>
<blockquote>Also, I still don't understand how this is looping though the rows of the image. Did I just get lucky and imexpr naturally loops through rows? Would this be different if I had to operate on columns? </blockquote><br>
<br>
    Right, the task is meant to apply the expression to the entire image, it does so one-row at a time.  If you wanted to work on columns I suppose you could simply IMTRANSPOSE the image before/after IMEXPR or loop using an image section.<br>
<br>
-Mike
</div>
