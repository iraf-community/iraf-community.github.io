**Mike Fitzpatrick** wrote on Jun 06, 2006

{% raw %}
<div>
I just tried this using the latest IRAF/DS9 as<br>
<br>
<pre><code>
cl&gt; ellipse dev$wpix foo.tab
cl&gt; isoexam foo.tab dev=red
</code></pre><br>
<br>
and saw no problems.  You might try issuing a "gflush" command after isoexam, especially if you're using an older IRAF version (there was a known bug with the graphics not flushing automatically).  If this is an especially large table the graphics buffer may be too small and can be resized with<br>
<br>
<pre><code>
cl&gt; reset cmdbuflen = 256000 ; gflush
</code></pre><br>
<br>
The 'gflush' here reinitializes the graphics system and is required.  You can put this in your login.cl/loginuser.cl for future use (or edit the value there and uncomment).  Lastly, try doing<br>
<br>
<pre><code>
cl&gt; set disable_wcs_maps = &quot;&quot;
</code></pre><br>
<br>
before running ISOEXAM, this works around an old bug in DS9.  You can also try a newer DS9, but if you still have problems please post your IRAF and DS9 version and platform as well as an example like the above using dev$pix and default parameters (unlearning tasks involved couldn't hurt either).  Hope this helps.<br>
<br>
Cheers,<br>
-Mike
</div>
