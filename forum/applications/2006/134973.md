<br>
Here is my answer to my quiestion, thanks to Maureen Conroy, who looked at the source code of reidentify and told me the following:<br>
<br>
the database id file looks like this, for a given aperture:<br>
<br>
# Wed 20:26:52 07-Jun-2006<br>
begin   identify COMP_f.ms - Ap 1<br>
        id      COMP_f.ms<br>
        task    identify<br>
        image   COMP_f.ms - Ap 1<br>
        aperture        1<br>
        aplow   29.99<br>
        aphigh  35.99<br>
        units   Angstroms<br>
        features        44<br>
                  4.82 6646.54164  6646.5407   4.0 1 1<br>
                 30.35 6644.66133  6644.6635   4.0 1 1<br>
                 43.41 6643.69688  6643.6976   4.0 1 1<br>
                 96.70 6639.74356  6639.7403   4.0 1 1<br>
                107.84 6638.91354  6638.9119   4.0 1 1<br>
                117.14 6638.21926  6638.2207   4.0 1 1<br>
                 and so on......<br>
<br>
where the last column is the actual weight, what is 1 by default. If you have a reference id file you use in reidentify (under the current database directory), than you can go into this text file and with a script --based on the wavelength as identification-- one can edit the last column and set a given weight for a given line, in all aperures if multispectra file. The weight  can be a float, doesn't have to be an integer. After this file is preapred, and reidentify is run, it will read the user set weights and apply those in the fit.<br>
<br>
So, that's tha way to set weight for lines automatically in a data reduction pipeline: prepare a 'master id reference' file and call it as a reference.<br>
Thanks for Maureen Conroy (Harvard-Smithsonian C fA) again!<br>
<br>
gabor
</div>
