<div>
A 'cannot open pixel file' typically means the 'imdir' variable is improperly defined (e.g. points to a directory that doesn't exist, bad syntax when using HDR$, etc).  The imdir defines where the .pix half of an OIF image-format goes and is defined in the login.cl file or can be reset on the commandline using<br>
<br>
<pre><code>cl&gt; reset imdir = &quot;/path/imdir/&quot;       # &lt;-- note trailing &#x27;/&#x27;
cl&gt; reset imdir = &quot;HDR$&quot;       # put .pix in same dir as .imh
cl&gt; reset imdir = &quot;HDR$pix/&quot;     # put .pix in a &#x27;pix&#x27; subdir of .imh
cl&gt; flpr 0           # zero, not &#x27;oh&#x27;
</code></pre><br>
<br>
The flpr is needed to reinitialize tasks in the cache.<br>
<br>
Likewise, on input the message means the imdir specified in the .imh head doesn't contain a valid path to the .pix file.  This can be fixed by editing the i_pixfile header field with the correct path (see the FAQ).  Lastly, if you can't even IMHEAD the image then it may be a byte-swap issue e.g. as when trying to read an old image from a tar backup.  In this case, the pixfile path is also commonly wrong and needs editing.<br>
<br>
Cheers,<br>
-Mike
