# imshift

**ping zhao** wrote on Apr 13, 2006

{% raw %}
<div>
I have a question about using imshift.  I found that imshift cuts off the <br>
images shifted out of the original boundary.<br>
<br>
e.g.  original image is 1000x1000 pixels<br>
when imshift it by [200,300], the output image is still 1000x1000, with the <br>
pixel positions shifted, but only the original 800x700 image pixels are saved in the <br>
output.  The rest is lost because they are outside the 1000x1000 boundary.<br>
Is there a way to save the full image when doing the imshift?  So in this <br>
example the output should be 1200x1300 in size.<br>
<br>
Thank you!
</div>
{% endraw %}

**Mike Fitzpatrick** wrote on Apr 13, 2006

{% raw %}
<div>
Ping,<br>
<br>
In the simple example you gave I'd just use ARTDATA.MKPATTERN to create a blank larger image of the desired size and then IMCOPY the image into the appropriate image section of the output image.  Note this only works for integer shifts, most mosaicing applications will require fractional shifts and I'm not sure why you'd need the blank area, but also have a look at the various combine tasks (e.g. IMCOMBINE, MSCCOMBINE, etc).  Hope this helps.<br>
<br>
Cheers,<br>
-Mike
</div>
{% endraw %}

**Mike Fitzpatrick** wrote on Apr 13, 2006

{% raw %}
<div>
Since you already know the shift you're after, the LINTRAN task can apply that to a list of positions for you to correct for each image.<br>
<br>
Another solution:  Since the ra/dec will be the same, look at WCSCTRAN to convert that 'world' position to a 'logical' one for the image, i.e. compute the (x,y) for the star given the (ra,dec) using the image wcs.<br>
<br>
-Mike
</div>
