**Francisco Valdes** wrote on Jan 05, 2006

{% raw %}
<div>
When the size of a section is discussed, such as with the error message, the size is computed as (max-min+1).  With binning you then have to add a binning factor.  In this case it seems the sizes are <em>really</em> not the same.<br>
<br>
DATASEC = [9:1032,1:1024] = 1024x1024 -&gt; x2 = 2048x2048<br>
CCDSEC = [2049:4128,2049:4098] = 2080x2050<br>
<br>
I think your CCDSEC should be [2049:4096,2049:4096]<br>
<br>
It looks like the CCDSEC is including the psuedo bias pixels/region.  But the definition is that CCDSEC is the active CCD pixels that map to the pixels stored in the image in the DATASEC.<br>
<br>
The note you found about a bug being fixed was probably an "off by one" error.<br>
<br>
BTW the attempt to use binned pixels for what is in the image file and unbinned pixels to refer to the CCD is correct for MSCRED.  In the earlier CCDRED package this was not the case.<br>
<br>
Yours,<br>
Frank
</div>

**Francisco Valdes** wrote on Jan 05, 2006

{% raw %}
<div>
Hi Vicky,<br>
<br>
The error message means that CCDPROC decided that a calibration file, one needed to process the specified file which is the flat in this case, needs additional calibration.  The reason it is an error is that in MSCRED.CCDPROC it cannot automatically recurse and process any dependencies.<br>
<br>
So the possiblities I can think of are:<br>
<br>
<ul><br>
<li> You did not have processing turned on when you ran ZEROCOMBINE<br>
<li> You change the processing options between processing the zero and processing the flat; e.g. you turned on "fixpix" but it was not turned on when you did the zero.<br>
<li> There is something going on with the fixpix option which you have turned on but don't have anything specified for the fixfile.<br>
</ul><br>
<br>
It seems funny to me that you don't have overscan and trim turned on, though it is legal and might mean you don't have any or useful overscan information.<br>
<br>
I hope this help.<br>
<br>
Frank
</div>
