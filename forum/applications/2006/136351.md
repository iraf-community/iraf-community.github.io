<div>
Pat,<br>
<br>
See the description of the 'addonly' parameter to HEDIT, this will cause the field to be added only if it doesn't already exist in the header (i.e. add a new value, don't overwrite an existing one).  Tasks like SETAIRMASS can add some of what you're after, but it sounds like you want a script that loops over a list of values for each image and then just calls HEDIT.  See also the HFIX task as a way of running some arbitrary program (e.g. an awk or perl script) over a header.  Hope this helps.<br>
<br>

**Mike Fitzpatrick** wrote on Nov 23, 2006

<div>
Pat,<br>
<br>
<blockquote>What I thought might work was if I used hselect to select a field, and the field doesn't exist then it would return a "zero" value. Thing is it doesn't seem to be possible to equate the value to a variable, can only write it to file and then read the value FROM file.[/code]<br>
<br>
A new 'missing' parameter was recently added to HSELECT just for this purpose, i.e. to have the task print out something predictable when a keyword isnt present.  This is actually available in the Nov22 macintel binary release but unfortunately not yet for other platforms.<br>
<br>
[quote:b3e947730b]Which is a bit bulky, and don't like the idee of making and deleting tempfiles so many time's. ......</blockquote><br>
<br>
This is exactly what "scan from pipe" is for, i.e.<br>
<br>
<pre><code>hselect(img, field, yes) | scan (s1)
if (nscan() == 0) 
     hedit (...)
else
    .....
</code></pre><br>
<br>
Note we use the nscan() function to test whether anything was read to avoid the problem with s1 not being changed from a earlier read.  Hope this helps.<br>
<br>
Cheers,<br>
-Mike[/code]
