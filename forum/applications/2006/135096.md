**Mike Fitzpatrick** wrote on May 30, 2006

{% raw %}
<div>
Have a look at STARFIND for creating object detection catalogs, and XYXYMATCH to match them up (i.e. will solve the rotation/shift between images).  It should be possible to automate this in a script and get the information needed to adjust each image to a reference frame.<br>
<br>
-Mike
</div>

**Mike Fitzpatrick** wrote on May 30, 2006

{% raw %}
<div>
Crowded fields can indeed be a problem, but keep in mind you only need to use enough stars to get a solution.  Tasks like TSELECT and TSORT in the TABLES package will let you use e.g. only the 100 brightest objects.<br>
<br>
The real problem though I think is in your 'tolerance' parameter setting of 50 pixels:  what this means is any star within a 50 pix radius is a possible match.  Try restricting this a bit more so the final solution is more accurate.  Hope this helps.<br>
<br>
Cheers,<br>
-Mike
</div>
