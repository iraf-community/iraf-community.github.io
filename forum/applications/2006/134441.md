MSCRED is not directly tied to the IRAF system releases so I don't think there should be anything in 2.12.2a that would change the behavior of mscred.  Is the data that fails and that which works at the 90" the same data?  One thing the merging requires is certain keyword values that can be used to identify which amps are from the same CCD.  Normally this would be CCDNAME which need to be identify strings for amps from the same CCD and different names between CCDs.<br>

**Francisco Valdes** wrote on Feb 13, 2006

{% raw %}
<div>
There are four things I can think that would result in nothing happening.<br>
<br>
<ul><br>
<li> The "merge" parameter is not set to yes.  :oops: <br>
<li> The data has not been processed for overscan and trim.  The program will not let you merge until after the overscan has been used and trimmed.  I guess if you simply trim the overscan it would also work.<br>
<li> The CCDNAME keywords are not setup correctly as I mentioned in my previous post.<br>
<li> The data uses different keywords than the default and then instrument translation file is not set or right.<br>
</ul><br>
<br>
The last one came to my mind when you mentioned the instrument file.  An instrument file is not absolutely required if the header uses exactly the keywords and imagtyp values the program requests.  So you might check to see if the mountain setup does indeed use a translation file.  If this still doesn't point you to the answer send a header listing of two extensions that should end up merged.<br>
<br>
Frank
</div>
