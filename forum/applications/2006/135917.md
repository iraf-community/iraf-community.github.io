<br>
<pre><code>ERROR: Impossible type conversion when accessing image header parameter (imagetype)
</code></pre><br>
<br>
I've tried<br>
<br>
<pre><code>hselect 0*.fit $I &quot;imagetyp ?= &#x27;*DARK*&#x27;&quot;

hselect 0*.fit $I &quot;imagetyp ?= DARK&quot;

</code></pre><br>
<br>
and probably some others.   The actual field in the headers reads<br>
<br>
<pre><code>IMAGETYP = DARK</code></pre><br>
<br>

</div>
{% endraw %}

**Mike Fitzpatrick** wrote on Sep 28, 2006

{% raw %}
<div>
Try<br>
<br>
<pre><code>hselect *.fits $I &quot;imagetyp ?= &#x27;DARK&#x27;&quot;</code></pre><br>
<br>
The '?=' is the string-equality operator and the value needs to be in a single quote.<br>
<br>
-Mike
</div>

The answer is in how you listed the value of the IMAGETYP keyword itself, i.e.<br>
<br>
<pre><code>IMAGETYP = DARK</code></pre><br>
<br>
The DARK is meant to be a string value and should be in quotes, i.e.<br>
<br>
<pre><code>IMAGETYPE = &#x27;DARK&#x27;</code></pre><br>
<br>
In that case your first example would have worked.<br>

**Mike Fitzpatrick** wrote on Sep 28, 2006

{% raw %}
<div>
You can use the HFIX task to run an arbitrary command over all the image headers and edit only those that match "DARK", e.g.<br>
<br>
<pre><code>
hfix *.fits command=&quot;!cat $fname | sed -e \&quot;s/DARK/\\&#x27;DARK\\&#x27;/g\&quot;  &gt; _z ; mv _z $fname&quot;</code></pre><br>
<br>
The various backslashes are escapes needed for the quotes, but basically you're using 'sed' to edit the headers.<br>
<br>
-Mike
</div>
{% endraw %}
