# Y2k bug in astcalc()

**jstottsj** wrote on Apr 05, 2010

{% raw %}
<div>
I stumbled across this while trying to add ST and AIRMASS headers to some old data.  astcalc() seems to be mis-handling two-digit years.<br>
<br>
Suppose I have a command file for astcalc() like this:<br>
<pre><code>
# Only difference is the date string passed to mst(), so they should be the same
printf(&quot;%10s %s\n&quot;, $GMD, mst($GMD, &quot;20:00:00&quot;, 110.000))
printf(&quot;%10s %s\n&quot;, $D,   mst($D,   &quot;20:00:00&quot;, 110.000))

# Supply my own strings, year is pre-2000 as a check
GMD = &quot;1995-04-05&quot;
D   = &quot;05/04/95&quot;

printf(&quot;%10s %s\n&quot;, GMD, mst(GMD, &quot;20:00:00&quot;, 110.000))
printf(&quot;%10s %s\n&quot;, D,   mst(D,   &quot;20:00:00&quot;, 110.000))
</code></pre><br>
<br>
Since the only difference is the formatting of the date string, nothing should change.<br>
<br>
When I feed it into astutil, what I actually see is<br>
<blockquote><br>
astutil&gt; astcalc commands=astcalcBug.txt <br>
mst() using current date settings<br>
<br>
2010-04-05 1:36:02.36<br>
  05/04/10 1:32:57.62<br>
<br>
mst() using pre-2000 date settings<br>
<br>
1995-04-05 1:34:35.50<br>
  05/04/95 1:34:35.50<br>
</blockquote><br>
<br>
-JS

**Mike Fitzpatrick** wrote on Apr 05, 2010

{% raw %}
<div>
Thanks for the report.  The task is working as described, although perhaps not as expected.  Whether this is a 'bug' is a question for philosophers and poets.<br>
<br>
What's described is that the '$D' builtin variable returns the date DD/MM/YY format, what you might not expect is that the FITS time standard says this format is meant to be interpreted as a pre-Y2K date and so the task is technically doing the right thing by treating this as a 1910 date.<br>
<br>
Since I couldn't think of a good (or bad) reason why anyone would want today's date 100 years ago, I've modified the task for the next release so the $D returns the date string as the post-Y2K YYYY-MM-DD format.  Using your earlier test shows the results are now the same.  If you tell me what platform you're on and need the fix quickly I can give you a new binary, otherwise this is fixed in the next release.<br>
<br>
Cheers,<br>
-Mike
</div>
