**Mike Fitzpatrick** wrote on Nov 30, 2010

{% raw %}
<div>
I was hoping it was something easy.<br>
<br>
I looked around and found a machine that did, in fact, reproduce the problem.  However, this was a machine running a 32-bit kernel and the problem is only reproducible using the 64-bit 'macintel' binaries.  Running the native 'macosx' binaries works fine.<br>
<br>
Check whether you define an IRAFARCH environment variable in your .cshrc/.login file, if you do then try setting the value to be 'macosx'.<br>
<br>
Next, at the unix prompt, issue the command "uname -m".  If the value is x86_64 then you are running a 64-bit kernel, if it's 'i386' then you may have a 64-bit capable machine, but it's booted to the 32-bit kernel.  Another way to check is with the command<br>
<br>
<pre><code>/usr/bin/system_profiler | grep 64-bit</code></pre><br>
<br>
The value should be 'yes' if you're using the 64-bit kernel.  Further<br>
info on booting your system to 64-bit mode can be found at<br>
<br>
  <a href="http://www.hackaapl.com/forcing-snow-leopard-os-x-to-boot-64-bit-kernel/">http://www.hackaapl.com/forcing-snow-leopard-os-x-to-boot-64-bit-kernel/</a><br>
<br>
and elsewhere via a Google search.
</div>
{% endraw %}
