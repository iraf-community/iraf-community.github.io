**AnTaR3s** wrote on May 19, 2010

{% raw %}
<div>
Here is the way you get ccdlist to work:<br>
<br>
ccdlist requires the Header-keyword IMAGETYP to contain a certain string<br>
<br>
            ""      - (the null string) all image types<br>
            object  - object images<br>
            zero    - zero level images such as a bias or preflash<br>
            dark    - dark count images<br>
            flat    - flat field images<br>
            illum   - illumination images<br>
            fringe  - fringe correction images<br>
            other   - other image types defined in the translation file<br>
            none    - images without an image type parameter<br>
            unknown - image types not defined in the translation file<br>
<br>
So a Biasframe for example has to contain the keyword "zero" <br>
To edit the Header, use the task "hedit" in a way similar to this:<br>
<br>
images  =                 foo*  images to be edited<br>
fields  =             IMAGETYP  fields to be edited<br>
value   =               object  value expression<br>
(add    =                  yes) add rather than edit fields<br>
(addonly=                  yes) add only if field does not exist<br>
(delete =                  yes) delete rather than edit fields<br>
(verify =                   no) verify each edit operation<br>
(show   =                  yes) print record of each edit operation<br>
(update =                  yes) enable updating of the image header<br>
(mode   =                   ql)<br>
<br>
this will write the string object into the Keyword header information IMAGETYP.<br>
<br>
now you can list the images with ccdlist like this:<br>
<br>
images  =               *.fits  CCD images to listed<br>
(ccdtype=               object) CCD image type to be listed<br>
(names  =                  yes) List image names only?<br>
(long   =                  yes) Long format listing?<br>
(ccdproc=                     ) CCD processing parameters<br>
(mode   =                   ql)<br>
<br>
There you go! ;)<br>
<br>
cheers
</div>

<div>
The keyword is not a valid FITS string, i.e. it needs to be a single quoted value starting in column 12 and not terminating before column 20 (see  <a href="http://archive.stsci.edu/fits/fits_standard/node31.html#SECTION00921000000000000000)">http://archive.stsci.edu/fits/fits_standard/node31.html#SECTION00921000000000000000)</a>  Once you change this then the expression should work.<br>
<br>
As for FILTPOS, it is not a string value at all and so the '==' operation (rather than the '?=' string comparison) is more appropriate.
</div>
{% endraw %}

**Mike Fitzpatrick** wrote on May 19, 2010

{% raw %}
<div>
Because the value is corrupted there doesn't appear to be a one-line command to replace it with HEDIT.  The HFIX task can be used to run an arbitrary command on the header so if you're proficient in sed/awk/perl you could write a command to fix it and then use HFIX on each of the images.<br>
<br>
Otherwise, you'll need to dump the header values, delete the keyword and replace the value, something like:<br>
<br>
<pre><code>
hselect *.fits $I,FILNAME yes &gt; &quot;fil.txt&quot;    # dump filename and value
list = &quot;fil.txt&quot;
while (fscan (list, s1, s2) != EOF) {
    hedit (s1, &quot;FILNAME&quot;, del+, ver-)    # delete the keyword
    hedit (s1, &quot;FILNAME&quot;, s2, add+, ver-)  # add back the value
}
</code></pre><br>
<br>
Try this by hand first to make sure it works.
</div>
{% endraw %}

**Mike Fitzpatrick** wrote on May 19, 2010

{% raw %}
<div>
This command simply produces a list of image and OBJECT keyword values, one per line.  The idea is then that you could write a script to read this list an rename the file to something based on the object name.  For this to work reliably you'd need to handle cases where there is a space in the object name, avoid multiple files with the same name, etc.  This script code you would need to write yourself, it isn't part of the HSELECT command or any other task.
</div>
