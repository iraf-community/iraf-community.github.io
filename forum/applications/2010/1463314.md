<div>
There's no elegant way other than to try the display, catch an error and then recover.  For example,<br>
<br>
<pre><code>
procedure zz ()

begin
        iferr {
            display (&quot;dev$pix&quot;, 1, &gt;&amp; &quot;dev$null&quot;)
        } then {
            printf (&quot;Warning: No display server running, starting ds9..\n&quot;)
            printf (&quot;!ds9 &amp;\n&quot;) | cl()

            sleep (10)          # give ds9 a chance to startup

            # Try to display again
            display (&quot;dev$pix&quot;, 1, &gt;&amp; &quot;dev$null&quot;)
        }
end
</code></pre>
</div>

Now I understand - the <strong>iferr</strong> check is a new feature of ecl.<br>
In old IRAF versions  (and in new ones with  cl -old) this does not work and complains on syntax error.<br>
So for this case (to be able to use old cl we still have on some older IRAF  installations) I have found a workaround using the UNIX socket which the ds9 opens in a default way of instalation:<br>
<br>
<pre><code>
if (access(&quot;/tmp/.IMT1000&quot;)){
 #For practical case the running ds9 uses the UNIX socket on display 1
            display (imname, 1, fill+,  &gt;&amp; &quot;dev$null&quot;)
         } else {
            printf (&quot;Warning: No display server running, starting ds9..\n&quot;)
            printf (&quot;!ds9 &amp;\n&quot;) | cl()
            sleep (1)          # give ds9 a chance to startup
 # Try to display again
            display (imname, 1, fill+, &gt;&amp; &quot;dev$null&quot;)
        }

</code></pre><br>
<br>
This is not so elegant as the error catch but works (and the user should be warned that the ds9 should not be run in a non-standard way - with forced sockets or pipes or in IP mode )<br>
<br>

Two comments:   The ".IMT1000" isn't fixed, it actually your userid appended to the string ".IMT" so it'll be different for different users.  Second,  the file isn't removed when the display server shuts down so it's possible the socket file can exist without having a valid display server.
