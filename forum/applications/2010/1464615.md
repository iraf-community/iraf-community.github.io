# Problem with \`scombine' option \`reject = "minmax"'

**Francois Schweizer** wrote on Jul 01, 2010

{% raw %}
<div>
I am trying to use `scombine' in `echelle' to combine the various<br>
orders of a flux-calibrated MagE spectrum in MS format into a<br>
single 1D spectrum on a linear, equidistant wavelength scale.<br>
<br>
When I `scombine' the object or sky orders with the following<br>
params:<br>
    scombine.combine = "average"<br>
    scombine.reject  = "none"<br>
the 1D spectrum looks just fine.  (I use a script to restrict<br>
the pixel range of each order, so order-boundary effects are<br>
minimized.)<br>
<br>
However, when I am trying to `scombine' the *sigma* orders, in<br>
admittedly primitive fashion, with the following params:<br>
    scombine.combine = "average"<br>
    scombine.reject  = "minmax"<br>
    scombine.nlow  = 0<br>
    scombine.nhigh = 1<br>
    scombine.nkeep = 1<br>
the 1D spectrum looks awful.  According to the help file for<br>
`scombine', the above params should make `scombine' always choose<br>
the *lower* value of the two sigma orders where they overlap.<br>
Instead, `scombine' insists on averaging both orders in the<br>
overlap zone.<br>
<br>
Replacing the "average" of `scombine.combine' with "sum" does not<br>
help.  On the contrary, now the sum of both orders is presented<br>
in each overlap zone, which is twice the average.<br>
<br>
FYI, the overlap zones always contain only 2 orders, never 3.<br>
Hence, `scombine' always faces either one pixel, in which case it<br>
takes it, or 2 pixels in an overlap zone, in which case it takes<br>
both instead of only the lower one under the `reject = "minmax"'<br>
option.<br>
<br>
Can someone please tell me how I can make `scombine' pick the<br>
lower of two values when two spectra are to be combined?
</div>
{% endraw %}
