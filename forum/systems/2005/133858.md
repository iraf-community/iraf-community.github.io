Hi Guillermo,<br>
        Try getting the binary distribution from<br>
<br>
        <a href="ftp://iraf.noao.edu/pub/fitz/x11iraf-v1.3.2-bin.redhat.tar.gz">ftp://iraf.noao.edu/pub/fitz/x11iraf-v1.3.2-bin.redhat.tar.gz</a><br>
<br>
This should fix the 'h_errno' message but ximtool is still limited to<br>
8-bit displays for the moment.  The libncurses is a known problem explained<br>
in the README file as:<br>
<br>
&gt; -------------------------------------------<br>
&gt; March 31, 2003 -- NOTES for RedHat 8 Users.<br>
&gt; -------------------------------------------<br>
&gt; <br>
&gt;         Users have reported two common problems using XGterm on RedHat 8<br>
&gt; systems:  <br>
&gt; <br>
&gt; 1) An error message of the form<br>
&gt; <br>
&gt;    xgterm:error while loading shared libraries: libncurses.so.4:<br>
&gt;    cannot open shared file: No such object or directory<br>
&gt; <br>
&gt;    Solution:<br>
&gt;         This is a known problem with how the binary was built and RH7 <br>
&gt;         systems.  The simplest solution is to just create a symlink to<br>
&gt;         satisfy the dependency, i.e. as 'root' do<br>
&gt;  <br>
&gt;                 # cd /usr/lib<br>
&gt;                 # ln -s libncurses.so.5 libncurses.so.4<br>
&gt;  <br>
&gt;         Alternatively you could recompile the system from the sources<br>
&gt; <br>
&gt; 2) The behavior that the xgterm window will appear briefly and then shut<br>
&gt;    down with no error message.<br>
&gt; <br>
&gt;    Solution:<br>
&gt;         The workaround is to either start XGterm as "xgterm -ut" to disable<br>
&gt;         this utmp entry, or else change the permissions on the binary as<br>
&gt;         root using<br>
&gt;  <br>
&gt;                 # chown root:utmp xgterm<br>
&gt;                 # chmod g+s  xgterm<br>
&gt;  <br>
&gt;         This will make the binary setgid root and should give it the proper<br>
&gt;         permissions to write a utmp entry.  The reason 'xterm' doesn't require<br>
&gt;         this is that it's linked against a special library which calls a<br>
&gt;         different setgid root task to create the same entry.<br>
<br>
        Also, for recent Fedora systems you'll probably want a patched<br>
version of the XGterm binary available from the <a href="http://iraf.noao.edu">http://iraf.noao.edu</a> <br>
iraf homepage.  <br>
        Hope this helps, let us know if you still have problems.<br>
