&gt; &gt; Hi Henry,<br>
&gt; &gt; 	Try using the 'psdump' device to produce a /tmp/irafdmpXXXX<br>
&gt; &gt; (where XXXX is some pid) file.  This uses the same sgi2uapl translator<br>
&gt; &gt; to produce the postscript.  If that works try<br>
&gt; &gt;<br>
&gt; &gt; 	prompt% cat /tmp/irafdmpXXXXX | lp<br>
&gt; &gt;<br>
&gt; &gt; to see if you get a print (i.e. simulate the DD string by hand).  If<br>
&gt; &gt; that fails, the PS generation works but the printer doesn't like the<br>
&gt; &gt; resulting file.  This is possible since that translator uses a simple<br>
&gt; &gt; "%!PS" prefix and some printers want "%!PS-Adobe-something".  You might<br>
&gt; &gt; instead try the sgi2ueps translator in place of sgi2uapl to send EPS.<br>
