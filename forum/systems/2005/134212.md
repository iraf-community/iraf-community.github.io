**James Turner** wrote on Dec 22, 2005

{% raw %}
<div>
Following on from the 2 posts above, I was trying to figure out how to keep the libtermcap.so.2 dependency in /usr/local/lib rather than /lib (so as to avoid any possible conflicts with system upgrades etc.) without having to set "LD_LIBRARY_PATH" in the environment for every user.<br>
<br>
This requires creating /etc/ld.so.conf (it doesn't exist by default in Ubuntu) with the following contents:<br>
<ul>/lib/<br>
/usr/lib/<br>
/usr/X11R6/lib/<br>
/usr/local/lib/</ul><br>
Running "ldconfig" then updates the dynamic linker's list of files.<br>
<br>
This initially didn't work as normal however. The problem turned out to be that ldconfig gets the shared library name from the binary itself, not from the filename, so when it follows the link "libtermcap.so.2", it still picks up "libncurses.so.5". To get around this, I made a copy of "libncurses.so.5.5" in /usr/local/lib and edited it with EMACS to change the the string "libncurses.so.5" to "libtermcap.so.2" (fortunately the number of characters is the same). Then running "ldconfig" puts libtermcap into the linker's cache as expected.<br>
<br>
Having done this, it is still necessary to create a link pointing from libtermcap.so.2 to the copy of libncurses.so.5 in /usr/local/lib, since the linker seems to find the file by name at runtime.<br>
<br>
It's hardly elegant, but perhaps it's more maintainable. I'm not sure whether avoiding /lib really matters or not. I suspect that upgrades would leave the link intact in /lib, but at least it means that IRAF is guaranteed to have access to the version of the ncurses library that is known to work. rather than some future version.<br>
<br>
James.
</div>

<div>
The 'proper' solution on Ubuntu is to install the Breezy 5.10 libtermcap-compat. It's not in Dapper or Edgy, but at least the package manager can keep track of things this way. It'll be kept as a 'local' packages and won't be removed or updated automatically as there is no replacement in the repos.<br>
<br>
Download it and its dependencies from<br>
<a href="http://packages.ubuntu.com/breezy/oldlibs/termcap-compat">http://packages.ubuntu.com/breezy/oldlibs/termcap-compat</a><br>
<a href="http://packages.ubuntu.com/breezy/oldlibs/libc5">http://packages.ubuntu.com/breezy/oldlibs/libc5</a><br>
<a href="http://packages.ubuntu.com/breezy/oldlibs/ldso">http://packages.ubuntu.com/breezy/oldlibs/ldso</a><br>
<br>
<strong>UPDATE: The Ubuntu package site seems to have just lost all of the individual package pages for breezy, though it still has the links to them. Weird.</strong><br>
You can instead get them from the repos directly:<br>
<a href="http://archive.ubuntu.com/ubuntu/pool/universe/t/termcap-compat/termcap-compat_1.2.3_i386.deb">http://archive.ubuntu.com/ubuntu/pool/universe/t/termcap-compat/termcap-compat_1.2.3_i386.deb</a><br>
<a href="http://archive.ubuntu.com/ubuntu/pool/universe/libc/libc/libc5_5.4.46-15_i386.deb">http://archive.ubuntu.com/ubuntu/pool/universe/libc/libc/libc5_5.4.46-15_i386.deb</a><br>
<a href="http://archive.ubuntu.com/ubuntu/pool/universe/l/ld.so/ldso_1.9.11-15_i386.deb">http://archive.ubuntu.com/ubuntu/pool/universe/l/ld.so/ldso_1.9.11-15_i386.deb</a><br>
<br>
Install them using dpkg:<br>
<pre><code>sudo dpkg -i ldso_1.9.11-15_i386.deb libc5_5.4.46-15_i386.deb termcap-compat_1.2.3_i386.deb</code></pre><br>
<br>
<em>Edit: This works on amd64 too. You'll need to use the --force-architecture flag with dpkg.</em>
</div>
{% endraw %}
