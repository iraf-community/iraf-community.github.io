<div>
1) The conflict with xpp is only a problem if you want to install a package named xpp on the same system (regardless of what it does).<br>
<br>
2) Whenever I've seen the "Memory has been corrupted" message it was indeed enough to raise the stack size limit (I haven't tried to see if large but finite values also work). <br>
Note that (a) Justin Pryzby is well aware of the problem, and (b) the workaround is built into the cl.csh script in the NOAO distribution of IRAF.<br>
<br>
The workaround is *not* built into PyRAF yet (as of PyRAF 1.2 / STScI Python 2.2) so you'll need it if you use PyRAF. <br>
(By the way, I've got Debian/Ubuntu packages for STScI Python; will see about publishing them.)<br>
<br>
Sergio Gelato
