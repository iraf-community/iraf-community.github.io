	IMFORT only works for .imh images (and only type 'short' or 'real'<br>
at that).  If you were able to get the task to run then there must have<br>
been an image by the same name but with a .imh extension in the same<br>
directory.<br>
<br>
&gt; then I modified it to load the image into a matrix and print some pixel value <br>
&gt; for test: the compilation is apparently ok but when I run the program <br>
&gt; (defined as a foreign task in the login.cl) from within cl I get:<br>
&gt; <br>
&gt; ERROR: Abnormal termination of child process '??'<br>
<br>
	This is a general error message that normally means the process<br>
itself wouldn't start in the first place.  If you execute the task outside<br>
of the CL you sometimes get a more informative error message from the<br>
system (e.g. missing shared lib).  Note that something general like a<br>
"memory corrupted" error needs to be debugged first and since this is a<br>
host program its easiest to do this outside of the CL as well.  If you're<br>
using a linux 2.6 kernel then try adding a "limit stacksize unlimited" to<br>
your .cshrc or on the command-line before you run the task.  This is done<br>
automatically by the CL login script but foreign tasks are run in a <br>
subshell that won't pick it up.<br>
	Hope this helps.<br>
