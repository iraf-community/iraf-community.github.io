&gt; Hello Giovanna,<br>
&gt; <br>
&gt; All IRAF tasks actually check for this (and other) variable and it is<br>
&gt; normal for it to be absent.  The problem with TELLURIC is that it gets<br>
&gt; confused by some other error and it then reports the wrong error<br>
&gt; message.  This is a bug in the way the program deals with errors and it<br>
&gt; will be fixed.<br>
&gt; <br>
&gt; So the problem is to determine what the actual error is.  It is most likely<br>
&gt; something simple with the parameters.  The way you can get to the true<br>
&gt; error is by setting the variables.<br>
&gt; <br>
&gt; cl&gt; set imio_bufmax = 16000000<br>
&gt; cl&gt; set imio_bufsize = 260000<br>
&gt; cl&gt; set imio_buffrac = 10<br>
&gt; <br>
&gt; These are the default values that the programs use when these variables are<br>
&gt; undefined so it will make no difference and you don't really need to know<br>
&gt; anything about these.  They are used to optimize image access.<br>
&gt; <br>
&gt; After setting these values then you should get the correct error.  If<br>
&gt; you get another misleading error like:<br>
&gt; <br>
&gt; Warning: Image header parameter not found (EXTVER)<br>
&gt; <br>
&gt; it probably means it could not open the calibration spectrum.<br>
&gt; <br>
&gt; I hope this helps and let us know if you still get errors which you don't<br>
&gt; understand with this task.  If all else fails and you can figure out what<br>
&gt; is wrong you can send the parameter listing for telluric and I can  provide<br>
&gt; a corrected binary executable that will then report the actual error.<br>
&gt; <br>
&gt; Yours,<br>
&gt; Frank Valdes<br>
&gt; <br>
&gt; <br>
&gt; NUMBER: 520<br>
&gt; MODULE: onedspec.telluric<br>
&gt; SYSTEM: -V2.12.2<br>
&gt; DATE:   Mon Feb 24 12:18:04 MST 2003<br>
&gt; FROM:   valdes<br>
&gt; <br>
&gt; BUG:    When an error, such as invalid parameters or missing images, occurs<br>
&gt;         the task first does some error clean up operations before reporting<br>
&gt;         the error.  The problem with this is that the actual error message<br>
&gt;         can get lost and a misleading message, such as environment variable<br>
&gt;         or image header parameter not found, will be given.  Avoid this<br>
&gt;         requires a code change.  One way to sometimes get to the true error<br>
&gt;         is to eliminate the misleading error by setting a value for the<br>
&gt;         missing evironment or header parameter.  Also check carefully all<br>
&gt;         the task parameters since most error are the result of problems<br>
&gt;         with them.<br>
&gt; <br>
&gt; STATUS: The error handling will be improved in the next release.<br>
