<br>
                Sorry for the late reply, I didn't notice this as still being open.<br>
<br>
The BadDrawable is an X11 message coming from XGterm itself and is not an IRAF error message.  It's been reported before and had several causes:<br>
<br>
1)  The X11 display was using a 16-bit visual (which isn't supported by XGterm).  You can use the 'xdpyinfo' command to see what the default visual is for your system.<br>
<br>
2) X11IRAF is still a 32-bit system and missing 32-bit compatibility libs on the machine can cause the problem.  The XGterm binary distributed with the IRAF v2.16.1 system from NOAO is a statically linked binary and shouldn't have this problem, but I can't say the same for other ways IRAF is distributed.  You can use the 'file' and/or 'ldd' command on the xgterm binary to see whether it is statically linked or has any missing dependencies.<br>
<br>
3)  The STSDAS package (in this case the NFIT1D task) is also 32-bit only, but is using the 64-bit CL binary to render the graphics.  Depending on the STSDAS version you may be seeing a known bug where the plotting WCS between these are incompatible.  The solution there is to use a 32-bit CL binary which you can find at<br>
<br>
    ftp://iraf.noao.edu/iraf/v216/PCIX/support/linux/vocl.e<br>
<br>
where there are also 'cl.e' and 'ecl.e' binaries.  Download these in binary mode, reset the execute permissions and install in your $iraf/bin.linux64 directory (after making a backup of the existing binaries).<br>
<br>
Lastly, there is an undiagnosed graphics bug still in the system but only shows up in very specific instances.  Hope this helps.<br>
