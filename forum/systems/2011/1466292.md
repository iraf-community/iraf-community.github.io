# Install 2.15.1a from source?

**Mark S.** wrote on Mar 15, 2011

{% raw %}
<div>
I'm trying to compile IRAF 2.15.1a from source, but running into problems making 64 bit executables.<br>
<br>
In file included from setbuf.c:10:<br>
libc_proto.h:20: error: conflicting types for `c_close'<br>
/arzach/data1/sienkiew/iraf/unix/hlib/libc/libc.h:157: error: previous declaration of `c_close' was here<br>
... repeat for c_close, c_envlist, c_envmark, c_flush, c_fredir, ...<br>
<br>
The pattern seems to be that anything in libc.h that has a parameter type of XINT is in conflict with the same parameter as defined in sys/libc/libc_proto.h<br>
<br>
Line 15 of libc.h defines XINT to be "long" not "int".  libc.h uses XINT, but libc_proto.h uses int.  The actual function definitions often use XINT.<br>
<br>
( It works ok to make 32 bit executables because in that case XINT is int, which matches libc_proto.h. )<br>
<br>
So, how does it work to compile 64 bit binaries?
</div>
{% endraw %}

**Mike Fitzpatrick** wrote on Mar 15, 2011

{% raw %}
<div>
For 64-bit you need to be sure your IRAFARCH variable is set to either 'linux64' or 'macintel' depending on your platform.  You'll also need to be sure the install script was run so there is a valid /usr/include/iraf.h link, and that the system was configured for the proper architecture.  All you should need to do is something like:<br>
<br>
<pre><code>
% cd /iraf/iraf
% make linux64
% make sysgen
</code></pre><br>
<br>
It sounds like the iraf.h file for your system is still the 32-bit version and that the system isn't configured for the proper architecture (i.e. is the 'bin' link pointing to bin.generci?).
</div>
{% endraw %}

The libc_proto.h file isn't actually used anywhere in the code so I'm not sure why you're getting any sort of complaint about it.  Did you modify something locally?  If so, what and how?<br>
<br>
The definition of XINT depends on 'MACH64' being defined during compilation, specifically when including the hlib$libc/libc.h file as when compiling the LIBC interface for the HSI.  Does "xc -c -dv setbuf.c" show the following:<br>
<br>
<pre><code>

munch&gt; xc -c -dv setbuf.c
cc -c -DMACH64 -DMACOSX -arch x86_64 -m64 -v -I/iraf/iraf/unix/hlib/libc setbuf.c
.....
</code></pre><br>
<br>
If not your environment might not be defined correctly.   Lastly, if you modified the install script did you make sure that the hlib$libc/iraf.h file was also modified with the path to your iraf installation?<br>
<br>
Is there some particular reason other than curiosity you're trying to compile from sources?  Also, are you actually on a 64-bit system (i.e. does "uname -a" show the arch as "x86_64"?) or are you trying to cross-compile on a 'macosx' native irafarch (which won't work, BTW).
