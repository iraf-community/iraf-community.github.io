Slow compared to what, expectations or earlier runs on the same machine?  I was able to find two roughly identical machines here running Solaris 7 and Solaris 9  and for the most part a benchmark script ran in about the same time.  There was the expected difference when using NFS-mounted disks and some unexplained slowness on CPU-intensive tasks that happened only occassionally.  However, the fact the script ran in the same time even once backs up my first thought that recompiling the system wouldn't really help.   <br>
<br>
You'll need to first rule out things like NFS performance, excessive system paging, full /tmp areas, runaway httpd on the machine, etc.  It would be simpler to isolate this to a real problem if you used a single compiled task in your tests rather than a script that may have its own  issues.   We don't use Solaris 9/10 here on most machines, others may have more relevant real-world experience.  Hopt this helps.<br>

**Mike Fitzpatrick** wrote on Feb 17, 2006

{% raw %}
<div>
I now officially recant my suggestion that relinking won't help.<br>
<br>
The problem reported was confirmed on Sol10 boxes of both the x86 and sparc flavors.  However, on my test systems there were no compilers installed and so profiling was limited to what I could derive from truss/vmstat/iostat.  There was no conclusive evidence, but there we hints that this is a memory/paging issue of some kind (involving shared system libs).  The disk i/o for FITS was slightly more than for imh but no more than expected, &gt;90% of the excess time was "someplace else".<br>
<br>
Anyway, on a Solaris 5.6 (sparc) box I simply relinked the stock V2.12.2a system and moved those bins to the Solaris 10 box (w/ no compiler).  Running the relinked binaries not only brought the FITS times in-line but also improved the imh performance as well.  For this experiment I simply relinked with a "-z" flag so as not to have to rebuild the shared library.<br>
<br>
On x86 there no iraf shared library and I have no comparable box here (the original Solaris 7 x86 is now dead) but suspect relinking against the native host libs might show similar improvement.  I'm out of time to track this any further but please try relinking the systems to see if the problem is fixed. To do this you would:<br>
<br>
    cl&gt; cd iraf$<br>
    cl&gt; mkpkg ssun                             # or 'sunos' for x86<br>
    cl&gt; mkpkg -z update                     # relink system<br>
    cl&gt; cd noao$                                  # repeat for NOAO pkg<br>
    cl&gt; mkpkg -p noao ssun<br>
    cl&gt; mkpkg -z -p noao update<br>
<br>
...and the like for all external packages.  However with just the above you should be able to rerun the bench.cl script to check the times.  In any case, please let me know what happens.<br>
<br>
-Mike
</div>
