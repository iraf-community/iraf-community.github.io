# Installation of 2.13BETA2 Red Hat binaries on Debian Sarge

**Emilliano Gregori** wrote on Jun 11, 2006

{% raw %}
<div>
Hello,<br>
I just installed the 2.13beta2 Red Hat linux (rhux) binaries on my PIII laptop running Debian Sarge (3.1) and it works great! :D<br>
Many thanks to Mike and the other iraf developers.<br>
<br>
Here the installation instructions.<br>
With respect to a normal iraf installation you need a few caveats:<br>
<br>
(1) first of all, install the "termcap-compat" package. From root:<br>
<br>
<pre><code>
# apt-get install termcap-compat
</code></pre><br>
<br>
(2) when unpacking ib and nb binary packages, make sure to unpack them in /iraf/irafbin/bin.redhat and /iraf/irafbin/noao.bin.redhat, as if you were installing on a Red Hat system:<br>
<br>
<pre><code>
iraf% mkdir /iraf/irafbin/bin.redhat
iraf% cd /iraf/irafbin/bin.redhat
iraf% tar xfvz /path/to/ib.rhux.x86.gz

iraf% mkdir /iraf/irafbin/noao.bin.redhat
iraf% cd /iraf/irafbin/noao.bin.redhat
iraf% tar xfvz /path/to/nb.rhux.x86.gz
</code></pre><br>
<br>
(3) edit and run the install script.<br>
We are using Red Hat binaries, but install script will guess (from uname) a generic Linux system, and this will cause errors in the installation (i.e. the install will not find binaries in the bin.linux directories, because they are in bin.redhat directories). <br>
The "-m redhat" option will tell install script to act as it was a Red Hat installation, but this will cause a "foreach: No match" error when checking file permissions. This is caused by a wrong value of $hmach variable: it should be "redhat" but is "linux".<br>
So edit the following section of install script which process command line options:<br>
<br>
<pre><code>
    case -m:				# set machine type
	if (&quot;$2&quot; != &quot;&quot;) then
	    shift
	else
	    ERRMSG  &quot;missing argument to &#x27;-m &lt;mach&gt;&#x27; switch&quot;
	    exit 1
	endif
	set mach = &quot;$1&quot;
	breaksw
</code></pre><br>
<br>
and change to:<br>
<br>
<pre><code>
    case -m:				# set machine type
	if (&quot;$2&quot; != &quot;&quot;) then
	    shift
	else
	    ERRMSG  &quot;missing argument to &#x27;-m &lt;mach&gt;&#x27; switch&quot;
	    exit 1
	endif
	set mach = &quot;$1&quot;
	set hmach = &quot;$1&quot;     # add this line to prevent foreach error
	breaksw
</code></pre><br>
<br>
then you can run the install script and proceed with the normal iraf installation. <br>
<br>
Emiliano.
</div>
{% endraw %}

<div>
Hi Emiliano,<br>
<br>
Thanks for the post.  The idea of a '-m' flag to the install script is interesting and probably something I'll include.  I do have a few small comments however:  The termcap-compat is now needed for the ECL but I've already modified the build so this isn't needed.<br>
<br>
More importantly, I presume you've defined an IRAFARCH in your environment as 'redhat'?  This is why you're able to install in a bin.redhat directory but for users who don't define an environment things like the cl.csh check for the existance of a /etc/redhat-release file when determining the arch.  On Debian this won't be found and the empty bin.linux will be used instead.  For the final release I'd like to merge all the linux versions to avoid stuff like this.  It is good to know that the current redhat binaries work under Debian Sarge, but a simpler install may be to simply install the IB/NB file under a 'bin.linux' directory and the for the HSI copy the iraf$unix/bin.redhat to iraf$unix/bin.linux (or make a symlink).  The HSI bin contains the XC/MKPKG binaries but also has the hardcopy printer translators (which is why the install script is looking there when making links in the system). <br>
<br>
Anyway, thanks again for the input.  BTW, I have recently built the system under Sarge and there weren't any problems or hiccups.  Same goes for some other debian-based releases.<br>
<br>
Cheers,<br>
-Mike
</div>
