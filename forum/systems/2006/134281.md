# IRAF shell script problems in Redhat FC2

**Doug Mink** wrote on Jan 10, 2006

{% raw %}
<div>
We've been building instrument data reduction pipelines in CL<br>
for quite a while and have been moving the top level to CL<br>
scripts callable from the Unix command line so that we can<br>
use multiple processors.  Every thing works well under Solaris<br>
and has moved pretty well between versions of IRAF, but<br>
when we try to run working scripts under Linux (Redhat FC2),<br>
they crash soon after entering any SPP program which is<br>
called by the CL script.  Functions such as lpar, dpar, dir, and<br>
epar work, but as soon as you try to access a data file, the SPP<br>
program and the script crash.<br>
<br>
Does anyone have any ideas of what could be going wrong?
</div>
{% endraw %}

---

**Mike Fitzpatrick** wrote on Jan 10, 2006

{% raw %}
<div>
The default hlib$cl.csh has the line<br>
<br>
    limit stacksize unlimited<br>
<br>
to workaround some memory layout changes in recent kernels. #!cl scripts of course don't use this script so my guess is you need to have that same line defined in the environment that starts the scripts (or "ulimit -s unlimited" for bash shells).  Note<br>
that a "!" escape from the script itself won't work, it has to be defined in the parent shell of the CL process.<br>
<br>
-Mike
</div>
{% endraw %}
