<br>
   I'm not quite sure I understand your intention in the code snippet:  The SLIST task produces a table where column 6 is the starting wavelength, but the 'wc' ouput only has four values in most cases.  This means the FIELDS output should be empty and so 'num_aper' isn't defined and would account for the error.  If all you want to do is count the number of lines of output from SLIST you could do it as<br>
<br>
    slist (filename) | count ("STDIN") | scan (num_aper)<br>
<br>
To make sure the value was read you can use the nscan() afterward to verify at least one value was scanned.<br>
<br>
    I can't explain why it works on one machine and not the other, the 'wc' should produce only 4 columns in an case.  Hope this helps.<br>
