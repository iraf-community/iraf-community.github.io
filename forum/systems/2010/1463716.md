**Mike Fitzpatrick** wrote on Mar 04, 2010

{% raw %}
<div>
Both problems can be accounted for assuming there is a problem with the image header, e.g. and END keyword is missing or some other mishandling of the header.  Strictly speaking, an EOF error might also mean the FITS file is truncated, either because the task writing it failed for some reason or perhaps because the zero-padding of the file is missing.  Is the file size an integer multiple of 2880 bytes?  If you page the file do you see and END keyword?  Do simple tasks like IMHEAD work to list the primary or extension headers?<br>
<br>
As was mentioned in the other post, the EXTVER message is typically a result of some other error message and the way that the error recovery works.  If you can't HEDIT the file to add an EXTVER to the primary header the file may be corrupted (could you post it to the anonftp on iraf.noao.edu:/pub)?  Can you regenerate that output file again (perhaps by explicitly adding the ".fits" extension, or verify that your 'imtype' environment variable is 'fits')?
</div>
{% endraw %}
