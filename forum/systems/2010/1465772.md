<div>
An error like this usually means your shell is printing something to the terminal when started.  At startup, the CL does the dynamic package loading using the hlib$extpkg.cl script that in turn relies on shell escapes for certain commands that aren't yet defined to the CL (e.g. "!pwd") to get the current path.<br>
<br>
I think what's happening is that the '!pwd' is causing some message like "Loading ...." to be printed and that is being used in the script instead of the directory path.  Check for an alias of the 'pwd' command, and/or source your .cshrc/.bashrc file and make sure these don't print any messages.  Write back if you still have problems.
</div>
{% endraw %}
