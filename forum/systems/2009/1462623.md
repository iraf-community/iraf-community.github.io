**Mike Fitzpatrick** wrote on Sep 18, 2009

<div>
There are known problems with compiling on a 64-bit system, in general it doesn't work however for this little program I was able to compile locally using your exact command line.  What we usually suggest is that you build a binary on a 32-bit system and move it, I've done that and put the result for this task in <a href="ftp://iraf.noao.edu/pub/wfpa.e">ftp://iraf.noao.edu/pub/wfpa.e</a><br>
<br>
I also verified that the 'slpa_' symbol does indeed exist in the iraf slalib and in the binaries distributed in at least the latest SciSoft release.  You can check for your self with the command<br>
<br>
<pre><code>
% nm -o  /iraf/iraf/bin.redhat/libslalib.a | grep -i slpa 
1737:/iraf/iraf/bin.redhat/libslalib.a:pa.o:00000000 T slpa_
1743:/iraf/iraf/bin.redhat/libslalib.a:pav.o:00000000 T slpav_
</code></pre><br>
<br>
I do find it strange that your final command line includes both /iraf/iraf and /scisoft/share/iraf/iraf paths to the libraries.  This may be a scisoft configuration error but since there is no equivalent /scisoft path to slalib it may also mean your '$iraf' is set incorrectly (i.e. it defines /iraf/iraf but that is an invalid path).  Does your .cshrc file source any scisoft setups or do you define things directly?  <br>
<br>
-Mike
