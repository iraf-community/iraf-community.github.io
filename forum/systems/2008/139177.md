**Mike Fitzpatrick** wrote on Mar 18, 2008

{% raw %}
<div>
The first thing to check is whether other X applications can start correctly (e.g. try an xclock or xterm).  If you see a similar "hang", check the value of your DISPLAY variable to be sure they aren't actually running but showing up on some other computer.  OTOH, of those work fine, then try running the command as <br>
<br>
<pre><code>% sudo /usr/local/bin/xgterm</code></pre><br>
<br>
I'm not running leopard, but some systems require that xterm-like windows be run as root, or try adding the '-ut' flag so it doesn't write a utmp entry when it starts up.  If that works, chown the binary so it's owned by root and give it setuid permissions, i.e.<br>
<br>
<pre><code>
% sudo chown 0 /usr/local/bin/xgterm
% sudo chmod 4755 /usr/local/bin/xgterm
</code></pre><br>
<br>
Write back if it still doesn't work.<br>
<br>
-Mike
</div>
{% endraw %}

**Mike Fitzpatrick** wrote on Mar 18, 2008

{% raw %}
<div>
Try forcing the display with either<br>
<br>
<pre><code>
% xterm -display localhost:0.0

or 

% setenv DISPLAY localhost:0.0
% xterm
</code></pre><br>
<br>
X11 under Leopard was/is seriously broken for some things, be sure you've installed whatever the latest update for X11 is.  This version also has an "auto-launch" feature for X11 when you start xterm, so try *not* starting X from the dock first and let xterm/xgterm doit for you.<br>
<br>
-Mike
</div>
