**Mike Fitzpatrick** wrote on Dec 09, 2008

{% raw %}
<div>
Compiling anything in IRAF requires that you define certain environment variables appropriate for your system e.g.<br>
<br>
<pre><code>
setenv iraf /iraf/iraf/                        &lt;-- trailing &#x27;/&#x27; required
setenv IRAFARCH redhat
source $iraf/unix/hlib/irafuser.csh
</code></pre><br>
<br>
In general, these (or the Bash equivalents) should be put in your .cshrc file (or .bashrc/.profile) so they can be used if you invoke MKPKG from within the CL.<br>
<br>
For compiling external packages, there is also the assumption that the 'tables' package variable has been defined in the hlib$extern.pkg file or as an environment variable (in both cases, with a trailing '/').  Compiling external packages also requires the '-p' flag to load a specific package environment, e.g.<br>
<br>
<pre><code>mkpkg -p tables</code></pre><br>
<br>
to do the compilation.  Pre-built binaries are available for most popular systems as well.<br>
<br>
-Mike

<div>
<blockquote>Executing mkpkg tables return the error</blockquote><br>
<br>
The command is "mkpkg -p tables" not "mkpkg tables".  The first uses the '-p' flag to name 'tables' as the package environment, the second command tells mkpkg to execute the 'tables' directive in the mkpkg file (which doesn't exist).<br>
<br>
-Mike

**Mike Fitzpatrick** wrote on Dec 09, 2008

{% raw %}
<div>
Sounds like the package isn't (properly) declared in the hlib$extern.pkg file, e.g.<br>
<br>
<pre><code>
setenv tables     /iraf/extern/tables/          &lt;-- trailiing &#x27;/&#x27; required
task tables = tables$tables.cl
</code></pre><br>
<br>
Note that the last line in the file must be 'keep', a missing trailing '/' would also account for the problem.
