**Mike Fitzpatrick** wrote on Jan 25, 2008

{% raw %}
<div>
The GIM2D package is actually called FUZZY.  Assuming you've got a directory with the various files, say /home/nick/fuzzy, you declare the package with the lines:<br>
<br>
<pre><code>
reset fuzzy  = /home/nick/fuzzy/              # trailing &#x27;/&#x27; required!
task $fuzzy = fuzzy$fuzzy.cl
</code></pre><br>
<br>
For personal use you can do this in your login.cl (or loginuser.cl) file before the final 'keep' statement.  To install it in the system you would edit the file hlib$extern.pkg in the iraf tree with the same lines.  Depending on where you defined it in the login.cl it will show up in another package (like NOAO), but if you install it in the hlib$extern.pkg file you should see it when you login to the CL.  In either case, typing 'fuzzy' should load the package.<br>
<br>
IRAF will look for binaries in a directory based on the architecture name (e.g. 'bin.macosx' for PPC and 'bin.macintel' for Intel on a Mac).  If you really have a directory named 'bin' you should rename it to one of these so the binaries will be found.<br>
<br>
Write back if you still have problems.<br>
<br>
-Mike
</div>

<div>
A 'cannot open connected subprocess' basically means the binary cannot be found, or executed.  Depending on any changes you made, the mkpkg file file be creating e.g. an xx_mgimfit2d.e until you do a 'mkpkg install'.  Or, the binary has the right name, but isn't in the proper bin directory:  A package 'bin' is usually a symlink to (in this case) 'bin.macosx' directory for  Mac PPC or 'bin.macintel' for Mac Intel.  It is okay if 'bin' is actually a directory, but the executable should be there.<br>
<br>
If the binary has the right name and is in the right place, make sure it is executable (e.g. try running it outside of IRAF, type 'bye' at the '&gt;' prompt to quite if it successfully starts, otherwise repost the error).   Did you get the source code or did Luc produce a mac binary?<br>
<br>
-Mike

<div>
Hi Nick,<br>
<br>
The bin.macosx and noao.bin.macosx directories belong in /iraf/irafbin and should contain the contents of the IB and NB distribution files respectively.    It appears you've put the GIM2D binaries in the 'bin.macosx' directory as well, and so they're not being found because the system is expecting them to be in the package directory tree.<br>
<br>
Typically you would install the FUZZY package someplace like /iraf/extern/fuzzy which would contain a 'bin.macosx' directory of its own (and a 'bin' symlink that point to it).  The binaries you got from Luc belong in this directory, i.e. /iraf/extern/fuzz/bin.macosx<br>
<br>
Cheers,<br>
-Mike
