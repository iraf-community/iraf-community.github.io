First, be sure to follow ":.snap" with ":.gflush" to flush the graphics buffer right away.<br>
<br>
If that doesn't work, try using the 'psdump' device to save the postscript to a /tmp/irafdmpXXXXX.ps file,  then try printing that file manually with 'lpr' outside of IRAF.  If it doesn't work let me know, you<br>
might also try changing the first line of the file from "%!PS" to "%!PS-Adobe-2.0" since some printers require that.  This can be done automatically in the graphcap and has been changed in the next release.<br>
<br>
Cheers,<br>

**Mike Fitzpatrick** wrote on Nov 14, 2007

{% raw %}
<div>
Hi Pat,<br>
<br>
Try doing a "cl&gt; !which sgidispatch" to see if you can find the command. The dispose command in the graphcap is done using a spawned shell and so if your .cshrc file doesn't define a path to the sgidispatch command it might not produce the final file. This usually means that your path is defined in your .login file instead, just add the extra directory to the .cshrc (or .bashrc) as well.  <br>
<br>
The 'sgidispatch' command is a symlink created by the install script and should point to the iraf$unix/bin.&lt;arch&gt;/sgidispatch.e binary.  If something changed the links in your system, rerunning the install script will fix it, but in most cases it's a path problem.<br>
<br>
Cheers,<br>
-Mike
</div>
