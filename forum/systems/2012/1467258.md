I have always had this problem, for decades already, starting on SunOS machines, then Solaris and all sort of Linuxes. It is really strange that almost nobody complains (I just found one post from 2000). Very unlikely that only I have this problem.<br>
<br>
When IRAF is started in xterm/xgterm window, it does not get the size of the terminal window properly, although, as mentioned by Mikes's reply to that 2000 post, it should (see <a href="http://iraf.net/phpBB2/viewtopic.php?t=76544&amp;sid=6fdf5737a4565504bafb645c55b43099)">http://iraf.net/phpBB2/viewtopic.php?t=76544&amp;sid=6fdf5737a4565504bafb645c55b43099)</a>.<br>

into login.cl file, somewhere after the "stty xterm" command.<br>
<br>
Maybe it could be just fixed - cannot be a difficult job.<br>

**Mike Fitzpatrick** wrote on Mar 24, 2012

{% raw %}
<div>
This appears to be non-trivial to fix.  The escape sequence to report the window size no longer appears to be recognized by XTerm and so when you type 'stty resize' the sequence is sent but no response is ever received, and so the hardwired value in the termcap is used.<br>
<br>
I can't say specifically when this started but I know XTerm underwent a major rewrite a while ago.  It appears that even though the man page says the sequence should work, it seems to reply on applications processing a SIGWINCH signal to respond to the resize.  Your envget() workaround is fine when you first login, but needs to be done again if the window is resized.  That and the SIGWINCH handling means nontrivial.<br>
<br>
Just curious, is there some reason you use XTerm over XGterm anyway?
</div>
{% endraw %}
