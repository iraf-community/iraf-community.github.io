<div>
<br>
                This bug in the install script was discovered following the last release, a patched install script is available from<br>
<br>
    ftp://iraf.noao.edu/iraf/v216/support/install<br>
<br>
At the point in the script where it is failing the script is attempting to edit the $iraf path into your startup files (e.g. .cshrc/.login if you use a C-shell, and .bashrc/.profile/.bash_profile/.bash_login if you use a Bash shell).  If these files don't exist you would see a message but the installation should continue, could you post the error message you're seeing?<br>
<br>
The .cshrc file isn't required to pre-exist, and likely won't if you use a Bash shell, but may be created anyway with the basic iraf setup you showed.  You can do "echo $SHELL" at the unix prompt to see which shell you are using, likewise do an "echo $iraf" to see if/what the iraf directory is to verify that it is correct.  Does the 'cl' command print any sort of error?  What directory did you unpack iraf into?<br>

{% raw %}
<div>
<br>
<br>
A long startup time is sometimes related to something happening in your .cshrc/.bashrc/.profile file, e.g. it's waiting for access to a file on an NFS partition, an rsh/ssh/wget or some other remote command is waiting for a network timeout, etc.  You can start the CL by running the $iraf/bin.linux.vocl.e binary directly, e.g.<br>
<br>
    % setenv arch ".linux"      # note the leading dot<br>
<br>
    % setenv IRAFARCH linux<br>
<br>
    % $iraf/bin.linux/vocl.e<br>
<br>
If this starts immediately then try tracing the 'cl' command itself, i.e.<br>
<br>
     % sh -x $iraf/unix/hlib/cl.sh<br>
<br>
to see where the wait is happening, if there is not output from the CL script right away then the problem is in your startup files somewhere.<br>
</div>
{% endraw %}

**Mike Fitzpatrick** wrote on May 14, 2014

{% raw %}
<div>
<br>
<br>
Then it's a networking timeout from the system version checker CHKUPDATE.  Even if you're not on a network this should fail immediately but it appears to be trying to connect and then timing out either on your machine or the intervening gateway.<br>
<br>
To disable this you can either comment out/delete the call to "chkupdate" in your login.cl file (and the system $iraf/unix/hlib/login.cl) or else once you are logged in set a negative interval parameter value, e.g.<br>
<br>
    cl&gt; chkupdate.interval = -1<br>
<br>
Note that if you don't have a login.cl in the current directory, you'll need to edit the global login file in $HOME/.iraf/login.cl<br>
</div>
{% endraw %}
