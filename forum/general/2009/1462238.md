**Christopher Gerardy** wrote on Aug 07, 2009

{% raw %}
<div>
Hi smp,<br>
  I believe that you're close with your login.cl edit, but you probably want to remove one or both of the $ in your task command.  If your new task has no parameters, then you want to keep the first $.<br>
<br>
ie:<br>
<pre><code>task $new = &quot;/swapnil/my_data/new.cl&quot;</code></pre><br>
for a task without parameters or <br>
<pre><code>task new = &quot;/swapnil/my_data/new.cl&quot;</code></pre><br>
for a task with parameters.  <br>
<br>
The $ in the path is usually a reference to a predefined alias for a path.  (tables$ standing in for the location of the tables package for example.)<br>
<br>
edit:<br>
The behavior with respect to epar is because you have told iraf that it's a task without parameters.  If you have parameters to edit, then you want the $-less version.
</div>
{% endraw %}

**Mike Fitzpatrick** wrote on Aug 07, 2009

{% raw %}
<div>
Tasks defined in the loginuser.cl file will become part of the 'user' package, if you define them in your login.cl they'll be part of whatever the current package is (i.e. it depends where in the file you define the task).  In either case, it is critical that the task definition come *before* the 'keep' statement that should be the last line of the file.<br>
<br>
A 'param not found' error usually indicates a path problem but if you change the task definition from one that used a '$' to indicate no params to another that says you have params (or vice versa), you should unlearn the task to remove any memory about parameters from the uparm file.  If there had been a problem with the task not being defined properly you would normally see a 'task not found' error.  If the unlearn doesn't work, double-check the path (e.g. is there an NFS mount-point you need to include?).<br>
<br>
-Mike
</div>

**Mike Fitzpatrick** wrote on Aug 07, 2009

{% raw %}
<div>
Package loading in the login.cl works the same as on the commandline, i.e. you cannot load CCDRED directly unless the IMRED package has been loaded, IMRED can't be loaded until NOAO is loaded, etc.  So,  <strong>following the 'noao' line and <em>before<em> the 'keep'</strong> you would add the lines<br>
<br>
<pre><code>
imred
ccdred
task new = /swapnil/my_data/new.cl
</code></pre><br>
<br>
Alternatively, just create a file called loginuser.cl in the same directory as your login.cl that contains<br>
<br>
<pre><code>
task new = /swapnil/my_data/new.cl

keep
</code></pre><br>
<br>
-Mike
</div>
{% endraw %}
