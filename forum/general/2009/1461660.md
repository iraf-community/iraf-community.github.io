# Possible bug in cl.csh

**jamesh** wrote on Jun 02, 2009

{% raw %}
<div>
(Note: edit for code examples, and general cleanup)<br>
<br>
I hope this is the right place for this. I had a user today complaining that the -o and -old flags were non-functional when trying to invoke cl. I did some testing and checked the script ("cl.csh") and it seems that he was correct. Looks like the problem is in this section: <br>
<br>
<pre><code># Determine CL binary to run based on how we were called.

set cl_binary           = &quot;ecl.e&quot;

if (`echo $0 | egrep ecl` != &quot;&quot;) then
    set cl_binary       = &quot;ecl.e&quot;
else if ($#argv &gt; 0) then
    if (&quot;$argv[1]&quot; == &quot;-ecl&quot; || &quot;$argv[1]&quot; == &quot;-e&quot;) then
        set cl_binary   = &quot;ecl.e&quot;
    endif
else if ($#argv &gt; 0) then
    if (&quot;$argv[1]&quot; == &quot;-old&quot; || &quot;$argv[1]&quot; == &quot;-o&quot;) then
        set cl_binary   = &quot;cl.e&quot;
    endif
endif</code></pre><br>
<br>
You've got two "else if" statements, and you never reach the second one. I hacked around a bit and this is fixable: <br>
<br>
<pre><code>if (`echo $0 | egrep ecl` != &quot;&quot;) then
    set cl_binary       = &quot;ecl.e&quot;
else if ($#argv &gt; 0) then
    if (&quot;$argv[1]&quot; == &quot;-ecl&quot; || &quot;$argv[1]&quot; == &quot;-e&quot;) then
        set cl_binary   = &quot;ecl.e&quot;
    else if (&quot;$argv[1]&quot; == &quot;-old&quot; || &quot;$argv[1]&quot; == &quot;-o&quot;) then
        set cl_binary   = &quot;cl.e&quot;
    endif 
endif</code></pre><br>
<br>
This still doesn't add any error checking (eg: what if someone specifies -e and -o? Only the $argv[1] is taken and the second flag is silently ignored.)  but at least you can invoke the "old" mode successfully.<br>
<br>
One could also go a step further, and incorporate all of the option handling (integrating the -v option), and warn if you're stacking incompatible options: <br>
<br>
<pre><code>if (`echo $0 | egrep ecl` != &quot;&quot;) then
    set cl_binary       = &quot;ecl.e&quot;
else if ($#argv == 1) then
    if (&quot;$argv[1]&quot; == &quot;-ecl&quot; || &quot;$argv[1]&quot; == &quot;-e&quot;) then
        set cl_binary   = &quot;ecl.e&quot;
    else if (&quot;$argv[1]&quot; == &quot;-old&quot; || &quot;$argv[1]&quot; == &quot;-o&quot;) then
        set cl_binary   = &quot;cl.e&quot;
    else if (&quot;$argv[1]&quot; == &quot;-v&quot; || &quot;$argv[1]&quot; == &quot;-version&quot; || \
        &quot;$argv[1]&quot; == &quot;-V&quot; || &quot;$argv[1]&quot; == &quot;--version&quot;) then
            head -1 $iraf/unix/hlib/motd
            exit 0
    endif
else if ($#argv &gt; 0) then 
    echo &quot;Only one argument may be specified to cl&quot;
    exit 1
endif</code></pre><br>
<br>
This section would have to be moved to after the determination of the IRAF root directory. Maybe it's too ambitious, but I'd love to see a fix in the next release (or a patch or something). <br>
<br>
We're running NOAO Sun/IRAF Revision 2.14.1-EXPORT on Solaris 10, although I would think this would happen to everyone.<br>
<br>
Cheers, <br>
<br>
-James
