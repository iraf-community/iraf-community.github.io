**Mike Fitzpatrick** wrote on May 07, 2009

{% raw %}
<div>
The message generically means the binary couldn't be found.  This is usually a problem in the definition of the $iraf path (which should always be defined with a trailing '/').  The x_system.e should be in the same directory as the CL binary which is obviously being found, but you're the second Ubuntu user this week to report a problem,<br>
<br>
Any chance this is a 64-bit system?  If you login without the login.cl file, what is the result of<br>
<br>
<pre><code>cl&gt; show iraf arch                     # note two variable names
cl&gt; =osfn(&quot;bin$&quot;)</code></pre><br>
<br>
I would expect the first command to return "/iraf/iraf/" and ".linux", and the second to print "/iraf/iraf/bin.linux/".  On 64-bit systems it's sometimes possible that the filesystem inode is a 64-bit value and causes problems in that the iraf kernel doesn't "see" the file.<br>
<br>
-Mike
</div>
{% endraw %}

The 'arch' variable isn't defined and I looked at the installation instructions you followed and if you indeed installed V2.13 then I think you're seeing a known bug in the CL startup script.
