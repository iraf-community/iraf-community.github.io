**Mike Fitzpatrick** wrote on Jan 07, 2009

{% raw %}
<div>
I think you may have simply mistyped the value of the 'arch' environment variable, which should be the same as the IRAFARCH except for a leading period.  In your case IRAFARCH is 'redhat', and so the arch should be ".redhat".<br>
<br>
This variable is used internally to find the bin directories and is normally set by the 'cl' script.  Also, be sure to do a "limit stacksize unlimited" in your .cshrc file or on the command line for recent linux systems (or use "ulimit -s unlimited" for Bash shells, again something done for you by the 'cl' startup script).  Otherwise your script looks fine and nominally works for me as expected.<br>
<br>
-Mike

**Mike Fitzpatrick** wrote on Jan 07, 2009

{% raw %}
<div>
Try using the "program mode" syntax, i.e. <br>
<br>
<pre><code>ccxymatch(sources, field, .....)</code></pre><br>
<br>
instead of<br>
<br>
<pre><code>ccxymatch sources field ....</code></pre><br>
<br>
As written, the script is looking for a file names 'sources', not the filename stored in the 'sources' variable.  It's a CL quirk, but you'd see the same thing at the interactive prompt:<br>
<br>
<pre><code>
ecl&gt; s1 = &quot;dev$pix&quot;
ecl&gt; imstat s1
#               IMAGE      NPIX      MEAN    STDDEV       MIN       MAX
Error reading image s1 ...
ecl&gt; imstat (s1)
#               IMAGE      NPIX      MEAN    STDDEV       MIN       MAX
              dev$pix    262144     108.3     131.3       -1.    19936.
</code></pre><br>
<br>
-Mike

<div>
Same problem, 'match' and 'residuals' are local script variables, not actual filenames.<br>
<br>
You can either use the DELETE command in IRAF to do the same thing, or if you need to construct a host command build the string and pipe it to the CL for execution, e.g.<br>
<br>
<pre><code>printf (&quot;!rm -f %s %s\n&quot;, match, residuals) | cl()</code></pre><br>
<br>
