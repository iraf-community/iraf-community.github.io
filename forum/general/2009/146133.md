**Mike Fitzpatrick** wrote on Apr 21, 2009

{% raw %}
<div>
You need to construct the image section so it is a valid string, e.g.<br>
<br>
<pre><code>imstat (input//&quot;[1:60,&quot;//i//&quot;:&quot;//i//&quot;]&quot;, fields=&quot;mean&quot;, .....</code></pre><br>
<br>
This concatenates the image name with some literal strings and the 'i' variable to create the image section. <br>

**Mike Fitzpatrick** wrote on Apr 21, 2009

{% raw %}
<div>
<blockquote><br>
(1) Regarding this<br>
Code:<br>
imstat(input_copy//"[1:60,"//i//":"//i//"]",.....<br>
<br>
is there any rule for when to use slashes (//) and when to use double quotes(") ?<br>
</blockquote><br>
<br>
Literal strings must be in double quotes, the '//' operator simply concatenates strings.  In this example, 'input_copy' is a string variable and 'i' is an int variable, but the 'i' variable is converted internally so the entire operation is one big set of string concatenations.<br>
<br>
<blockquote><br>
ERROR on line 27: cannot open `means_left' for writing</blockquote><br>
<br>
By default, IRAF won't let you overwrite an existing file.  The '&gt;&gt;' is a file append, if you want to overwrite you need to either explicitly delete the file first, or else do a <br>
<br>
<pre><code>cl&gt; set clobber = yes</code></pre><br>
<br>
where the 'clobber' environment variable says to let you overwrite.<br>
<br>
As for the last example, a scan() to a literal string can't be done, the first two answers should be all you need.<br>
<br>
-Mike<br>
<br>
[/quote]
</div>
{% endraw %}

**Mike Fitzpatrick** wrote on Apr 21, 2009

{% raw %}
<div>
<blockquote>I mean, can't I save different file names in this variable - means_left - if it is one?</blockquote><br>
<br>
Yes.  A 'file' type is effectively a string variable, but you need to use it as a variable, i.e. do not put it in quotes so the value of the variable is used and not the literal string "means_left".<br>
<br>
