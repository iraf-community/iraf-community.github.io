<blockquote><br>
[2] iMac CPU up to 100% - fc-cache is hogging up my CPU. Normally goes away when I quit IRAF/X11, but sometimes it just hangs there for a minute.<br>

<br>
The fc-cache is the X11 font-cache and nothing to do with IRAF.  X11 on Intel systems has all sorts of issues, check the various apple sites for hints on this.<br>
<br>
<blockquote><br>
[3] I have these tutorials on <a href="http://iraf.noao.edu/iraf/ftp/iraf/misc/">http://iraf.noao.edu/iraf/ftp/iraf/misc/</a> (file: exer211.tar.Z), and I'll need your help here. Let's expand the package and go to exercises/intro. Inside there are files fintro0001 and fintro0002. On previous installations, I could use rfits on the two files fine, but now on both computers, rfits gives me a "cannot open pixel file" error. </blockquote><br>
<br>
The error means that the 'imdir' environment variable is naming either a directory that doesn't exist, or one you can't write to.  The 'imdir' is set in your login.cl file, you can use a value like<br>
<br>
<pre><code>reset imdir = &quot;HDR$pix/&quot;</code></pre><br>
<br>
to put the pixel files in a 'pix' subdirectory of where the headers live.<br>
<br>
<blockquote><br>
Also, a note about the tutorial: On an old installation (2008), on my iMac G5, when I do an rfits and work with files, I am free to use .imh, but on my MacBook, the files come out as .fits and I have to work in .fits. Is there any way I can change that too?</blockquote><br>
<br>
The default 'imtype' for v2.14 systems in now FITS, you can uncomment and edit the value in your login.cl file to reset it back to 'imh' if you like, but FITS files can be used directly by the system.  For the tutorial data, you can add the needed ".fits" extension with the command<br>
<br>
<pre><code>cl&gt; rename fintro* fits field=extn</code></pre><br>
<br>
-Mike
