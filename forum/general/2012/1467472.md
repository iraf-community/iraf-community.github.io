<div>
Other than access to a machine that reproduces the problem, the only thing that might help is to run the task under a debugger to get a stack trace, i.e.<br>
<br>
<pre><code>
cl&gt; epar imcombine
    ..... set the parameters 
cl&gt; dpar imcombine &gt; dpar
cl&gt; logout

Then at the unix prompt

    % gdb /iraf/iraf/bin.macosx/x_images.e
    gdb&gt; run imcombine @dpar
    ......if it then stops at the segfault
    gdb&gt; where
</code></pre> <br>
<br>
and send/post the stack trace.<br>
<br>
Two things though:  this will only help if it points to an obvious coding error, if this is a memory corruption where we need to debug this ourselves we back to needing a machine to reproduce the problem.  Second, you should try the above using a v2.16 binary to see whether this is either a new bug or something possibly fixed already.  In any case, a patch would likely require a new binary or IRAF update to fix unless you find a parameter setting that works around the problem.
</div>
