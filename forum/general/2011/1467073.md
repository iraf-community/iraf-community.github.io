# fitcoords changes in IRAF v2.15

**emma** wrote on Dec 20, 2011

{% raw %}
<div>
Hi Mike,<br>
<br>
I'm currently testing IRAF v2.15 and I was hoping you could confirm that the minimum value for the fitcoords.xorder and fitcoords.yorder parameters are now equal to 2? Previously, with IRAF v2.14.1, I had xorder set to 1 and fitcoords didn't complain. Now, fitcoords says "Parameter xorder: value `1' is less than minimum `2'".<br>
<br>
I checked the help file for fitcoords and this change wasn't mentioned. I also checked the bug log (<a href="http://iraf.noao.edu/iraf/ftp/iraf/v215/bugs.log)">http://iraf.noao.edu/iraf/ftp/iraf/v215/bugs.log)</a> but it wasn't mentioned there either.<br>
<br>
If the minimum value is now 2, I'd like to update our help files accordingly ... please can you confirm that this is the case?<br>
<br>
Many thanks,<br>
<br>
Emma :)
</div>
{% endraw %}

**Mike Fitzpatrick** wrote on Dec 20, 2011

{% raw %}
<div>
The change was made earlier this year, presumably in response to a bug report.  From the longslit$Revisions file:<br>
<br>
transform/trsetup.x<br>
transform/igsfit/igscolon.x<br>
fitcoords.par<br>
    1. The fitcoords fitting orders can not be set to less than 2.<br>
    2. There is an attempt to avoid divide by zero in trsetup.x.<br>
    (2/1/11, Valdes)
</div>
{% endraw %}
