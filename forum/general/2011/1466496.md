<div>
<blockquote><br>
If I install the 2.15 with 64 bits support, I am getting strange errors with the STSDAS package (example, igi "segmentation error'). </blockquote><br>
<br>
This is a separate issue from installation of IRAF, see my comment on the other thread.<br>
<br>
<blockquote><br>
If I try to install the 2.14 version forcing architecture, I get the following error: "/iraf/iraf/bin.linux/ecl.e: error while loading shared libraries: libtermcap.so.2: wrong ELF class: ELFCLASS64" </blockquote><br>
<br>
This message just means that you don't have the 32-bit termcap libraries installed.  You can get a statically linked ecl.e binary from <a href="ftp://iraf.net/ftp/pub/fitz/ecl.e">ftp://iraf.net/ftp/pub/fitz/ecl.e</a>  that will work around this problem for now.<br>
<br>
I'm not sure what you mean by 'forcing the architecture'....If you have both the 32- and 64-bit binaries installed you can 'force' which one to be used by setting the IRAFARCH variable but it sounds like you mean something else.  Note the STSDAS/TABLES binaries already <strong>are</strong> the 32-bit version even if the IRAF system is 64-bit.    Unless you've recompiled the package locally, the problem is in the IGI task itself.  If you did compile however, it is know to now work since STSDAS hasn't been/won't be ported to 64-bit<br>
<br>
So what I have to do? Uninstall my system to the 32 bits version?! I hope to not do that...
