# dealing with spaces (" ") in image names

**Andrew Staunton** wrote on Jun 15, 2011

{% raw %}
<div>
I have a set of .fit files with a space (" ") instead of a hyphen ("-") or underscore ("_") separting the components, eg:<br>
<br>
first second1.fit<br>
first second2.fit<br>
first second3.fit<br>
etc.<br>
<br>
I want to rename them with a connecting character (such as hyphen), eg:<br>
<br>
first-second1.fit<br>
first-second2.fit<br>
first-second3.fit<br>
etc.<br>
<br>
so step one is list all the files into a text file, say original.txt and then create a second textfile with the spaces replaced by hyphen, call that altered.txt - this much can be done with translit...finally I want to use imcopy  to rename them:<br>
<br>
<pre><code>
imcopy @original.txt @altered.txt 
</code></pre><br>
<br>
however, imcopy does not recognise the space and so I get error message:<br>
 <br>
<blockquote><br>
ERROR: Cannot open image (firstsecond.fit)<br>
</blockquote><br>
<br>
ie the space was ignored....<br>
<br>
Be grateful for advice on how to deal with this.
</div>
{% endraw %}

**Mike Fitzpatrick** wrote on Jun 15, 2011

{% raw %}
<div>
Spaces aren't legal in IRAF filenames, even if you quote or escape them in many cases.  Simplest thing is to deal with this outside of IRAF entirely, e.g.<br>
<br>
<pre><code>% paste original.txt altered.txt | sed -e &quot;s/^/mv /g&quot; &gt; rename.sh
% sh rename.sh
</code></pre><br>
<br>
where I'm assuming the filenames in 'original.txt' have the spaces escaped with a backslash.  This will create a 'rename.sh' script using the unix 'mv' command to rename the files.<br>
<br>
Note the same issue applies to directory names, e.g. if the path to your data directory is "/home/Andys Computer/data" you may encounter problems.
</div>
{% endraw %}
