<div>
I don't know how to use pselect, but I've worked around your problem in other ways.<br>
<br>
As it happens, you can put the relevant .pst file in the exclude option for substar, and that solves the problem of having to make another nst file completely. <br>
<br>
It's not in the Massey/Davis 1992 document, which is unfortunate, because I figured the whole pst thing out AFTER I wrote some IDL code that does make a new NST file.  I'd be happy to give a copy of the code to someone to help them out, but this is what my does:<br>
<br>
1.  Uses the NASA IDL tools program readcol to read in the NST file.  Readcol is a reasonably smart function and will ignore the second line per star, since the format does not mach the first line. <br>
2.  Makes a histogram of the column "group".  This returns an array with the number of elements in each group, in order, and doesn't care WHAT they are.<br>
3.  Gets the number of unique elements of the column group (same as the number of elements in our histogram).<br>
4.  Makes a new nst file numbered n+1<br>
5.  Reads in the old nst file AGAIN, this time line by line.  The first 42 lines are pumped in directly to the new file.<br>
6.  Now we loop over the number of groups.  First we read the next two lines into a dummy variable.<br>
7.  If our histogram tells us there is two or more stars in our group, we read in two lines for each additional star, writing them directly to our new nst file.<br>
8.  We loop until we are out of groups and close both nst files.<br>
<br>
There may be a better way to do this, but that worked for me.  Though seriously knowing about the .pst thing in substar would have saved me hours of time.
