# Incorrect sensitivity curve for spectroscopic data

**Kimmo Lehtinen** wrote on May 06, 2011

{% raw %}
<div>
Hi <br>
<br>
I was analyzing our long-slit data from ESO VLT/FORS instrument and noticed that the sensitivity curve I derived was different  from what it used to be. I am sure that the sensitivity curve I derived earlier is OK. <br>
<br>
I found out the reason to be the following: in the file 'std', which is the output flux file from the standard-task (and used by SENSFUNC), the observed spectrum of the standard star is shifted in wavelength. <br>
That is, the observed spectrum of the standard star in the file 'std' is the same as previously, but it is shifted by about 250 Angstrom into longer wavelengths. That will make the derived sensitivity curve different. This was easy to note because the sensitivity curve drops <br>
rapidly below about 4000 Angstrom. <br>
<br>
I am using IRAF V2.15.1a on a 64-bit Linux/Centos machine. I installed IRAF at 4th of May. <br>
<br>
I am following the manual 'A User's Guide to Reducing Slit Spectra with IRAF'.<br>
I am using an arc-lamp image to get the wavelength solution for the standard. <br>
I also noticed that in the first plot of the identify-task, showing the spectrum of the arc-lamp, the number of pixels is over 4000, although my spectrum has only 2048 pixels. <br>
However, later within the identify-task when I use the 'h' graph key to plot wavelength versus pixel coordinate, the pixel values <br>
seem to be correct. <br>
<br>
The following files can be found at the page   www.helsinki.fi/~kklehtin/IRAF<br>
<br>
FORS2.ms.fits	Spectrum of the standard star from apall-task<br>
<br>
cFORS2.fits  	A trace from the arc-lamp image. Output from apall-task, and input for the identify task<br>
<br>
idcFORS2	Output from the identify-task. In this file the wavelengths and pixel coordinates seem to be correct. <br>
<br>
dFORS2.ms.fits  spectrum of the standard star, after using the dispcor-task. I used 'linearize=no'. This file is used as an <br>
 		input to the standard-task. <br>
<br>
Thanks for your help, Kimmo Lehtinen<br>
<br>
			University of Helsinki, Finland
</div>
{% endraw %}

<br>
I now need to know something specific about what you think is wrong.  You say things are shifted but is there some quantitative feature that tells you this.<br>
<br>
My concern is the following.  Your arc fit looks quite reasonable but there are no constraining lines near the end of the spectrum, particularly in the blue.  So the wavelength you derive for the first pixel can be off significantly from what you might thing it should be and will change with the fitting order you use.  So leaving off the blue end, is there evidence for a shift?  After you dispersion calibrate the standard star you could check the strong absorption lines and see if they are at the right wavelength, say using SPLOT.  If the wavelengths appear correct in the dispersion calibrated standard star then there doesn't seem to be anything that can go wrong with sensfunc.<br>
<br>
So we need a specific quantitative feature which is wrong to figure out the source of a problem.<br>
