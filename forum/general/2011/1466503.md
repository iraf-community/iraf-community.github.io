**Mike Fitzpatrick** wrote on May 13, 2011

<div>
While it's true SPLOT is not core Pyraf functionality, pyraf implements its own graphics system to render plots, read the cursor, etc, even up to the point of manipulating the window focus as needed. See e.g.<br>
<br>
<a href="http://stsdas.stsci.edu/pyraf/doc.old/pyraf_tutorial/PyRAFGraphics.html">http://stsdas.stsci.edu/pyraf/doc.old/pyraf_tutorial/PyRAFGraphics.html</a><br>
<br>
where it states:<br>
<br>
<blockquote><br>
PyRAF attempts to manipulate the window focus and the cursor location in a sensible way. For example, if you start an interactive graphics task, the mouse position and focus are automatically transferred to the graphics window. If the task does not appear to be responding to your keyboard input check to see that the window focus is on the window expecting input.</blockquote><br>
<br>
This is certainly not an IRAF issue, your best bet is to go back to ST if you don't get a firm reply here.  Note this bug seems to have been reported to them before:  <a href="https://trac6.assembla.com/pyraf/ticket/111">https://trac6.assembla.com/pyraf/ticket/111</a><br>
<br>
That said, you can set focus-follows-mouse policy for the Terminal.app and X11 apps using the commands<br>
<br>
<pre><code>
% defaults write com.apple.Terminal FocusFollowsMouse -string YES
% defaults write com.apple.x11 wm_ffm true
</code></pre><br>
<br>
The XQuartz pyraf window would need to implement something similar.
</div>
{% endraw %}
