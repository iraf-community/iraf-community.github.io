**Mike Fitzpatrick** wrote on Mar 22, 2011

{% raw %}
<div>
I think I found a problem that was caused by relative differences between the size of the integer values used internally, and the real valued array being used by the task.  In theory this affects all tasks, but practically speaking it only affects columnar access to the data.<br>
<br>
In any case, I've put a patched x_tv.e binary in <a href="ftp://iraf.noao.edu/iraf/v215/support/macintel">ftp://iraf.noao.edu/iraf/v215/support/macintel</a> that should fix your IMEXAM problem, there's also an x_images.e binary that will fix many other tasks.<br>
<br>
Longer term until a patch is built, I'd suggest you install the V2.15 that includes both the 'macosx' and 'macintel' binaries.  if you run into other problems a quick workaround is to then fall-back to using the 32-bit binaries by setting an 'IRAFARCH' environment variable (with a value of 'macosx') before logging into the CL.  Otherwise, let me know if you're still have problems with IMEXAM, I'm still running a few tests.
</div>
{% endraw %}
