**Mike Fitzpatrick** wrote on Mar 15, 2010

{% raw %}
<div>
Hi Amber,<br>
<br>
There are two problems:  Less fatal is the fact that the FITS file is not properly zero-padded to an integral number of 2880 byte blocks.  The cause of the segfault however is a bug in the FITS kernel where the BZERO value is causing the image to be seen as a real and the kernel is trying to read the pixels as real values rather than as shorts with a scaling.  This means it's reading beyond the physical length of the file and returning an invalid pixel pointer leading to the error.<br>
<br>
The fix is trivial, simply copy the images in place and allow the system to rewrite the images as real, i.e.<br>
<br>
<pre><code>
cl&gt; imcopy *.fits *.fits
</code></pre><br>
<br>
The resulting images will be properly padded and written with 32-bit pixels.  Doing this to your sample image allowed FIXPIX to work properly, you might want to backup your image first just to be safe.<br>
<br>
-Mike
</div>
{% endraw %}
