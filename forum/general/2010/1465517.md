# Possible bug in imcombine v2.14.1?

**emma** wrote on Oct 29, 2010

{% raw %}
<div>
Hello :)<br>
<br>
I wanted to report a possible bug in imcombine in v2.14.1, related to the new imcmb parameter. In the revsion notes for v2.14.1 (v2141revs.txt), it says:<br>
<br>
images.immatch.imcombine<br>
	A new parameter "imcmb" was added to control the value written to<br>
	the IMCMBnnn keywords in the output image.  The value is a keyword<br>
	in the input images to be copied to the output IMCMBnnn keywords.<br>
	The default parameter value, "$I", is the basename input image<br>
	name as before.<br>
<br>
This means that, as default, the IMCMBnnn keywords should be written as they would have been using v2.14. However, this appears not to be the case. Running v2.14.1 of imcombine does not write the IMCMBnnn keywords, even when the imcmb parameter is explicitly set to be equal to "$I".<br>
<br>
Would it be possible for someone to take a look into this? I would very much like those keywords in the header ;)<br>
<br>
Many thanks,<br>
<br>
Emma :)
</div>
