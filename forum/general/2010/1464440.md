<div>
Right, in XDIMSUM the TIME task is actually a CL builtin command but it is used repeatedly in the package as<br>
<br>
<pre><code>time (&quot;&quot;)</code></pre><br>
<br>
You'll need to change each instance in the various tasks.  The package author apparently isn't a pyraf user but this is the first report we've had of any incompatability.

**Mike Fitzpatrick** wrote on May 27, 2010

{% raw %}
<div>
In this case I think the problem is a bug in PyRAF.  The code in question is something like<br>
<br>
<pre><code>nin = sections.nimages</code></pre><br>
<br>
which says to set the script variable 'nin' to the value of the SECTIONS task 'nimages' parameter, this is perfectly legal CL syntax.  The confusion I think is coming from the fact that the XFIRSTPASS script also defines 'sections' as a hidden string param, disambiguating the task from the parameter in the script should fix it.<br>
<br>
<blockquote>Since much of the code in xdimsum is written in cl, there may be other problems down the line. <br>
Generically speaking, should I expect cl code to work when called via the Pyraf command line, or am <br>
I expecting too much.</blockquote><br>
<br>
I don't think pyraf ever claimed to be 100% compatible with CL syntax and there *are* known (and unknown) issues.  (Personally, though, I do have some issues about some claims that *have* been made, but that's another thread).  In general, we make NO claims that any and all scripts will/should run under pyraf, problems will need to be dealt with as they arise.
</div>
{% endraw %}
