<div>
An excerpt of CL script code that would compute the rotation angle looks something like:<br>
<br>
<pre><code>

        # Get the CD matrix from the image.  We initialize the values above
        # so if they don&#x27;t exist in the header we won&#x27;t change the value here
        # (but we need to read them one at a time).
        hselect (img, &quot;cd1_1&quot;, yes) | scan (cd11)
        hselect (img, &quot;cd1_2&quot;, yes) | scan (cd12)
        hselect (img, &quot;cd2_1&quot;, yes) | scan (cd21)
        hselect (img, &quot;cd2_2&quot;, yes) | scan (cd22)

        # Compute the plate scale (arcsec/pixel) for the image.
        scale = 3600. * sqrt ((cd11**2+cd21**2+cd12**2+cd22**2)/2.)
        xrot  = abs (datan ( cd21, cd11))
        yrot  = abs (datan (-cd12, cd22))
        rot   = (xrot + yrot) / 2.0
</code></pre><br>
<br>
where 'rot' is the rotation angle.<br>
<br>
Otherwise, have a look at the SREGISTER, WREGISTER or XREGISTER tasks for ways to register the images to a common WCS for easier stacking.
</div>
{% endraw %}

<div>
There is also a tool within the images package:<br>
<br>
images.imcoords.ccmap<br>
<br>
take this as an example<br>
<br>
input   =         coo.dat  The input coordinate files<br>
database=                coo.out  The output database file<br>
(solutio=                     ) The database plate solution names<br>
(images =            foo.fits) The input images<br>
(results=                     ) The optional results summary files<br>
(xcolumn=                    1) Column containing the x coordinate<br>
(ycolumn=                    2) Column containing the y coordinate<br>
<br>
...<br>
<br>
The file coo.dat has to include the x, y, Rec, Dec positions of stars in the image (one per line, the more the better).<br>
Then everything is computed and written into coo.out, including the angle you are looking for.
</div>
{% endraw %}
