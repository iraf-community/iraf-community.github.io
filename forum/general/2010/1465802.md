# Problem with for loop

**ofwolf42** wrote on Dec 24, 2010

{% raw %}
<div>
Hi, I'm new to the forums and fairly new to IRAF as well. I'm using it for a college project and I'm trying to set up a basic script to find the pixel position of a source on a series of fit images.<br>
<br>
I've set up a for loop that essentially looks like this:<br>
<pre><code>{ for(i=1; i&lt;10; i+=1)
{ 
s1= &quot;0&quot;//i
s2= s1//&quot;.fit&quot;
minmax s2 &gt;&gt; data.txt
}}</code></pre><br>
<br>
To my knowledge this should get the min and max positions of a series of images with the names: "01.fit", "02.fit", "03.fit" etc and output the information to data.txt.<br>
But each time I run the for loop it says "Warning: could not open image (s2)" Whereas when I replace the minmax call with print(s2) it ouputs the file names perfectly. There must be some basic syntax error I'm making but I don't know what it is.<br>
<br>
Also I will point out that the file names do exist, I can call them outside the for loop with out issue. <br>
<br>
Any help would be greatly appreciated, thank you
</div>
{% endraw %}

**Mike Fitzpatrick** wrote on Dec 24, 2010

{% raw %}
<div>
Your last line needs to be written in "program mode" so the script variables aren't confused with literal names, e.g.<br>
<br>
<pre><code>minmax (s2, &gt;&gt; &quot;data.txt&quot;)</code></pre><br>
<br>
Note the literal name 'data.txt' needs to be quoted.  You can also just combine all the concatenation operators as needed, e.g.<br>
<br>
<pre><code>minmax (&quot;0&quot;//i//&quot;.fit&quot;, &gt;&gt; &quot;data.txt&quot;)</code></pre>
</div>
{% endraw %}

{% raw %}
<div>
Try turning on the 'force' parameter (e.g. "force=yes" or "force+" in the argument list), some image may already have min/max keywords defined as a result of processing.
