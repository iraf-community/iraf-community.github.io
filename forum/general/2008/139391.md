# tabpar bug?

**sw** wrote on Apr 16, 2008

{% raw %}
<div>
I'm using tabpar to extract something from a file. Normally this works fine, but when I'm extracting something that is number-colon-number it doesn't.<br>
<br>
For example: I have a file named foobar. This file contains only "123:456" (without quotes).<br>
<br>
Using the code:<br>
<pre><code>
tabpar(table=&quot;foobar&quot;, column=1, row=1)
print(tabpar.value)
</code></pre><br>
<br>
I get the result: "130:36.0"<br>
<br>
Why does this not print out "123:456"?<br>
<br>
This happens for any number-colon-number situation. Is there some reason why this should happen?<br>
<br>
Thanks,<br>
<br>
Sam
</div>
{% endraw %}

**Mike Fitzpatrick** wrote on Apr 16, 2008

{% raw %}
<div>
The CL is interpreting the value 123:456 as a sexagesimal number, and so converts it to real as "123.0 + 456.0/60."    The result is 130.6 (I assume your 123.36 is a typo), to work around it you need to quote the value.<br>
<br>
-Mike
</div>
{% endraw %}
