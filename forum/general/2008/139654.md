HI Henry,<br>
<br>
Good to hear from you again.<br>
<br>
What happens if you try running the /iraf/iraf/bin.linux/ecl.e file directly?  A 'command not found' usually indicates the command isn't in your path, but it can also happen when e.g. a symlink to a command file isn't valid, there's a permissions problems further up in the path (e.g. is /iraf world readable, etc), or the command cannot be executed for some reason. <br>
<br>
You might also try starting as "cl -old" to fire up the old CL to see if that works.  If it does, the problem may just be limited to the ECL binary and if so I'd suspect it's because of a missing termcap/ncurses library (e.g. does "ldd /iraf/iraf/bin.linux/ecl.e" show anything missing?).  You can workaround the last problem by getting a static binary from <a href="http://iraf.net/ftp/pub/fitz/ecl.e">http://iraf.net/ftp/pub/fitz/ecl.e</a> and just replace the binary you have after making it executable.  Hope this helps.<br>
<br>
Cheers,<br>
-Mike

I recalled this morning that I had a problem like this on another 64 bit installation while trying to run some 32 bit applications.<br>
<br>
Running the wonderful 'ldd' command did the trick.<br>
For thos who don't know, this command gives the library dependencies of an executable.<br>
<br>
&gt; ldd /iraf/iraf/bin.linux/ecl.e<br>
  shows us<br>
<br>
        linux-gate.so.1 =&gt;  (0xffffe000)<br>
        libncurses.so.5 =&gt; /lib32/libncurses.so.5 (0xf7eb8000)<br>
        libm.so.6 =&gt; /lib32/libm.so.6 (0xf7e93000)<br>
        libc.so.6 =&gt; /lib32/libc.so.6 (0xf7d43000)<br>
        /lib/ld-linux.so.2 (0xf7ef5000)<br>
<br>
This gave me the clue that I was missing some 32 bit libraries.<br>
<br>
It turns out that on ubuntu, we only have to load up the package 'lib32ncurses5'. This also loads another 32 bit c library.<br>
<br>
I believe that I have seen other 64/32 bit postings. I suspect that we may not have loaded every 32 bit library we will need, but so far so good.<br>
<br>
[edit]<br>
We found further problems for those using 'xgterm' and 'ds9'.<br>
For these we needed the following ubuntu packages installed:<br>
<br>
libx11-dev<br>
ia32-libs<br>

**Mike Fitzpatrick** wrote on Jun 03, 2008

<div>
The 'not a dynamic executable' simply means the binary is linked statically, which it should be.  If you go to the $iraf/bin.linux directory and try executing the 'ecl.e' file (e.g. with "./ecl.e") it should either start or give you an error message of some kind (post that)).  <br>
<br>
If what you're generally seeing is a 'command not found' message then check your path definition in your .cshrc or .bashrc file to be sure it includes the directory where you installed the iraf commands (typically /usr/local/bin).  If you're seeing the message as in the original post where the 'cl' command is found but the binary isn't, then there may be something wrong in the way the distribution files were unpacked (i.e. check the $iraf/bin.linux directory to be sure there is something there).<br>
<br>
-Mike
</div>
