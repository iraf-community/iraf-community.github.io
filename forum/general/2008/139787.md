Without seeing the script I can't really comment, the error might mean there is an actual bug in the script or it could be something more subtle that is trashing memory in the CL and leading to a bogus message.  You can use the d_on/d_off commands to turn debugging on/off if you want to see the gory details of script execution, a gentler approach may be to use the d_trace toggle command to at least find out more about where in the script the problem is happening.  <br>
<br>
In general, there are no open problem reports related to this error, but it can happen legitimately if you e.g. try to pass arrays to another procedure through parameters.<br>
