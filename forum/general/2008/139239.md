**Mike Fitzpatrick** wrote on Mar 25, 2008

<div>
A segfault is usually a coding error, but in some cases can be caused by the data.  Does an IMSTAT on the image manage to read it successfully or do you see a similar segfault.  Did you do the subtraction with IMARITH or something else?<br>
<br>
If no other task can read the image either then it's the data:  You can force the image to be a different format using e.g.<br>
<br>
<pre><code>cl&gt; imarith im1 - im2 result.fits</code></pre><br>
<br>
If you can then implot/imstat the 'result.fits' check your 'imdir' variable:  This is where the .pix files for IMH format images are stored and in your case may not be valid or writable.<br>
<br>
OTOH if it's only implot that's failing, please post a url to the image or put it in the anonftp at <a href="ftp://iraf.noao.edu/pub">ftp://iraf.noao.edu/pub</a> and I'll try to reproduce the problem.<br>
<br>
Cheers,<br>
-Mike<br>
<br>
P.S.   Also be sure you're using the Jan14 critical update mentioned on the homepage, that usually causes a different error but better to check anyway.
</div>

**Mike Fitzpatrick** wrote on Mar 25, 2008

{% raw %}
<div>
The image you posted has the pixel file has just an empty string, i.e. what you have is a header but no pixels.<br>
<br>
What *is* the value of your 'imdir' variable (i.e. "cl&gt; show imdir")?  Is this a directory you can write to and that actually exists?<br>
<br>
A simple test is to rest the imdir to something known like the directory where the image is being created:<br>
<br>
<pre><code>
cl&gt; reset imdir = &quot;HDR$/&quot;
cl&gt; flpr 0                                           # zero, not oh
cl&gt; imarith one.fits - two.fits result.imh
cl&gt; imstat result.imh
</code></pre><br>
<br>
You can reset the imdir by editing your login.cl file, note that a value like "HDR$pix/" (trailing '/' required!) will create a 'pix' subdirectory and put the pixel files there.<br>
<br>
-Mike
</div>
{% endraw %}
