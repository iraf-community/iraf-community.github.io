<div>
*******************************************************<br>
<br>
    TABLES/STSDAS v3.8 and STSCI_PYTHON v2.6 NOW AVAILABLE<br>
<br>
    *******************************************************<br>
<br>
The Science Software Branch of the Space Telescope<br>
Science Institute wishes to announce the availability of version<br>
3.8 of the Space Telescope Science Data Analysis Software (STSDAS).<br>
Concurrent with the STSDAS release, we have also released v3.8 of<br>
the TABLES external package. Both of these packages are layered upon<br>
IRAF as external packages; it is therefore necessary to obtain and<br>
install IRAF (from <a href="http://iraf.noao.edu)">http://iraf.noao.edu)</a> before installing TABLES<br>
and STSDAS.  STSDAS is linked against libraries in TABLES, so TABLES<br>
must be installed before STSDAS.<br>
<br>
This release of STSDAS contains changes to NICMOS, ACS, STIS,<br>
WFPC/CALWP2, Dither, SYNPHOT, Nebular, and CTOOLS, with some minor<br>
changes to GFLIB. One new package has been added; namely, WFC3. This<br>
package currently only contains CALWF3, the pipeline processing<br>
software for WFC3 data.<br>
<br>
STSDAS also includes some Python-based tasks; running these requires the<br>
STScI Python Libraries to be installed (all the non-Python tasks<br>
can be used in the traditional way and do not require Python<br>
or the STScI Python libraries). These tasks can only be run from<br>
PyRAF using standard IRAF CL task syntax, or within Python scripts<br>
using Python syntax.<br>
<br>
The Science Software Branch of STScI also wishes<br>
to announce the availability of version 2.6 of STSCI_PYTHON.<br>
Stsci_python is a collection of Python modules, packages and C<br>
extensions that has been developed to provide a general astronomical<br>
data analysis infrastructure. They can be used for Python tasks<br>
that are accessible from within STSDAS when running under PyRAF or<br>
standalone from within Python.<br>
<br>
All tasks in this release of STScI_Python rely on the<br>
use of numpy for array operations and will be the last release to provide<br>
any support for the use of numarray. It has been reorganized such that<br>
tasks specific to each HST instrument are grouped as separate packages, with<br>
the addition of new tasks for WFPC2 and COS data. This release also <br>
contains an<br>
updated version of Multidrizzle as used by the HST ACS and WFPC2 pipelines,<br>
along with new versions of PyFITS and PyRAF. Use of the Python<br>
tasks requires upgrading to this version of STSCI_PYTHON.<br>
<br>
FIRST RELEASE TO USE NUMPY<br>
==========================<br>
This release is the first release that uses numpy as the base array<br>
package. Numarray is no longer used within STScI_Python. Support<br>
for numarray will be phased out entirely within a year of this<br>
release. Support for numarray now is limited to critical problems or<br>
major platform support issues. The threshold for 'critical' or 'major'<br>
is continually becoming harder to meet; you are advised to migrate<br>
to numpy as soon as possible.<br>
<br>
This switch to numpy represents a step towards unifying the Python<br>
scientific community in the use of a common array package.  This is<br>
a very desirable outcome despite the inconvenience in making the<br>
switch. Information on making the switch to numpy from numarray can<br>
be found in this document:<br>
<br>
<a href="http://www.stsci.edu/resources/software_hardware/numarray/numarray2numpy.pdf">http://www.stsci.edu/resources/software_hardware/numarray/numarray2numpy.pdf</a><br>
<br>
STSCI_Python on WINDOWS<br>
=======================<br>
This release includes a port of stsci_python that runs natively under Windows.<br>
Although IRAF is now available for running under Cygwin, PyRAF is not yet<br>
available for use under Windows. This means that, in this release, all<br>
the tasks in the STScI_Python distribution will be run under Python<br>
(or preferably, IPython) on Windows using Python syntax rather than<br>
a parameter-based interface provided by PyRAF and IRAF.<br>
<br>
The primary requirement is that the Windows executables were built<br>
against and, therefore, can run only under Python 2.5.<br>
