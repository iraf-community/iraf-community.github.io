# Double slashes cancel out in Iraf path

**Nicola Caon** wrote on Sep 26, 2008

{% raw %}
<div>
Hi,<br>
<br>
I've just noticed that when a string used as a path contains two adjacent slashes, they cancel out. The following example will make it clear:<br>
<br>
<pre><code>
ecl&gt; s1=&quot;/1/2/3/4/&quot;
ecl&gt; path(s1)
dhcp-dyn-55-44.a!/1/2/3/4/
ecl&gt; s1=&quot;/1/2//3/4/&quot;
ecl&gt; path(s1)
dhcp-dyn-55-44.a!/1/23/4/
</code></pre><br>
<br>
More in general, it seems that this is true for an even number of repeated slashes, while an odd number will leave just one slash in the path. I checked this in v2.12.2a and v2.14 (Linux) and v2.14 MacIntel.<br>
<br>
It's not that I define variables with extra slashes for fun; I was building a path string by appending to a Unix environment variable read using the envget command, something like:<br>
<pre><code>s1=envget(&quot;MYPATH&quot;)//&quot;/some/subdirectory/&quot;</code></pre><br>
with MYPATH already containing a trailing slash.<br>
<br>
I'm not sure whether this is a feature of Iraf, and it's there for very good reasons, or is some sort of parser bug. As far as I know, in Linux/Unix extra slashes are silently ignored and thus completely harmless. <br>
<br>
Thanks very much,<br>
Nicola
</div>
{% endraw %}

**Mike Fitzpatrick** wrote on Sep 26, 2008

{% raw %}
<div>
Nicola,<br>
<br>
It;s not a bug in the sense that the task is doing what it says it will, even if that's not what you expect 8-)  Specifically, the argument to PATHNAMES is a template string in which you're allowed to use wildcards and other metacharacters to expand the template.  In this case the '//' is being interpreted as the string-concatenation operator in the template.<br>
<br>
One workaround for this in a  script is to simply remove the duplicate, e.g.<br>
<br>
<pre><code>
s1 = &quot;/1/2//3/4/&quot;
prinit (s1) |  tr (&quot;STDIN&quot;, &quot;//&quot;, &quot;/&quot;, collapse+)
</code></pre><br>
<br>
If you know the envget returns a path with a trailing '/' you can also just leave it out of your string when you build the directory string. <br>
<br>
Cheers,<br>
-Mike
</div>
