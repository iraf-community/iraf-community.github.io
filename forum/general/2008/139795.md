# some daophot inconsistencies

**Jason Quinn** wrote on Jul 05, 2008

{% raw %}
<div>
I noticed some minor bugs and inconsistencies in the handling of certain things in <strong>daophot</strong> package that should be easy to fix.<br>
<br>
1) The <strong>phot</strong> and <strong>pstselect</strong> tasks' output files incorrectly use "scaleunit" as the descriptor of CLEAN rather than "switch". Actually this seems to affect all the phot tasks in the <strong>apphot</strong> package too (<strong>wphot</strong>, etc.) A bug in every IRAF photometry file ever produced! :wink:<br>
<br>
2) The <strong>daofind</strong> task's output coo file has FWHMPSF listed twice in the headers. I'm not sure how the subsequent tasks read the headers. Is the second one needed? Seems like it should be removed.<br>
<br>
3) IMAGE is described by <strong>pstselect</strong> in the headers of the output file (usually .pst.1) as "name" when it should be "imagename" to match the <strong>daofind</strong> (coo), <strong>phot</strong> (mag), <strong>psf</strong> (pst.2), and <strong>allstar</strong> (als) tasks.<br>
<br>
4) This next one is probably an apphot vs daophot thing that can't be fixed for history. IFILTER is described "name" in the mag file of <strong>phot</strong> while the <strong>pstselect</strong> (pst.1), <strong>psf</strong> (pst.2), and <strong>allstar</strong> (als) tasks call it "filter". Also SCALE is described as "units" by <strong>daofind</strong>, <strong>phot</strong>, and <strong>pstsel</strong> but "units/pix" by <strong>psf</strong> and <strong>allstar</strong>. I do think there's value in having it be "units/pix" but this would entail checking and changing wphot and so on. In any case, <strong>pstsel</strong> should be using the "units/pix" daophot style description.<br>
<br>
Jason
</div>
{% endraw %}
