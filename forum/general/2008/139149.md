<div>
The safest way to make changes to a package, even if it is just one <br>
task, is to copy the entire package tree to another directory.  The<br>
advantage of this is that usually changing one environment variable<br>
will replace the installed version with a private version.<br>
<br>
There is also one change that generally needs to be made to the package<br>
definitions so that the task is excuted from your executable rather than the<br>
one installed in the top level package (e.g. noao$bin.redhat) and the <br>
parameter files are found.  This generally means replacing references to<br>
x_*.e with xx_*.e.<br>
<br>
PSFMEASURE is actually structured in a convenient way so that you don't<br>
need to do the whole OBSUTIL package.  So I'll give you the details <br>
for making a private development version for just this task.<br>
<br>
1. cd &lt;some development directory&gt;<br>
2. cp -rp /iraf/iraf/noao/obsutil/src/starfocus .<br>
3. cd starfocus<br>
4. vi mkpkg<br>
        :g/^\$/s//#$/<br>
5. mkpkg<br>
<br>
6. cl <br>
7. cl&gt; obsutil<br>
8. cl&gt; reset starfocus=&lt;some development directory&gt;/starfocus/<br>
9. cl&gt; redefine psfmeasure=starfocus$xx_starfocus.e<br>
<br>
Notes:<br>
2. You could use some other name for the directory but there is no need.<br>
4&amp;5. This is to comment out the default lines so that "mkpkg" falls <br>
through to standalone.  This is for safety.  You could just do<br>
"mkpkg standalone"<br>
<br>
You can now modify files and recompile with mkpkg and test the <br>
changes.
