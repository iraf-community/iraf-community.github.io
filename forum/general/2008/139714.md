# ERROR: ambiguous parameter \`show' within \`&lt;searchpath&gt;

**Jason Quinn** wrote on Jun 19, 2008

{% raw %}
<div>
I'm confused by an error message that I'm getting that seems to be related to defining a task in my loginuser.cl file. I've made a minimum test case. If I make a file called ttt.cl containing:<br>
<br>
<pre><code>procedure ttt()

begin

hedit(&quot;someimage.fits&quot;,&quot;PSFMAG&quot;, &quot;15.0&quot;, add=no, addonly=no, delete=no, verify=no, show=yes, update=yes)

end
</code></pre><br>
<br>
and then load this in my loginuser.cl file via<br>
<br>
<pre><code>task $ttt=/data/jquinn/uqbar/lc/register.jason/ttt.cl
keep
</code></pre><br>
<br>
I get errors such as<br>
<br>
<pre><code>ERROR: ambiguous parameter `show&#x27; within `&lt;searchpath&gt;&#x27;
     called as: `ttt ()&#x27;
</code></pre><br>
<br>
It seems like the CL might be confusing the show parameter in hedit with the system show or some other task. But why, in context it is unambiguous. And why only show and not the update parameter? In a longer script, the error report points the user to a more-or-less random line.<br>
<br>
If I define the task within the CL rather than the loginuser.cl I get no problems at all. I might just not understand the way IRAF handles the searchpath.<br>
<br>
Jason
</div>
{% endraw %}

**Mike Fitzpatrick** wrote on Jun 19, 2008

{% raw %}
<div>
Hi Jason,<br>
<br>
This was a bug in the CL, basically the CL 'showtype' parameter was being found twice and causing the ambiguity.  The normal searchpath for paramters is task-&gt;package-&gt;cl, but in this case the task has no parameters and package and the cl are the same thing.  In any case, it is fixed for the next release and might explain similar errors over the years.<br>
<br>
A workaround until then is simply to declare a dummy 'show' param in you script, e.g.<br>
<br>
<pre><code>
procedure ttt()

begin
bool  show

hedit(&quot;someimage.fits&quot;,&quot;PSFMAG&quot;, &quot;15.0&quot;, add=no, addonly=no, delete=no, verify=no, show=yes, update=yes)

end </code></pre><br>
<br>
If you still have problems or would like the code change, let me know.<br>
<br>
Cheers,<br>
-Mike
</div>
