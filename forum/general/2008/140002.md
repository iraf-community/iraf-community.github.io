**Francisco Valdes** wrote on Aug 04, 2008

<div>
Hi Robert,<br>
<br>
Thanks for the data.  I found the source of the problem.  For the last version (the one identified as<br>
V4.8 ) there was a bug fix for binned data.  However it causes you error where you have<br>
flipped CCDSEC/DETSEC in the raw data.  The bug log is reproduced below.  I have put a<br>
fixed version of the source and binaries for some systems in the <a href="ftp://iraf.noao.edu/iraf/extern/">ftp://iraf.noao.edu/iraf/extern/</a><br>
directory.<br>
<br>
Yours,<br>
Frank<br>
<br>
<blockquote><br>
NUMBER: 562<br>
MODULE: mscred.ccdproc<br>
SYSTEM: V4.8<br>
DATE:   Tue Aug 12 12:19:30 MST 2008<br>
FROM:   valdes<br>
<br>
BUG:    The fix for bug number 546 was not fully correct.  It works for<br>
        binned data but results in an error for data which is flipped<br>
        (e.g. when CCDSEC/DETSEC have a starting column greater than<br>
        the ending column as in '[2048:1025,1:2048]'.  The error<br>
        is that the resulting CCDSEC in the processed image will<br>
        be off by one.  This can result is losing a column when<br>
        merging multiple amps.<br>
<br>
STATUS: Fixed for mscred V4.9.<br>
</blockquote>
</div>
