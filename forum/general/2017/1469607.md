**Mike Fitzpatrick** wrote on Apr 25, 2017

<div>
<br>
                IRAF commands are intended to be run from the CL interface since that is what handles things like parameter passing, graphics rendering, etc.  IRAF scripts *can* be executed as host level commands (see http://iraf.noao.edu/iraf/web/new_stuff/cl_host.html) and for a simple script such as your example it may be easier to write a CL script than to try to call IRAF binaries directly.<br>
<br>
You can call IRAF tasks from unix so long as you know the path to the binary containing the task and can supply the parameters, however this doesn't usually work well for any graphics or interactive tasks or tasks which require iraf environment variables (e.g. the "dev$pix" test image won't resolve the 'dev$' part of the path normally).  For example, to run IMCOPY you could use the command:<br>
<br>
/iraf/iraf/bin.linux64/x_images.e imcopy input=foo.fits output=bar.fits verbose=no<br>
<br>
For tasks with many parameters it is easier to supply the params using the @-file syntax, e.g. in the CL you can dump the params with:<br>
<br>
    cl\$this-&gt;_split2($m[0]) dpar imcopy \$this-&gt;_split2($m[0]) imcopy.par<br>
<br>
Then edit the 'imcopy.par' file with your values and execute the task as<br>
<br>
    /iraf/iraf/bin.linux64/x_images.e imcopy @/path/imcopy.par<br>
<br>
where you would substitute the iraf path and architecture name appropriate for y<br>
<br>
our system.<br>
<br>
Information on CL scripting can be found at https://iraf.net/irafdocs/script/<br>
</div>
{% endraw %}
