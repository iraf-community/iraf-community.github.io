**Emilliano Gregori** wrote on May 22, 2006

{% raw %}
<div>
Hello, try this:<br>
<br>
<pre><code>
disp img1.fits 1
disp img2.fits 2
!xpaset -p ds9 blink
</code></pre><br>
<br>
the first two "disp" lines load the images in the ds9 frames.<br>
the last line calls the "external" program xpaset and tells ds9 to start blinking. <br>
You can download the XPA clients xpaset and xpaget from the ds9 website, and you can find more info in the DS9 manual, section "XPA Access Points".<br>
<br>
Emiliano
</div>

**Mike Fitzpatrick** wrote on May 22, 2006

{% raw %}
<div>
Since you're creating a data cube it is also possible to have DS9 load this directly:  Use the 'File-&gt;Open Other-&gt;Open Multi Ext as Data Cube' menu to open the MEF where each extension is a different frame in the sequence, then use the 'Frame-&gt;Data Cube' menu to bring up the control box for it.  There may be XPA access points for these, check the docs or perhaps Emiliano can confirm this?<br>
<br>
Displaying from within IRAF is limited to 16 frames due to the IIS protocol.  You can automate the loading in a script, e.g.<br>
<br>
<pre><code>for (i=1; i&lt;=16; i=i+1) 
    display (&quot;hip12345.fits[&quot; // i // &quot;]&quot;, frame=i)</code></pre><br>
<br>
but before you ask, tasks in the system like 'BLINK' which may seem appealing are  obsolete and specifically meant for an IIS device (the ancient hardware, not the protocol).  Tasks like 'xpaset' can be declared as foreign for easier use in scripts if that's where you're headed with this.  Hope this helps.<br>
<br>
Cheers,<br>
-Mike
</div>
{% endraw %}

**Mike Fitzpatrick** wrote on May 22, 2006

{% raw %}
<div>
I try to avoid IDL so I can't answer the first part.<br>
<br>
If you have the FITSUTIL package installed you can use the FXHEADER task to list the contents of a MEF.  Since extensions might also be tables then to get the number of images try something like<br>
<br>
cl&gt; fxheader foo.fits | match IMAGE | count<br>
<br>
There is an NEXTEND keyword sometimes produced, but nothing says it is either correct, required to be there, or counts only the number of images and so is unreliable...<br>
<br>
-Mike
</div>
