**Mike Fitzpatrick** wrote on Dec 03, 2006

{% raw %}
<div>
Kelle, <br>
<br>
I think it's the data:<br>
<br>
<pre><code>fitsutil&gt; hselect test_mef[0] OBJECT yes
U20179
fitsutil&gt; hselect test_mef[SCI] OBJECT yes
2
</code></pre><br>
<br>
So there is already an OBJECT keyword in the SCI extension with a value '2', the IMCOPY is just preserving this.  You can use HEDIT to delete the keyword from the extension, then the IMCOPY will work as expected.  How this value got into the data might be a question for the Gemini helpdesk.<br>
<br>
BTW, I consider V2.13-beta2 to be the latest version.  Despite the 'beta' label it is pretty stable, the 'final' release is waiting on new features.  Hope this helps.<br>
<br>
Cheers,<br>
-Mike
</div>
