# Defining a foreign task in the pkgname.cl file.

**Ed Anderson** wrote on Jul 25, 2006

{% raw %}
<div>
Mike (or anyone),<br>
<br>
I'm have a standalone fortran program that is part of a local external package.<br>
<br>
Previously, I would define the task in my loginuser.cl file as:<br>
<br>
    task $taskname = $/path-to-executable/executable-name<br>
<br>
Inside the packagename.cl file I have:<br>
<br>
cl &lt; "y4kcam$lib/zzsetenv.def"<br>
package y4kcam, bin=y4kbin$<br>
<br>
task $taskname = $executable-name<br>
<br>
The result of trying to run the task is:   "command not found"<br>
<br>
If I put:<br>
<br>
   task $taskname = $y4kbin$executable-name<br>
<br>
then I get:  command not defined<br>
<br>
What is the proper syntax for doing this?<br>
<br>
thanks,<br>
<br>

**Mike Fitzpatrick** wrote on Jul 25, 2006

<div>
Hi Ed,<br>
<br>
Interesting question.  In most cases one can get away with simply declaring the task to be "$foreign", but this assumes the unix PATH would find the executable (which is why you get the 'command not found' message).  I presume you've got a host command in a package bin directory and want to resolve the path as part of the package loading regardless of the host path?  In that case you need to convolve the task declaration as something like (assuming a 'Hello World' task in the IRAF bin directory)<br>
<br>
<pre><code>
printf (&quot;task $hello = $%s ; keep\n&quot;, osfn(&quot;bin$hello&quot;)) | cl()
</code></pre><br>
<br>
This formats the task statement by resolving the path with osfn(); the 'keep' preserves the declaration in the CL context, and the result is piped to a CL interpreter for processing.  A similar trick is used to append e.g. the helpdb string where a simple string concatenation would exceed the CL string length limit. <br>
<br>
I haven't actually tried this in a package loading script, but don't forsee some reason why it wouldn't work there as well.  You could do something similar by creating the path string and using a redirected cl command but while obscure, this is more compact.  Let me know if it doesn't work.<br>
<br>
Cheers,<br>
-Mike
</div>

Anyway, I stumbled on the answer ... or one that seems to work.<br>
<br>
In the packagename.cl file  (y4kcam.cl  in this case):<br>
<br>
*******************************<br>
<br>
package y4kcam, bin=y4kbin<br>
$task    $pickbig        = "y4kbin$$pickbig"<br>
<br>
                                        ^^^^^^<br>
 <br>
    Two "$" ... the first dereferences the environment variable (the path<br>
to the executable), the second is the "foreign" definition.<br>
<br>
*********************************************<br>
<br>
The faculty member claims that things are working ok now.<br>
<br>
-- Ed
