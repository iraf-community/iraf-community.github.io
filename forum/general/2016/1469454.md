14.6   How can I change the background color in my ximtool window - the default<br>
<br>

<br>
   The image display window in XImtool is nothing more than a GTerm widget<br>
<br>
so the trick is to simply change the background and foreground colors.  A<br>
<br>
"reverse video" option may be included in a later release to simplify this,<br>
<br>

<br>

<br>
        XImtool*imagewin.color0: white<br>
<br>
        XImtool*imagewin.color1: black<br>

<br>
    % ximtool -xrm "*imagewin.color0:white" -xrm "*imagewin.color1: black"<br>
<br>
[NOTE for SAOtng Users:  resource settings for SAOtng should be specified<br>
<br>
as e.g. "*color0" instead of "*imagewin.color0" due to small differences<br>
<br>
in the code.]<br>

<div>
<br>
                Sorry, wrong question, the point is:  the color0 and color1 resources define the background/foreground colors.<br>
<br>
14.1   How do I change colors (cursor, background, text, etc) in my XGterm <br>
<br>
       window?<br>
<br>
    The crosshair cursor color is set by the "crosshairCursorColor" X<br>
<br>
resource, you would reset it by defining e.g.<br>
<br>
    *Gterm.crosshairCursorColor:   cyan<br>
<br>
in your .Xdefaults file.  The background and text colors are set using a <br>
<br>
combination of X resources to set the predefined colors and an iraf environ-<br>
<br>
ment variable to say which colors are used for text, background, axis labels,<br>
<br>
etc.  The color resources are named 'color0' through 'color9', colors zero<br>
<br>
and one are the background and foreground colors respectively and defaults<br>
<br>
to white on black.  You set these resources using e.g.<br>
<br>
    *Gterm*color0:                 darkslategrey<br>
<br>
    *Gterm*color1:                 linen<br>
<br>
    *Gterm*color2:                 red<br>
<br>
    *Gterm*color3:                 green<br>
<br>
    *Gterm*color4:                 blue<br>
<br>
    *Gterm*color5:                 cyan<br>
<br>
    *Gterm*color6:                 yellow<br>
<br>
    *Gterm*color7:                 purple<br>
<br>
    *Gterm*color8:                 magenta<br>
<br>
    *Gterm*color9:                 slategray<br>
<br>
The environment variable I mentioned is called 'glbcolor' and is defined in<br>
<br>
V2.10.3 (or after) to be<br>
<br>
        pt=3,fr=9,al=3,tl=6,ax=5,tk=5<br>
<br>
where<br>
<br>
        pt      - plot title<br>
<br>
        fr      - viewport frame (the background around the plotting area)<br>
<br>
        al      - axis labels<br>
<br>
        tl      - tick label<br>
<br>
        ax      - axis<br>
<br>
        tk      - tick<br>
<br>
        gr      - grid between tick marks<br>
<br>
The numbers are the color indices above (i.e. "tk=5" say that the tick marks<br>
<br>
are done in color5 (cyan)).   To make use of xgterm color graphics you<br>
<br>
should have the following set in your login.cl or loginuser.cl file:<br>
<br>
        stty xgterm<br>
<br>
Color graphics is enabled only if you are using V2.10.3BETA or a<br>
<br>
later version of IRAF, but using X resources you can still change <br>
<br>
the background and foreground colors when working with an earlier version<br>
<br>
of IRAF.  Resources for the text window are the same as for xterm.<br>
<br>
</div>
{% endraw %}

**Mike Fitzpatrick** wrote on Sep 14, 2016

{% raw %}
<div>
<br>
                Those resources wouldn't be there by default, you would need to add them and then load them using<br>
<br>
    % xrdb -load ~/.Xdefaults<br>
<br>
before starting a new XGTerm window.  In the unlikely event you have a 'XGterm.ad' file in the same directory these would override the resource settings.  Also note that under OSX the .Xdefaults file is normally called ".Xresources".<br>
<br>
Now the bad news is that setting the resources, or starting with,<br>
<br>
    xgterm -xrm "*Gterm*color0:white" -xrm "*Gterm*color1:black"<br>
<br>
to set the reverse video no longer appears to work under the OSX XQuartz server and I haven't been able to find a workaround.  If you experiment with the resource settings and find a workable solution please post it here.<br>
</div>
{% endraw %}
