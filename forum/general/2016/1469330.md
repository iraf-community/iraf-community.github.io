**Mike Fitzpatrick** wrote on Mar 15, 2016

{% raw %}
<div>
<br>
                The problem happens because in the 64-bit v2.15 port the size of the WCS graphics structure was changed, and a corresponding change was required in pyraf (which is responsible for the graphics the same way the CL is).  This bug was fixed in pyraf but apparently only for the 32-bit version.   Since support for pyraf is being dropped it is unlikely that STScI will address this in a future release, but since this bug affects relatively few tasks you can workaround it by simply using 32-bit binaries for the IRAF tasks.<br>
<br>
You can download the binary from: <br>
<br>
       ftp://iraf.noao.edu/iraf/v216/support/linux/x_daophot.e<br>
<br>
Just download in binary mode, make sure it's executable and install in your iraf$noao/bin.linux64 directory.  If you're already using a 32-bit crippled distribution like Ureka then the bug may have crept back into pyraf in a recent release, you can reach the STScI Help Desk by writing help@stsci.edu to see if they have another workaround.<br>
<br>
</div>
