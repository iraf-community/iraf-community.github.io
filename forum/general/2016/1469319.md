**Mike Fitzpatrick** wrote on Mar 01, 2016

{% raw %}
<div>
<br>
<br>
The SIMULATOR task appears to be compiled into the UCSCLRIS binary, but isn't normally declared as a task in the package.  Apparently you figured out how to do this yourself or was the task already declared as part of some version of the package you installed (i.e. did you do a "make ucsclris" to install the package or get a version some other way)?<br>
<br>
Since the task hasn't been modified since 2001 it is likely this is a 64-bit problem if it's not some more mundane coding bug.  If so, you could try installing the 32-bit 'macosx' architecture version and use that binary instead.  For example,<br>
<br>
<pre><code>
    % cd $iraf/extern
    % setenv IRAFARCH macosx                    # or 'export IRAFARCH=macosx' on Bash shells
    % make ucsclris                                         # force reinstall of package
    % /bin/rm -rf ucsclris/bin.macintel              # remove 64-bit binary
 </code></pre><br>
<br>
Even on a 64-bit system IRAF will be able to use older 32-bit binaries.<br>
<br>
If the problem continues then it may be because this is a graphics task and the CL (which provides the graphics kernel) is unhappy about something.  You can get 32-bit versions of the CL binaries from ftp://iraf.noao.edu/iraf/v216/support/macosx you can install in your iraf$bin.macintel directory to see if this fixes the problem.<br>
<br>
Ultimately the package will need to be ported to 64-bits, however it was developed by an outside author so didn't receive much testing (esp. the undeclared simulator task!).   Hope this helps.<br>
</div>
{% endraw %}
