**Mike Fitzpatrick** wrote on Sep 16, 2014

{% raw %}
<div>
<br>
                There are two issues here:<br>
<br>
For compressed images like this (i.e. with a ".fits.fz" extension) you need to be sure that the FITS kernel is used by adding the "fz" to the list of filename extensions given in the 'imextn' variable.  This can be set in your login.cl file, the systemwide hlib$zzsetenv.def, or on the commandline with:<br>
<br>
<pre><code>
cl&gt; reset imextn = "oif:imh fxf:fits,fit,fts,fz plf:pl qpf:qp stf:hhh,??h"
 </code></pre><br>
<br>
where the 'fz' is added to the 'fxf' kernel type.<br>
<br>
Secondly, IRAF doesn't operate directly on FITS compressed data so you can't e.g. run DISPLAY on a specific extension or MSCDISPLAY on the entire file, you need to run the FUNPACK task (either from the FITSUTIL external package, or the unix binary available as part of CFITSIO) first.  It is however possible to run IMHEADER on the primary header, and THEADER on the other extensions (because as compressed imaged they're stored as binary tables) so long as you specify the extension explicitly, e.g.<br>
<br>
<pre><code>
cl&gt; imheader FaTestDECamNoAccess.fits.fz[0]
 </code></pre><br>
<br>
</div>
{% endraw %}
