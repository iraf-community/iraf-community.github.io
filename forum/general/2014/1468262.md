**Ole Streicher** wrote on May 22, 2014

{% raw %}
<div>
<br>
                Hey, it is you who distributes the code (or AURA, or NOAO, if you like). You should know which licenses apply and how to put the bits and pieces together to follow all the rules.<br>
<br>
And the rules in question are quite simple here:<br>
<br>
1. If you use GPL code, specifically if you link to it, your code must be GPL as well. If you don't like that, or if you cannotfullfill this, then you cannot use GPL code. You cannot use SLALIB, you cannot use Readline in this case.<br>
<br>
I would anyway recommend to use <a href="https://github.com/liberfa/erfa">ERFA</a> instead of slalib since it provides the same functionality but is BSD-licensed and is actually maintained (leap seconds and so on).<br>
<br>
For Readline, you probably have no choice (except writing your own command line editing library). Even if you link to the one provided by the system, the resulting software has to be licensed under GPL (there is a lengthy discussion about that, and be prepared to fight with the GNU foundation if this is ignored).<br>
<br>
This applies to the source code as well as to the binaries -- if you offer binaries that use GPL code, you are required to offer the full source code as well (under GPL).<br>
<br>
2. If you distribute some code, you should be allowed to do so, specifically under the license you choose resp. that you are required to use. So, if you distribute NR code (and you must do this under GPL as just stated), then you should be allowed to do so. It is your responsibility to check this.<br>
<br>
Ofcourse, this all also applies to the parts of the code where you don't provide binaries: class and jar files for the VO stuff. I didn't check that yet, you however must make sure that it is distributable under GPL. And this all applies to all the dependent packages as well: if you put IRAF under GPL, and they are built on top of it (link to it or so), then they must be GPL as well, and ofcourse provide all source code.<br>
<br>
I would also question that you are allowed to distribute NR (or derived) source code as part of the sources of IRAF. The <a href="http://www.nr.com/licenses/redistribute.html">NR QA</a> states clearly:<br>
<br>
<blockquote><ul><li><em>[...]</em> Can you include Numerical Recipes routines as part of that source code, including a notice that they are only allowed to be used with your application?<ul><li> Sorry, no. We never give permission for Numerical Recipes source code to be posted on any public server, or distributed with any freeware or shareware package <em>[...]</em></li></ul><br>
<br>
</li><li>You want to translate some (or all) the Numerical Recipes routines to a different computer language, and then redistribute the resulting translations.<ul><li><em>[...]</em> However, you can't redistribute the translations in any manner, since they are "derivative works" and still subject to our copyright.</li></ul></li></ul></blockquote><br>
<br>
This sounds so clear to me that you should really explicitely state that putting the code into the public IRAF distribution is legal and still covered by the permission you got 25 years ago.<br>
<br>
To summarize (and to answer your question): Yes, I think that it is <strong>not legal for you</strong> to distribute sources or binaries of IRAF in the current form, since you seem to be not able to provide the full sources under GPL, which you would be required to.<br>
<br>
If you ask what I want: I want to get IRAF into Debian, and for this I am going through the code and also through the legal issues. I am bound here to the <a href="https://www.debian.org/social_contract#guidelines">Debian Free Software Guidelines</a>. This is not specific to IRAF, we discussed similar things f.e. for Starlink packages (AST) which at the end converted from SLALIB to erfa.<br>
<br>
However, specifically the issue with the Numerical Recipes is quite common among astronomical software packages. Since the problem is so common, it may be worth to start some common effort, either to create a clean-room implementation of them, or to use existing libraries (like the GNU Scientific library) instead. You should just get in contact with the other major software players in our area  <br>
</div>
