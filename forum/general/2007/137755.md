<div>
Depends how rigorous you want to be:  The STARFIND or DAOFIND tasks can be used to create lists of stellar detections within images and will provide either an HWHM or FWHM value in an ascii table.  The FIELDS task can the extract that particular column and the AVERAGE task in the LISTS package will compute a value for you.  Should be an easy enough thing to script to plow through a night's worth of data and print a single value as a result, but note this isn't the same as estimating the seeing throughout the night.<br>
<br>
Cheers,<br>
-Mike

<div>
<blockquote><br>
1) Is it possible to use the imexam method I tried?<br>
2) Is it statistically sound?<br>

<br>
1) Sure.  If you don't want to do it all by hand then you can create a cursor file to drive the task automatically, i.e. create a command-input file to do the 'a' at the various positions automatically.  Note however that STARFIND will produce a value you can use more easily, and that most of the functions in imexam are based on other tasks available elsewhere in the system.  See "help cursors" for details on cursor files.<br>
<br>
2) Computing an average of a list of numbers is very sound.  Whether your interpretation of those numbers in what you're trying to do is statistically sound - I don't know.<br>
<br>
3) I'd do it by hand first, then write it up as a procedure script to automate it for the next time.  See the 'Script Programmer's Guide' in the docs page.<br>
<br>
4) A very crude way is to multiply your FWHM by the plate scale.  More rigorous solutions would take into account the bandpass, airmass, bin it into time slices, etc.<br>
<br>
5) Use either the int() intrinsic function or scan it to a variable, e.g.<br>
<br>
<pre><code>s1 = &quot;4&quot;
i = int(s1)                 # ... or
print (s1) | scan (i) </code></pre><br>
<br>
Cheers,<br>
