Use the FIELDS task to extract only columns you need, i.e.<br>
<br>
<pre><code>cl&gt; fields myfile.in &quot;1,2,4&quot; &gt; myfile.out</code></pre><br>

**Mike Fitzpatrick** wrote on Jun 22, 2007

<div>
I'm not quite sure I understand exactly what you're doing but maybe the following will help.  First, TCALC can't use strings within an expression so you can't really trigger off of that column directly, although I'm not sure what you gain by having the cursor file in a table anyway.  Normally what you would do is process the cursor file by either passing it in to a task 'cursor' parameter so you can run the task in batch mode, or process it as a list (e.g. the commands you typed mean something to you but wouldn't to another task).  <br>
<br>
For example,<br>
<br>
<pre><code>
rimcur (&gt; &quot;cur.txt&quot;)             # create cursor file
list = &quot;cur.txt&quot;
while (fscan (list, x, y, z, s1) != EOF) {   # read the list
    if (s1 == &quot;a&quot;) {
         ....do something
    } else if (s1 == &quot;4&quot;) {
         ....do something else
    } 
         ....and so on
}
</code></pre><br>
<br>
Here you use the built-in CL x/y/z parameters to read the position an WCS, and store the command in the 's1' string.  Does this help?<br>
<br>
Cheers,<br>
-Mike
