**Mike Fitzpatrick** wrote on Jul 11, 2007

{% raw %}
<div>
Sean,<br>
<br>
I can't fully explain your data, but I don't think there's a problem in the task.  I noticed a few things:  <br>
<br>
- The 'L' shapes in your maskedflat.fits file appears to be the result of a shift between the mask and the input file and not a case of bad interpolation.  There's no header information in the files so I can't say how that might have happened.<br>
<br>
- Your badpixelmask.fits file appears to be mostly values of 1 or 200 -- the task can take a standard image as a mask file but assumes "good" pixels are flagged with a zero value<br>
<br>
- By subtracting 1 from the mask file I was able to run FIXPIX with that new mask either as a FITS image, an IMH, or a pixel-list .pl file with no 'L' shape in the final file.  In my result there is also a 1 pixel on all but the left side of the image,  in your maskedflat.fits file the "border" is several pixels wide on the left side.<br>
<br>
Are you sure there's not something funny going on in the mask creation task?<br>
<br>
Cheers,<br>
-Mike
</div>
{% endraw %}
