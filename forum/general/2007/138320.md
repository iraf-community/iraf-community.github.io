# Problem with dir and files commands on nfs device

**BruceT** wrote on Oct 12, 2007

{% raw %}
<div>
We have a Solaris installation of IRAF and we have a Mac OSX server sharing an nfs mount.  This mount is attached to the sun workstation at the root level of the directory structure as /data3.  When we try to run some of our data reduction packages on groups of files using wildcard file specifiers nothing happens.  <br>
<br>
I have traced down the problem to what appears to be an iraf bug.  Neither the "dir" or the "files" command works properly on the nsf share. If I navigate to a data directory on the nfs share I can list the files using the ls command.  If I try to use the dir or dir * command I get a "no files found" response and the "files" command returns nothing.  If I enter "dir test.fits" and test.fits exists it will list back test.fits, the same thing happens with the "files" command.  The result is that we are able to run out data reduction commands on one file at a time but if we try to process an entire directory nothing happens.<br>
<br>
We are running version 2.12 for SunOS 4 and Solaris 2.8
</div>
{% endraw %}

**Mike Fitzpatrick** wrote on Oct 12, 2007

{% raw %}
<div>
It should just need to be an option you put in the e.g. /etc/auto_&lt;host&gt; file.  For instance<br>
<br>
<pre><code>home           -rw,intr,soft,nfsvers=2   radix:/home</code></pre><br>
<br>
to mount /home from machine 'radix' using v2 NFS.  The exact filename will depend on how you've setup your automount files.<br>
<br>
-Mike
</div>

<div>
It's been a while since I did this:  Does the disk show up in the /etc/vfstab as having the nfsvers=2 option?  The example I gave may have been linux-specific as it appears the Sun uses an option like "-o vers=2" for the mount_nfs command.  You could try manually mounting it with something like<br>
<br>
<pre><code>mount -F nfs -o rw,vers=2 saturn:/data3 /data3</code></pre><br>
<br>
Note I'm suggestion vers=2 because of the older SunOS version, it might be that Solaris8 does support vers=3.  I don't remember having to do anything special to have the disk exported from the Mac properly.  In the end, Google may be more reliable than my memory...<br>
