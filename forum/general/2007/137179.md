# options for default editor

**Chad Bender** wrote on Apr 11, 2007

{% raw %}
<div>
I am running IRAF 2.12.2a under RHEL5, and have emacs set as the default editor.  I would like to add a command line option to the emacs call so that the top level frame opens  with a width of 82 (or more) instead of the default 80 characters, without actually modifying my .emacs file (I'd like normal emacs behaviour outside of IRAF).  This would avoid line wrapping when editing fits headers and would save me from manually resizing the window each time.<br>
<br>
At a csh/tcsh prompt this is easily done with &gt;emacs -g 82<br>
<br>
IRAF doesn't seem to be able to understand that.  If I do the following:<br>
set editor="emacs -g 82"<br>
then I get:<br>
cannot find edcap file for `emacs -g 82'<br>
<br>
I also tried aliasing "clemacs" to "emacs -g 80" and setting the default editor to "clemacs", but that didn't work either.  <br>
<br>
The only 'edcap' file I have is /iraf/iraf/pkg/cl/edcap.c, which suggests to me that the problem is compiled into the cl.  Is there a way to include normal command line options like this in IRAF?<br>
<br>
Thanks<br>
Chad Bender<br>
<br>
N.B. I would just run vi, but was having trouble with the whole delete/backspace thing under xgterm, and for some reason using emacs as the editor fixed that.
</div>
{% endraw %}

**Mike Fitzpatrick** wrote on Apr 11, 2007

{% raw %}
<div>
Chad,<br>
<br>
There's no way to include the flag in the editor definition, however you can simply include as part of the command in IRAF, e.g.<br>
<br>
<pre><code>cl&gt;  edit -g 82 myfile</code></pre><br>
<br>
Alternatively, the 'emacs' command is declared by default in your login.cl so using the 'emacs' command should work as well.<br>
<br>
As for the BS/DEL problems, the ECL is an enhanced version of the CL that fixes this and adds arrow-history manipulation as well.  This is the default in the v2.13 releases from this site, or see the iraf.noao.edu web page for details.<br>
<br>
Cheers,<br>
-Mike
</div>
{% endraw %}

<div>
Ugly, but try enclosing the '-g 82' in quotes so it's seen as one argument.  Because it's a builtin task you can't redeclare it, but you could write a myedit.cl procedure script to hide the flag, e.g.<br>
<br>
<pre><code>
procedure myedit (fname)
file  fname
begin
    edit(&quot;-g 82&quot;, fname)
end
</code></pre><br>
<br>
-Mike
