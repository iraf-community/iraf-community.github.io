**Mike Fitzpatrick** wrote on Feb 09, 2007

<div>
So long as all of the output is redirected this shouldn't be a problem normally.  I'm assuming you're talking here about things like procedure scripts.  One possible problem might be with a script that uses foreign commands:  These are executed in a spawned shell and if your .cshrc file does something which expects a terminal (e.g. an 'stty' or 'tset' command belonging in our .login file) the script may die.  Graphics from tasks can be redirected to a file using the "&gt;G" convention or with a task 'device' parameter to save the metacode if needed, graphics input would require a cursor command file.<br>
<br>
-Mike
</div>

**Mike Fitzpatrick** wrote on Feb 09, 2007

{% raw %}
<div>
Be sure to turn off the 'verify' package param in DAOPHOT to suppress the prompts, after that something like<br>
<br>
<pre><code> da&gt; allstar dev$ypix default default default default default &gt;&amp; out.txt &amp; </code></pre><br>
<br>
should run it in the background and you can log out.  If you have a number of images, the a file of those commands (without the final '&amp;') can be run as "cl &lt; cmds &gt;&amp; cmd.out &amp;" and should process each command in turn.<br>
<br>
-Mike
</div>
{% endraw %}

**Mike Fitzpatrick** wrote on Feb 09, 2007

{% raw %}
<div>
Using just the script you sent:<br>
<br>
<pre><code>
apphot&gt; cd /tmp
apphot&gt; vi doit.cl
   ....and I cut-n-paste your code....
apphot&gt; task $doit = doit.cl
apphot&gt; doit
111111 
apphot&gt; doit &gt;&amp; out
apphot&gt; doit &gt;&amp; out &amp;
[1]
apphot&gt; 
[1] done  0.0 0:00 0%
</code></pre><br>
<br>
Check your 'uparm' directory, I'm wondering whether there's an old background file in there (i.e. beginning w/ 'bkg', just delete it).<br>
