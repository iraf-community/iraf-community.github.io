<div>
There's not a lot of information to go on, but I have two guesses:<br>
<br>
Suse 10 uses the Linux 2.6 kernel and *if* you get a similar segfault from any task then you may be seeing a "stacksize" error caused by a change in the memory management under 2.6.  This is fixed by issuing either of the commands:<br>
<br>
<pre><code>% limit stacksize unlimited           # for C-shell
% ulimit -s unlimited                 # for Bash</code></pre><br>
<br>
I'd suggest putting these in your .cshrc file if you don't type them in the commandline before logging in.  Note the 'cl' command is a C-shell script and so to make this permanent you'll need to put it in a .cshrc file regardless of what shell you use.<br>
<br>
The second guess has to do with the mixed use of image types, e.g. your input images are FITS but your imtype is 'imh' and there is some problem with creating imh temp images on your system (e.g. an invalid 'imdir' , permission problems in the directory, etc).  In this case doing a <br>
<br>
<pre><code>cl&gt; reset imtype = fits
cl&gt; flpr 0                       # zero not oh
</code></pre><br>
<br>
usually helps since it forces the temp images to be done as FITS as well.  You can make this change permanent by editing your login.cl file.<br>
<br>
Otherwise we'd need more information such as sample data and the parameters you used.  Hope this helps.<br>
<br>
Cheers,<br>
-Mike
</div>
