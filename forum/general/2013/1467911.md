<div>
<br>
<br>
The update script doesn't appear to be re-editing the default iraf path with the local iraf path once it updates the utility scripts, at least in the case of the setup scripts.  Try explicityly setting a $iraf before the 'make latest' to avoid using the default iraf path, e.g.<br>
<br>
    setenv iraf /opt/iraf/     (for C-shell)<br>
<br>
    export iraf=/opt/iraf/<br>
<br>
Note the trailing '/' is required.<br>

**Nicola Caon** wrote on Mar 17, 2014

{% raw %}
<div>
<br>
                I'm trying to install IRAF 2.16.1 and am experiencing the same problem reported by the OP. This happens to me when installing the external packages (I did not run the general install script though, as we have a multi-version installation here and we create symlinks, change paths etc. by hand to be safe).<br>
<br>
I think the problem originates from the file setup.sh, in particular the lines shown below.<br>
<br>
<pre><code>
# Allow a previously defined $iraf to be used.
if [ -n $iraf ]; then
    export iraf=/iraf/iraf/
fi
 </code></pre><br>
<br>
Since "-n" means true if the length of the string is non-zero, the test will overwrite any previous definition of iraf. Shouldn't the test be negated, that is:<br>
<br>
<pre><code>
# Allow a previously defined $iraf to be used.
if [ ! -n $iraf ]; then
    export iraf=/iraf/iraf/
fi
 </code></pre><br>
<br>
I'll try to do this small change in the script and check whether installing external packages works out.<br>
<br>
Thanks<br>
<br>
Nicola<br>
