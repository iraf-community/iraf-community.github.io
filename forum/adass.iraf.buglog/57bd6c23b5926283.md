# buglog.453: module = scopy, author = valdes

**Frank Valdes** wrote on Dec 14, 1999

<pre style="background: transparent; box-shadow: none; border: none;">
NUMBER:	453
MODULE:	scopy
SYSTEM:	V2.11-V2.11.3
DATE:	Tue Dec 14 11:48:12 MST 1999
FROM:	valdes

BUG:	When copying out a region of a spectrum which is log-linear sampled
	(DC-FLAG=1) the coordinate system of the copied region is wrong.
	This applies whether or not the &quot;rebin&quot; parameter is set.  The
	workaround is to use DISPCOR; set &quot;w1&quot; and &quot;w2&quot; to the desired
	limits and set &quot;log=yes&quot;.  This will do the same thing as
	SCOPY with &quot;rebin=yes&quot;.  To extract a region without rebinning
	the simplest thing is to use an image section.  The pixel limits
	corresponding to the desired wavelength range will have to be
	determined in some way such as with SPLOT, LISTPIX, or calculated
	from the CRVAL/CDELT keywords (these are in log units for log-linear
	sampled spectra.

STATUS:	Fixed for the next release.
</pre>

Q:  I was using right now &#x27;scopy&#x27; to extract a set of apertures (lines)
from a long-slit spectrum, which is log-linear sampled, without
rebinning and copying the whole range.  May you specify in more detail
in which consist the bug, please? Which are the consequences?

Is it only that  WAT0_001= &#x27;system=world&#x27; changes to  WAT0_001=
&#x27;system=equispec&#x27; ?  If it&#x27;s the case, is enough with changing this
keyword in the new 1D image with &#x27;hedit&#x27; after using &#x27;scopy&#x27;?

If nothing is wrong with that change, is it still possible to correct
the error in the coordinate system after using &#x27;scopy&#x27;?

I prefer &#x27;scopy&#x27; to simply extract lines from long-slit spectra because
this task maybe creates a more adequate image header, eliminating the
spatial dimension in the header. But I don&#x27;t know, maybe that is not a
problem for any other task.  So, in this case, it&#x27;s OK to just &#x27;imcopy&#x27;
the line instead of using &#x27;scopy&#x27; ?



A: When w1=w2=INDEF then there is no problem.  The change of the WAT keywords
is not an error.  Technically your input is a 2D spectral image; i.e
a long slit image.  SCOPY &quot;extracts&quot; one or more lines (depending on
the package &quot;nsum&quot; parameter) into a 1D spectrum.  The &quot;equispec&quot;
word tells the software that it is dealing with a particular type
of 1D spectrum file, one where all the lines of the image have the
same dispersion system.  So there is no need to do anything about
the change of keywords.  If you are thinking of SCOPY as an easy way to
extract 1D spectra from longslit rectified images (as opposed to the
more complex APEXTRACT tasks) then you are right.  This is preferable
to using IMCOPY though the IMCOPY files would still be valid spectra.

The bug does not affect the data, it is correctly extracted and copied.
The error is simply that the CRVAL/CD/CDELT keywords are not updated
correctly for the subregion extracted.
