# Changes to cnvdate, cnvtime

**Doug Tody** wrote on Sep 29, 1998

<pre style="background: transparent; box-shadow: none; border: none;">
The system routine cnvtime (in etc$), used to convert a long integer time
value to a string, had to be modified slightly due to a Y2K code change.
The new date-time string is now 2 characters longer and looks like

    Tue 13:26:24 29-Sep-1998

whereas the date was given as &quot;98&quot; before.

The calling sequence has not changed, but the output string is longer than
before.  The length of this string is given by SZ_TIME in &lt;time.h&gt;.
Existing code which calls cnvtime could truncate the time string unless
it is recompiled.  Cnvtime uses a &quot;maxch&quot; argument however to limit the
length of the output string, so string overflow should not be a problem.

This is a very minor interface change, and a search of about 22,000 *.[cxh]
files in our external package collection suggests that very little outside
code should be affected (65 or so core/noao IRAF files were affected but
a recompile should fix it).  Indirect effects are possible however.  This
change will affect IRAF V2.11.2 or any development shared library patches.
</pre>
