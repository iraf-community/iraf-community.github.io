This warning has to do with the fact that there is a small bug in the GUI
configuration file for XImtool.  This problem is fixed for the next
release.  If it gets annoying, let us know and we&#x27;ll send you instructions
on how to get rid of it.

: X Error of failed request: BadMatch (invalid parameter attributes)
: Major opcode of failed request: 72 (X_PutImage)
: Serial number of failed request: 3670
: Current serial number in output stream: 3675
: Seems to be same error that others here have gotten but depth is set to
: 8 as I have seen in these other messages and X works fine for other
: functions. I don&#x27;t see any other replies in this forum. Any other
: ideas?

Yes, this is an 8 bpp problem.  Try running &#x27;xdpyinfo&#x27;.  What you&#x27;ll get is a 
long listing of display information for X windows.  Look for the entry marked, 
&quot;default visual id&quot; and then the number after it.  Then match that number to an 
entry marked, &quot;visual id&quot;.  This should be in an entry that provides info like, 
&quot;class&quot;, &quot;depth&quot;, &quot;size of colormap&quot;, etc.  To properly use Ximtool, this entry
should look something like this: 

  visual:
    visual id:    0x20
    class:    PseudoColor
    depth:    8 planes
    size of colormap:    256 entries
    red, green, blue masks:    0x0, 0x0, 0x0
    significant bits in color specification:    8 bits

If it isn&#x27;t, you can change the &#x27;default visual id&#x27; using Xconfigurator.

The critical pieces here are to make sure you&#x27;re running 8-bit
pseudocolor.

Let me know if you have problems with any of this stuff.

Matt Cheselka
NOAO/IRAF

	Since this is a RH6.1 system chances are you&#x27;re using the default
Enlightenment window manager with Gnome.  Enlightenment has a bug which
prevents XImtool from ever gaining the colormap focus which means it
always shows the random colormap and contrast scaling is broken.  Unfor-
tunately the only workaround for this is to use a different window manager
(e.g. Gtk or WindowMaker I think will work) under Gnome or switch to the
KDE Desktop as an alternative. The Gnome config panel should allow you to
choose a different manager, but you may have to install other choices if
you didn&#x27;t install everything by default.
	The &quot;cannot allocate colormap&quot; messages can also sometimes be
blamed on the window manager.  Both Gnome and KDE are big color hogs with
an 8-bit colormap and if Netscape is running it will grab all available
colors.  In general colormap flashing can also be reduced by setting some
ximtool resources, e.g.

        XImtool*basePixel:              128
        XImtool*maxColors:              100
        XImtool*cmapInitialize:         True

This will allocate only 100 colors starting at cell 128 and should help
limit the flashing (ximtool defaults to use ~210 colors).  If you must run
in 8-bit mode note there is also a &quot;-ncols &lt;N&gt;&quot; flag to Netscape to limit
the colors it uses (otherwise it grabs them all), or just shut it down
when using ximtool.
	All the pretty desktop icons come at a price though, if it gets to
be too annoying you can always go back to an &quot;old&quot; window manager such as
FVWM, Motif, etc and solve both problems.
