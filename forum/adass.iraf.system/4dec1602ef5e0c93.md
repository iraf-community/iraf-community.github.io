## IRAF Plots to Image Formats

**Mike Fitzpatrick** wrote on Jun 17, 1998

<pre style="background: transparent; box-shadow: none; border: none;">


&gt; Is there a (comprehensible) way to port GRAPH output to a bitmap, .jpg,
&gt; e.g.?  Now I&#x27;m using a screen-capture utility-surely there is a better
&gt; way.  I&#x27;ve discovered that I can export to .eps but don&#x27;t know of a
&gt; utility which converts this properly-text, especially, seems to suffer
&gt; considerably from the translation.

	The output from iraf graphics is normally some sort of plotter
language (e.g. Postscript), but as long as you&#x27;ve got some way to convert
that to another format it&#x27;s possible to write a graphcap entry to create 
the new format automatically.  For converting Postscript files two poss-
ibilities are the &#x27;gs&#x27; task as part of Ghostview (but you sometimes need
to configure the output formats specially when building it), or the
&#x27;convert&#x27; task in the ImageMagick package (available from most X mirror
sites, e.g. ftp://ftp.x.org/contrib/applications/ImageMagick).  For example,
the following entry creates a device name &#x27;gif-dump&#x27; that create a 640x480
GIF image called &#x27;irafXXX.gif&#x27; in the current directory (where XXX is a 
process id) using the convert program:

gif-dump|UNIX generic interface to GIF file dump:\
        :DD=psdump,tmp$sgk,!{ sgidispatch sgi2uapl -t $F -l$(XO) -w$(XW) \
        -b$(YO) -h$(YW) -p$(PW) &gt; /tmp/irafdmp$$.ps ; \
        convert /tmp/irafdmp$$.ps -geometry 480x640! iraf$$.gif ; \
        rm $F /tmp/irafdmp$$.ps; }&amp;:tc=sgi_apl:

The &#x27;-geometry&#x27; flag fixes the image size, there are other options to this
task you may want to add as well.  The &#x27;-t&#x27; flag to the sgi2uapl translator
is needed to keep the small timestamp from appearing on the page.  To use
this entry you would do the following:

    cl&gt; copy dev$graphcap home$mygraphcap	# make a private graphcap
    cl&gt; edit home$mygraphcap
	....add the above entry to the file
    cl&gt; reset graphcap = home$mygraphca		# declare it
    cl&gt; gflush					# reinitialize

Then use either &quot;:.snap gif-dump&quot; in a cursor mode to make the image, or
something like

	cl&gt; contour dev$pix dev=gif-dump ; gflush

to make it in batch mode, the &#x27;gflush&#x27; is needed to flush the graphics
buffer right away.  If you need help tweaking this to get it to do exactly
what you want let me know,  the actual conversion task you use is up to
you but it will have to be installed separately.
	There&#x27;s no real general way to workaround the text conversion prob-
lem.  It is caused by the fact that the postscript file is written assuming 
a page resolution on order 3300x2500, but you&#x27;re converting this to a smaller
image of say 640x480.  The individual strokes in the character drawing get
lost in the lower resolution and the text quality degrades.  Using the 
&#x27;convert&#x27; task does about as well as any other at this, but it has a
&#x27;-density&#x27; option you can use to increase the resolution but also the size
of the image (the defaults is 72 dpi which corresponds to normal screen
resolution which is why the GIF image looks the same on the screen as when
previewing the postscript file directly, normal page resolution is 300dpi).
	The other drawback to this method is that the SGI translators won&#x27;t
preserve any color info you may see in an XGterm window.  You can use the
STSDAS Postscript kernel and another modification to the graphcap to work
around this but it won&#x27;t help the text presentation.  If what you&#x27;re after
is a nice image of a plot window then using a screen capture tool like
&#x27;snapshot&#x27; on Suns or &#x27;xwd&#x27; elsewhere will preserve the colors and the image
appears as it does on the screen.  The text isn&#x27;t degraded in this case
because the plot is normally drawn using a screen font and not with the
stroke data used for hardcopy in the SGI kernel.
