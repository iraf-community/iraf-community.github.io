	All of the errors cascade from the failure to compile the cor.x
file, which in turn punts on the compilation of later files resulting in
the many unresolved references.  The exact cause is an obscure bug in
the hlib$f77.sh script used to drive the F2C/GCC compilation of SPP source
files.  First there are three workarounds: 

	1) install the redhat binaries for MSCRED V2.0 I&#x27;ve just put in 
	   the archive directory.  
	2) before doing the main package compilations, compile the file 
	   mscred$src/ccdred/src/generic/cor.x by hand using the commands

		% xc -F cor.x		# produce a cor.f file
		% xc -c cor.f		# compile it to a .o file

	3) Edit line 157 of hlib$f77.sh to read

		sed -e &quot;s/$b\\.f/$b.x/&quot; &lt; $b.c &gt; $b.t; mv $b.t $b.c

	   and compile the package normally.  This last option fixes the
	   bug mentioned above.

Analysis:
	In compiling the cor.x file, as with all SPP files, spp variables
are shortened to 6 characters by eliminating the underscores and using the
first five plus the last character to form the final name.  A new set of
procedures called e.g. &#x27;cor1flats&#x27; was added to the file in this version,
the resulting name in the intermediate cor.c file is then &#x27;cor1fs&#x27;.  When
this file is compiled the f77.sh script edits the file to change the
filename as it appears in the program comments (&#x27;cor.f&#x27; in this case), but
the sed script mistakenly uses the &#x27;.&#x27; as a wildcard character.  In this
case the filename &#x27;cor.f&#x27;, with the wildcard, matches the &#x27;cor1fs&#x27;
variable name produced and changes this variable to then be &#x27;cor.fs&#x27; which
is causing the compilation errors.
	This bug is pretty obscure due to the special filename
requirements to trigger it and has only been seen once before.  The f77.sh
script has been fixed for the next release of PC-IRAF.  If you still have
problems let us know.

Mike Fitzpatrick
</pre>
