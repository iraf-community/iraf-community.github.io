## SPP parameter flushing?

**Rob Seaman** wrote on Nov 16, 1998

<pre style="background: transparent; box-shadow: none; border: none;">
Bob Abraham writes:

&gt; I have a question with regard to SPP programming: do SPP tasks always set
&gt; their parameter variables on exit after being called from CL scripts, or
&gt; does one sometimes need to flush a buffer or something in order to update
&gt; the variables correctly?

No such flushing should be needed.  Note, however, that only a very few
tasks rely on writing to their parameter files.  The biggest complication
with this mechanism is that IRAF tasks that are run in the background
are not permitted to actually update their parameter files on output.
The point of this is to avoid collisions with other instances of the
same task running in either the foreground or in other background jobs
and reading and writing the same parameters.

&gt; I find that if I run this interactively from the command line, it works
&gt; fine, but if call my SPP program from a CL script and try to access the
&gt; task&#x27;s parameter variables within the script (eg. with statements like
&gt; total = sum.maskpix after calling sum to analyse the image) then the
&gt; variables are not correctly set. But if I wait until the CL script is
&gt; finished and then examine the hidden parameter variables (ie. by typing:
&gt; =sum.maskpix at the command line), lo and behold the numbers are correct.

You don&#x27;t explicitly mention whether the script is being executed in the
foreground or the background.  (The fact that the parameters appear to be
updated when the script is finished suggests that you are running in the
foreground.)

It isn&#x27;t clear what is happening from the information provided.  I would
first suggest that you take a look at the &quot;cache&quot; and &quot;update&quot; commands.
Most IRAF users seem to be aware of the &quot;unlearn&quot; command, but may not
have encountered &quot;cache&quot;, which arranges for a copy of a task&#x27;s parameters 
to be buffered in a memory cache, or &quot;update&quot; which forces a cached
parameter set to be written to the corresponding disk copy of the
parameter file in the user&#x27;s uparm directory.

The fix for the problem of using a task that writes output values into
its parameters - within a background script - is to include the line
&quot;cache (taskname&gt;&quot; near the top of the script.

On the other hand, if there is some unknown problem with your SPP task
updating its parameter file, perhaps an explicit &quot;update &lt;taskname&gt;&quot;
immediately after running the task may help.

Please contact the IRAF group at iraf@noao.edu if you continue to have
problems and we can arrange a closer look at your program and script.

Rob Seaman
NOAO/IRAF
