## tbplot.pltpar

**Biro Imre Barna** wrote on Oct 12, 2000

<pre style="background: transparent; box-shadow: none; border: none;">

  I am experiencing a  problem while trying to set the &quot;errtype&quot;
parameter in the
&quot;pltpar&quot; pset, controlling the type of error bars to be plotted. The
admitted values are said to be &quot;bartck|bar|tick|limit&quot;. However,
when I try to select &quot;bar&quot;, the task does not accept it, no matter if
enclosed in single or double quotes or none, or given within  &quot;epar&quot;
or as a command-line parameter -- in the latter case, the message
&quot;ambiguous abbreviation &#x27;bar&#x27;&quot; is displayed. 

I guess the above message describes the reason of the failure reasonably
well, suggesting that the task cannot decide between &quot;bartck&quot; and &quot;bar&quot;
when only &quot;bar&quot; is given. Could this be a bug in the TABLES package?

One workaround which I used exploited the capability of &quot;szmark&quot;  to
represent errors, by setting 
  
  szmark=0., 
  mark=&quot;vline&quot; (that is, bar-like errors),
  pointmode=yes, 

and arranging
for the error column values
to be negative, with the absolute values representing the real errors
(input of negative values is needed to draw in WCS units). With this
setup the errors are plotted as vertical lines of correct amplitudes.
However, resolving the ambiguity in &quot;pltpar.errtype&quot; would be the
straightforward solution. Is there any way to do that?

  Thanks.
