# XImtool wcsbox colors

**Mike Fitzpatrick** wrote on Dec 08, 1998

<pre style="background: transparent; box-shadow: none; border: none;">
&gt; Second, is there an Xdefault I can set to change the colour of the text in
&gt; the &quot;coords box&quot; of ximtool, as I can&#x27;t read the co-ordinates at present?

        Well, yes and no.  The resources &#x27;markerTextColor&#x27; and
&#x27;markerTextBgColor&#x27; set the default foreground/background colors for text
markers (which is what the wcsbox is), but since these are set explicitly in
the XImtool GUI file as black/yellow the resources won&#x27;t override it.  To
change them you&#x27;d need to modify the GUI itself and use it instead.  For
example

        % ximtool -defgui &gt; xim.gui             # dump the current GUI
        % vi xim.gui                            # edit the defaults
        ....search for &#x27;textColor&#x27; and
            &#x27;textBgColor&#x27; and change the
            values
        % ximtool -gui xim.gui                  # start up the new GUI

or else add the resource

        XImtool*gui:    /path/xim.gui

to your .Xdefaults so it will use your modified version.

        If you can&#x27;t currently see the colors there may be a conflict with
ximtool not getting enough of the colors it needs, try shutting down
Netscape or XV to see if that clears it up (I&#x27;m assuming this isn&#x27;t
unreadable because of the colormap you&#x27;re using in ximtool but that it&#x27;s
e.g. black on black).  It is possible however to minimize the colormap
flashing when using other applications.  For example setting the resources

        XImtool*cmapInitialize:                 true
        XImtool*basePixel:                      128
        XImtool*maxColors:                      100
        Netscape*maxImageColors:                64

would force ximtool to use only 100 colors starting at cell 128, and limit
Netscape to use only 64 colors.  As long as Netscape is started after ximtool
you usually won&#x27;t see color flashing.

-Mike
</pre>
