	I believe the Creator3D card will work in either 24 or 8-bit 
mode automatically and supports simultaneous multiple-depth visuals.
The default visual depends on how the server is started but you can
always use the &#x27;xdpyinfo&#x27; command to find out what the default visual 
is.  
	For newer cards such as the PGX card on Ultra 5 systems they
claim to support both depths but it needs to be reset at the hardware
level by issuing the command

	# /usr/sbin/m64config -depth 8

as root.  Use &quot;m64config -prompt&quot; to show the current settings.
	One tip which works well is the set the card to use an 8-bit
visual as a default but start applications like Netscape with a
&quot;-visual TrueColor&quot; flag to run in the 24-bit mode and avoid colormap
conflicts with ximtool.  SAOtng can make use of an 8-bit visual if one
is available even if it&#x27;s not the default and it&#x27;s DS9 successor can
work in 24-bit mode (currently as a standalone display program but I
think the IIS protocol is also now working so it can be used as an IRAF
display server).

&gt; is already running) and run ximtool from my normal cde session.  I
&gt; tried the modification of the /usr/dt/config/Xservers, i.e. the original

&gt; However, when I do this I get an error: &#x27;Cannot open console :0&#x27; - I&#x27;m

&gt; have to kill this message to verify it... The upshot is that the cde 
&gt; login screen doesn&#x27;t come up when I make the change to Xservers.

	A reboot would probably fix this but a more elegant solution might
be to use the command

	# /usr/dt/bin/dtconfig -reset

to reset the dtlogin program.  Where I get fuzzy is how/if a .xserverrc file
trumps the server started by dtlogin.  Note that for other systems using
XDM the file to be changed is /usr/X11/lib/xdm/Xservers (or for Sun
/usr/openwin/lib/xdm/Xservers).
	Hope this helps, perhaps somebody else can followup with a more
informed suggestion.
