## CL scripting from Unix (Examples)

**Mike Fitzpatrick** wrote on Mar 07, 2000

<pre style="background: transparent; box-shadow: none; border: none;">
&gt; Any chance of a couple of example scripts ?

	I was afraid somebody was gonna ask this. But since you did...
In all the examples the only deviation I&#x27;ve made from my last reply is
that I&#x27;m assuming that the &quot;arch&quot; variable is set by the user&#x27;s envir-
onment in the .cshrc file.  Doing so along with the use of a generic path
to the CL executable such as &quot;/usr/local/bin/cl.e&quot; means that there is
no platform dependence in the script itself.  All that is required to
re-use the scripts on a different machine is that 1) a link to the CL
binary be created and 2) the user define an &#x27;arch&#x27; variable in their
unix environment.


Example 1:  A host DISPLAY command.
-----------------------------------

	For the first example let&#x27;s write a wrapper script around the
DISPLAY command to allow images to be displayed from the command line.
A simplified version of the script would look something like:

    #!/usr/local/bin/cl.e -f

    reset stdimage = imt1024		# default environment	
    logver = &quot;IRAF V2.11 May 1997&quot;	# needed for IMAGES package

    images				# load needed packages
    tv
	    # Execute the command.
	    printf (&quot;display %s\n&quot;, args) | cl()
    logout				# shut down

Note that we must define a &#x27;stdimage&#x27; if we intend to use something other
than the default imt512.  The setting of &#x27;logver&#x27; is required since we
will be loading the IMAGES package to get to the task.  In order to let
the script execute as fast as possible we don&#x27;t define environment vars we
don&#x27;t strictly need here, e.g. home$, uparm$, etc.
	The task itself is executed by simply creating a command string we
will pipe to a cl() call that executes it.  This allows us to simply pass
all the arguments on the command line to the task.  For example,

	% display dpix.imh 1
	% display dpix.imh 1 zscale-
	% display dpix.imh 1 zs- zr- z1=100 z2=1200
	% display dev\$pix.imh 1

Notice that in the last case when displaying dev$pix it was necessary to
escape the &#x27;$&#x27;, otherwise the entire argument list is passed to the
DISPLAY command as-is, allowing us to retain the CL syntax for setting
parameters.  This is one reason the command is executed using the &quot;command
mode&quot; syntax, using the normal procedure script &quot;program mode&quot; would mean
that each argument would have to be broken out separately in order to
define the parameter.


Example 2: A host IMARITH or IMEXPR command.
---------------------------------------------

	The idea here is roughly the same as above:

    #!/usr/local/bin/cl.e -f

    set imdir = &quot;HDR$pixels/&quot; 		# default environment	
    logver = &quot;IRAF V2.11 May 1997&quot;	# needed for IMAGES package

    images				# load needed packages
    imutil

	    # Execute the command.
	    printf (&quot;imarith %s\n&quot;, args) | cl()
    logout				# shut down

Note that the environment and necessary packages will be different here
so there is a little customization required for each script.  In this case
since we&#x27;ll be creating an output image of some kind we&#x27;ll need to define
an &#x27;imdir&#x27; of some kind.
	Again we pass in the entire command line but with a task like this
we not only need to be careful about escaping the &#x27;$&#x27; of an IRAF logical,
but other special chars such as &#x27;*&#x27;.  For example,

	% imarith dev\$pix \* 10 newimg 

The host csh regards &#x27;*&#x27; as a special char and so it too must be escaped 
so as not to be expanded on the command line.

	The same example could be used as a wrapper for the IMEXPR command
by simply changing the command name from &#x27;imarith&#x27; to &#x27;imexpr&#x27; since the
rest of the script is identical.  The thing to note here however is again
the shell escapes required.  For example, the expression argument to this
task is often put in quotes on the CL command line, and those quotes need
to be passed thru to the script in order for the command to execute
properly.  To do this you would use a command such as

	% imexpr &#x27;&quot;(a &gt; 100 ? 0 : a)&quot;&#x27; newimg a=dev\$pix


Example 3: A host graphics command.
-----------------------------------

	Graphics commands can also be used in #!cl scripts, but note that
in this case we need to set the terminal type so the plot appears correctly.
This can either be some hardwired value or it can set using an envget()
call on the TERM environment variable as is done in the login.cl.  In
this case it may also be desirable to set the &#x27;stdplot&#x27; variable so the
&#x27;=&#x27; or &#x27;:.snap&#x27; hardcopy commands work as needed.  For example, a script
around IMPLOT might look something like:

    #!/iraf/iraf/bin.ssun/cl.e -f

    reset stdplot = &quot;lw8&quot;		# default environment
    stty xgterm				# set the terminal type

    plot				# load needed packages.
	    # Execute the command.
	    printf (&quot;implot %s\n&quot;, args) | cl()
    logout				# shut down


Example 4: A host HELP command.
-------------------------------

	As a last example let&#x27;s see write a #!cl script that parses
the args list to make the command look more like a unix command.  In
this case we&#x27;ll write a wrapper for the HELP command that uses &#x27;-r&#x27; and
&#x27;-p&#x27; command line options to modify the task behavior slightly.

    #!/usr/local/bin/cl.e -f

    set     home    = &quot;/u2/fitz/&quot;	# default environment
    set     uparm   = &quot;home$uparm/&quot;

    stty xgterm				# set terminal type for pager
    lists				# need LISTS for arg parsing

	# Declare local variables.
	string	arglist			# arg values
	string	command = &quot;help&quot;
	string  task			# options

	# Parse unix command-line args.
	arglist = mktemp (&quot;tmp$help&quot;)
	print (args) | words (&quot;STDIN&quot;, &gt; arglist)
	list = arglist
	while (fscan (list, s1) != EOF) {
	    if (s1 == &quot;-r&quot;) {  
		command = &quot;references&quot;
	    } else if (s1 == &quot;-p&quot;) {  
		command = &quot;phelp&quot;
	    } else {
		task = s1
	    }
	    ;				# needed to fix CL grammar quirk
	}
	delete (arglist, ver-)		# clean up
	list = &quot;&quot;
	
	# Finally, execute the requested command on the task.
	printf (&quot;%s %s mode=&#x27;q&#x27;\n&quot;, command, task) | cl()

    logout				# shut down

For this script the default behavior is to simply call the HELP task on
the named argument (i.e. the task).  By setting the &#x27;-p&#x27; flag we can
instead call PHELP in order to page the output, or by using &#x27;-r&#x27; call
REFERENCES to do a subject search for a given keyword.
	In this case we do define a uparm$ local because we might wish to
make use of the quick-reference file normally stored there and used by the
REFERENCES task (and assuming the references.usequick param has been set
in a CL session earlier).  Again we need to define the terminal type
because we may be using the file pager.
	The LISTS.WORDS task is used to break an &#x27;args&#x27; string such as &quot;-p
imexamine&quot; (i.e. we want to run &quot;phelp imexamine&quot;) into a list of
arguments written to a temporary file.  We fscan the file to get each
argument and act accordingly to set the command to be run or the task
name.  Note there is no method here for setting specific parameters that
might be desired such as the help &#x27;option&#x27; or &#x27;section&#x27;,  but they could
be easily added in the same way.
	To use this task it could be called as

	% help -r mask			# to find all &#x27;mask&#x27; tasks
	% help -p imexam		# page help for IMEXAMINE

In this way we can combine several similar tasks into one. 

	The &quot;script body&quot; in these examples are all relatively primitive.
As long as the proper environment is defined and required packages loaded,
the body of the script can declare it own variable or tasks and be written
in much the same way as any other procedure script.  Users should note 
however that the same rules against multiply loading packages in scripts
which call scripts (and lead to &quot;dictionary full&quot; errors) still apply,
to be safe packages can be checked before loading using something like

    	if (!defpac (&quot;images&quot;)) {
       	    images
	}

This example also points out a bug in the CL in which a null &#x27;;&#x27; statement
is required following an if-clause if there is no other valid statement
following the closing brace (see the arg parsing).
	Lastly, if no arguments are passed at all to any of these scripts
the normal parameter prompting will still be in effect, but the escapes
for special characters will not be required.  For example,

	% implot
	image to be plotted: dev$pix


	The earlier posting and these examples, along with revisions to
them, will be made available from our web page.  Feel free to followup with
questions and anyone who develops a handy #!cl script they&#x27;d like to 
distribute should feel free to drop if off in our /contrib directory on
iraf.noao.edu (along with a readme saying what it does) or post it to
adass.iraf.sources.

Cheers,
-Mike

	Excellent question!  The answer lies in the fact that &#x27;at&#x27; and
&#x27;batch&#x27; commands are executed using the Bourne shell.   For your script
you would start an at job on the command line using something like

	% at -f show.cl now + 2 hours

What happens is that the file named by the -f flag, as well as the current
environment (more or less), userid, etc, are written to a file in the
/var/spool/at directory (on linux anyway) which looks something like

	#!/bin/sh
	# atrun uid=359 gid=100
	# mail     fitz 0
	umask 22
	HOSTNAME=zippy.tuc.noao.edu; export HOSTNAME
	LOGNAME=fitz; export LOGNAME
	      :
	      :   [remainder of environment deleted]
	      :
	COLUMNS=80; export COLUMNS
	LINES=60; export LINES
	cd /tmp || {
	         echo &#x27;Execution directory inaccessible&#x27; &gt;&amp;2
	         exit 1
	}
	#!/iraf/iraf/bin.redhat/cl.e -f
	
	set arch=&quot;.redhat&quot;              # or whatever
	set clobber = yes
	show 
	logout

When it comes time for the task to be run this file is executed.  Notice
that the contents of your #!cl script are now in the middle of #!/bin/sh
script, and so the commands in your file are expected to be Bourne shell
commands.  In this case the &#x27;set&#x27; command are recognized but &#x27;show&#x27; is
taken to be the /usr/bin/show command if it&#x27;s recognized at all.  So 
for at/batch commands the #! part of the script is never executed to start
the CL as the interpreter, it&#x27;s simply taken as a comment.  Note that the
same thing happens when using #!/bin/csh scripts in at files.

	To execute a #!cl script in an at/batch command the actual file
you pass to the at command should contain e.g. only the path to the #!cl
script you want to execute (assuming it&#x27;s an executable file).  Lastly, 
there are also problems with your example in having the output not be 
redirected.  This can be worked around by having the file passed to &#x27;at&#x27;
do the redirection, but be sure to use Bourne shell syntax when doing so.

-Mike
