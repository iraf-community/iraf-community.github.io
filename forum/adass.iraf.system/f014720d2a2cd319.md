**Frank Valdes** wrote on Feb 02, 1999

<pre style="background: transparent; box-shadow: none; border: none;">
Hi Rob,

The &quot;String_File&quot; error is generally caused by some other error occuring
in a task which is not properly trapped by the task and then eventually
causing memory corruption errors.  The specific error has to do with 
in memory writing using a psuedofile and so it does not have anything to
do with real file permissions.  The error is coming from one of the
compiled tasks called by ccdproc.cl and not from the script.  The line
number reported when an error occurs in a script is generally not very
useful.  So the answer is I don&#x27;t know what is causing the error or what
it means.  The only way to help is to reproduce the problem on your machine
or here.  The first thing for you to try is to unlearn things and try
again.  It may be that some parameter got set wrong.  If the problem
is very reproducible then I can suggest some debugging output to collect
which might shed some light on the matter.  Let me know how things stand
and if you need help getting this resolved and I&#x27;ll give you list of some
things to send.

Cheers,
Frank Valdes
</pre>

Erg.  I figured out the problem; it&#x27;s the classic &quot;filename length too

domeflat.  When I put the flat in the current directory (really, a symbolic
link), the problem went away.  The error was bizarre, and didn&#x27;t suggest
a too long filename... but I should have realized that that was one of the
things to check first.
