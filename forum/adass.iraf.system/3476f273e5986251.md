## Using "showcap" to debug tapecap entries

**Doug Tody** wrote on Dec 10, 1999

<pre style="background: transparent; box-shadow: none; border: none;">
As Tony Ferro points out below there is a bug affecting Exabyte support
in the tapecap.linux file in PC-IRAF which I am passing on in case it
saves someone else from having to debug this as well.  This also shows
how to use the showcap task to debug any *cap file.  (The task certainly
could be made more convenient to use on arbitrary *cap files, but even so
this is easy enough).

----
Hi Tony,

&gt;   I finally tracked down a typo in your dev$tapecap.linux file in the
&gt;   RedHat PCIX distribution.  The &quot;mtexb?&quot; entries end in &quot;tc=generic-exabyte&quot;
&gt;   instead of &quot;tc=generic-exb&quot; which is the actual entry lower on.  With
&gt;   this change the drive is at least recognized.

This has been fixed in the master system, thanks.
 
&gt;   Is there any utility similar to the showcap program for graphcap which
&gt;   will display the &quot;expanded&quot; tapecap entry?  That would have helped debug
&gt;   this problem.

It isn&#x27;t very apparent but showcap is in fact what you use for all the &quot;cap&quot;
files.  For example in the current case I just did this and here is what
it looks like:

    cl&gt; set graphcap = dev$tapecap.linux
    cl&gt; 
    cl&gt; showcap
    cmd :  `set&#x27; device
	|  `*&#x27; (to dump full graphcap entry
	|  cc [arg1 [arg2 [arg3]]]
	;

    cc  :   a two chararacter capcode (e.g., &#x27;cm&#x27;)
	|   an encoder program (non alpha first char)
	;

    * set mtexb0
    :al=st0 nst0:dv=nst0:lk=st0:dt=Exabyte EXB-8200 8mm tape drive:\
    tt=P6-120MP:ts#2347794:bs#0:mr#32768:or#32768:fb#10:rs#2000:fs#188416:\
    mf:

An extra &quot;cl&quot; before the above, followed by a &quot;bye&quot; when done, would
remove the temporary redefinition of graphcap.

	- Doug
