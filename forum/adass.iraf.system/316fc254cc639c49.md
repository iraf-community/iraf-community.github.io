## RedHat Linux and C IMFORT programs

**Mike Fitzpatrick** wrote on Sep 29, 1999

<pre style="background: transparent; box-shadow: none; border: none;">
&gt;         I have just successfully installed IRAF V2.11 on my RedHat 6.0
&gt; system. Everything works fine, except that I&#x27;m having trouble
&gt; compiling and linking to IRAF a .c code I&#x27;ve written, which uses the
&gt; IMFORT library. I&#x27;ve gotten this code to compile, link, and run on a
&gt; previous version of IRAF on a SPARC20, and I have the c bindings.
&gt;         When I try to make this code using fc.csh, I get the following
&gt; messages:
&gt; 
&gt; ---------------------
&gt; /usr/local/iraf/iraf/unix/hlib/fc.csh -c -h -O  multifit2.c
&gt; /usr/local/iraf/iraf/unix/hlib/fc.csh -h multifit2.o  -limfort -lsys
&gt; -lvops -los -lm -o multifit2.e
&gt; /iraf/iraf/unix/bin.redhat/libf2c.a(main.o): In function `main&#x27;:
&gt; main.o(.text+0x78): multiple definition of `main&#x27;
&gt; multifit2.o(.text+0xed4): first defined here
&gt; /usr/bin/ld: Warning: size of symbol `main&#x27; changed from 2391 to 159 in main.o
&gt; /iraf/iraf/unix/bin.redhat/libf2c.a(main.o): In function `main&#x27;:
&gt; main.o(.text+0x10c): undefined reference to `MAIN__&#x27;
&gt; collect2: ld returned 1 exit status
&gt; make: *** [multifit2] Error 2

	The problem is caused by use of the clarg() imfort procedures for
getting command line arguments.  When this procedure is used it causes the
linker to load the zgcmdl() procedure which in turn requires an &#x27;xargv&#x27;
symbol found in the libf2c main.o object file.  main.o obviously also
contains a &#x27;main&#x27; symbol which clashes with the one in your program, it
also then requires the &quot;MAIN__&quot; symbol which is taken to be the start of
the fortran code.  From there the whole thing falls apart as you&#x27;ve seen.
This is not a problem when compiling Fortran imfort programs because a
fortran &#x27;program&#x27; statement is translated by F2C into the &quot;MAIN__&quot; symbol
and the only &#x27;main&#x27; symbol required comes from the libf2c.a itself.

        For C imfort programs the best workaround I was able to find was to
simply avoid using the clarg procedures and deal with the arguments using
the standard argc/argv variables.   I would have to experiment some more
to find a different way to link the program or rewrite the f2c main() but
I don&#x27;t think these would be as reliable.

-Mike
</pre>
