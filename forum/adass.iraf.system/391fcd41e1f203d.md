Hi John,

Someone else who has played with this more may be able to give you some
better pointers, but I can at least give you a couple of leads.  First,
you are probably already doing so, but make sure you are running &quot;256 colors&quot;
for the desktop on the Windows side.  Avoid using a fancy wallpaper to
minimize color usage.  VNC does a compressed screen rectangle copy, 
calculating every pixel, so matching the screens as much as possible should
make things go faster (it will still be slower than a real X display).
If the screen depth is matched it should just be a matter of an 8 bit lookup
table to map the colors.

Second, if you can&#x27;t get VNC to work acceptably you might also want to take
a look at VMware.  VMware creates a virtual PC on top of a real PC operating
system such as Linux or NT.   Your situation is difficult since you are
running Windows 95.  An option to consider in your case would be to partition
the disk and install both Win95 and Linux as native systems on two different
disk partitions.  You would run the native Win95 partition when you needed
to run software that would only run under native Win95.  In other cases you
could run Linux on the PC, but run Win95 within a VMware virtual machine,
which appears as a window containing Windows on the PC.  This would give you
both a very fast native Linux capability (good for IRAF display), plus a
Windows capability for running (most) Windows apps.  Apps that need 3d video
card features might not work, but most things run pretty well under VMware.

Assuming you have a powerful enough machine, the only additional cost is
for VMware, which is in the $50-100 range for a single user.  After working
with VNC under Windows for a while, this is how I ended up running my PC
most of the time.  I have Win98, NT4, and RedHat Linux installed in separate
bootable partitions, but most of the time I run Linux as the native OS
with WinNT and all its apps running in a VMware window.  A FAT partition
somewhere can be used to share files between the different operating systems,
alternatively VMware now has the capability to install SAMBA on Linux so
that you can access the Linux disks from within Windows.

Just some options to consider.

Are you running something like Cygwin on your Windows PC? I have had
success on a Win98 PC running Cygwin and MIX as an X server. I then
export the xhost from the Windows machine thusly:

xhost ip address    # remote machine

then telnet to the Solaris machine and login and:

export DISPLAY=xxx.xxx.xxx:0  # IP address of windows machine

then open up xterms, x programs, ximtool, etc.

It is essential that the Win machine run the same number of colors
required by the software you are attempting to run.

Cygwin source is available from
http://sourceware.cygnus.com/cygwin/cvs.html

I acquired both Cygwin and MIX included with the Windows version of 
FTOOLS/fv available from HEASARC for download or free of cost on CDROM. 

Another alternative X server for Windows is Hummingbird Exceed
http://www.hummingbird.com. This software is included in newer versions
of SuSE linux.

Personally I think the best solution is to partition the Windows hard
drive to be shared by Linux and then export the xhost as described
above. Otherwise why not run Samba to give you file sharing capability
if what is required is to put your ximtool/iraf files onto the Windows
machine quickly.
